## Дополнение: минимальный путь к исправлению и STOP

В `@rus/npc-runtime` найден `orderNpcConversationDecisionRequests(requests, directAddresseeRefs)` (`packages/npc-runtime/src/conversation-contracts.js:224-239`, экспорт `src/index.js:24`). Он лишь сортирует уже допущенные формальные requests по явно переданным `directAddresseeRefs`; **applicability не вычисляет**. В активном контракте `npc_conversation_mode_contract.md:1142-1152` applicability rule должна до signal решить, есть ли meaningful response. Готового export для выбора ответчика из одного `actualHeardListenerIds` нет. `packages/turn/src/turn-step-admission-support.js:3-10` знает `active_interlocutor`, но текущая live observation такого поля не передаёт.

Текущий player `turn_step_plan_v1` для прямой речи допускает только `utterance.{speaker_ref,utterance_text,input_mode,delivery}` (`packages/turn/src/turn-step-contracts/plan-validator.js:131-158`, `plan-schema.js:101-104`). Поля addressee нет. `emit_interaction.target_actor_refs` существует (`operations.js:293-298`), но live direct speech создаёт его из **всех** видимых actors в `p3-boundary.js:728-733`; это список кандидатов, а не смысловой адресат. После `runP3TurnStep` coordinator сохраняет лишь `native_readback` (`p3-live-coordinator.mjs:59-64`), и формальный выбор адресата уже потерян. Regex по именам, первый услышанный или новая LLM-классификация не исправляют boundary.

Native CDDA предоставляет выбор конкретного собеседника: `artifacts/2026-10-19/nativebuild/upstream-base/src/npctalk.cpp:1063-1088` принимает позицию и проверяет видимость/дальность, `:1229-1234` использует `creature_select_menu` для выбора NPC; `game.cpp:5347` вызывает `talk_to`. Это native dialogue UI с canned dialogue, а не свободная речь через согласованный новый semantic popup. План Task03 прямо оставляет CHAT без перехвата (`TASK03-PLAN.md:71`). Поэтому его нельзя молча заменить или задействовать как второй dialogue owner.

Минимальная техническая дельта при отдельном решении владельца: выбрать адресата native способом до отправки intent и включить явный `target_actor_id` в actor-safe live input; в `p3-live-coordinator.mjs` передать его в `runP3TurnStep`/`runP3NativeNpcReply`; в `p3-boundary.js` создавать NPC boundary только если этот exact ID видим, есть в native `actualHeardListenerIds` и остаётся тем же после refresh. Без адресата оставить native speech для всех слышащих, но 0 NPC model calls. `orderNpcConversationDecisionRequests` можно использовать только после admission, для одного responder сортировка не нужна. Проверки: неадресованная речь при двух слышащих → 0 NPC calls; точный выбранный адресат слышит → 1 reply; адресат не слышит/исчез после refresh → 0; перестановка actors/IDs не меняет выбор; invalid id fail-closed.
