## Метод

1. Детерминированный скрипт (python `csv`, независимый от `lib.cjs` сборщика), по всем строкам всех файлов:
   - число строк и распределение `kind` / `confidence` / `period` — сверено с README;
   - пустые `source_refs` / `confidence`, дубли id внутри и между файлами, дубли `name_ru`;
   - для каждой строки entity-файлов пересобраны из книжной базы: набор `source_refs`, `fact_count`, худшая `confidence`; обрезка `facts_summary` на 1200 символах;
   - поиск потерянных оговорок: `note` фактов книжной базы с маркерами «анахрон / позже 1230 / не Новгород / Смоленск / не использовать как c1230 / редкость / XIV–XV / ориентир», не перенесённые в выходную строку;
   - `route_modes.csv` сверен поле-в-поле с `sources/nov-region-audit-v1/novgorod_region_route_guidance.tsv`; JSON-поля проверены парсером.
2. Локальная копия книжной базы сверена с удалённым оригиналом (ssh read-only): sha256 совпадает (`0b63959f…f508`); `VERIFICATION.md` идентичен; `rejected.csv` — только заголовок. `FIXES.md` удалённой машины прочитан (правки уже внесены в CSV, удалено 0 строк).
3. Содержательная выборка: 34 строки entity-файлов, стратифицированно (seed 20260926; все уровни confidence: A 7, B 21, C 6 в выборке) + все 16 строк `route_modes.csv`. Каждая строка сверена с цитатой, `note`, `period` исходных фактов книжной базы.

## Проблемы, общие для трёх entity-файлов

1. **Потеряны верифицированные оговорки.** `build.cjs` собирает `facts_summary` только из `fact_type: value` и выбрасывает `note`. Именно в `note` верификатор и `FIXES.md` внесли датировочные и региональные оговорки. Потеряно в 22 строках: transport 6, health 1, recreation 15. Примеры:
   - `hlb_020 «мор 1230 г.»`: факт о Смоленске, в note «Смоленск, не Новгород; смоленский мор не переносить на Новгород» — в выходе нет, имя сущности вводит в заблуждение;
   - `rec_005 шахматы`, `rec_056 тавлеи`: «в Новгороде надёжно датированные фигуры — со 2-й пол. XIII в.; для 1230 г. редкость»;
   - `rec_049/050/051/052/053/036` (Костомаров): «историография XIX в., реалии XIV–XV вв.; не использовать как c1230»;
   - `trv_061 Устав о мостех` (1265–66, позже 1230), `trv_033` (находки не новгородские), `trv_056` (Олеарий XVII в. как аналогия);
   - `rec_045 варган`, `rec_040 сопель`, `rec_024 мяч`, `rec_047 ботало`: широкий диапазон датировок.
   Исправление механическое: добавить колонку `notes` (объединённые `note` фактов) и перезапустить скрипты.
2. **Сущности = точная строка `entity_ru`.** Варианты названий из разных книг дали почти-дубли: `trv_003` / `trv_042` (одна и та же статья Русской Правды о цене ладей, причём номер статьи расходится: «ст. 73» и «Пространная ст. 79»), `trv_011` / `trv_041` (перевоз), `trv_045` / `trv_056` (волховские пороги), `trv_002` / `trv_039` (волок), `hlb_006` / `hlb_041` (знахарки), `hlb_001` / `hlb_039` (лечец / летец), `hlb_019` / `hlb_031` (мор / эпидемии), `rec_006` / `rec_057` / `rec_002` (бабки, кости), `rec_007` / `rec_027` (игрушки). Для каталога сущностей их нужно слить (авторский шаг).
3. **`kind` по regex местами ошибочен:** `trv_027 волокуша` → `portage` (это волоковые сани); `trv_060 уличная мостовая` → `bridge`; `trv_061 Устав о мостех` → `bridge` (правило `infrastructure_law` мертво: `/мост/` срабатывает раньше); `trv_056 волховские пороги` → `other`, а `trv_045` → `hazard_river_rapids`; `hlb_009 травмы и хирургические болезни` → `caregiver_role`; `rec_020 свирель`, `rec_002 игральная кость`, `rec_024 мяч` → `other`.
4. `source_refs` содержат только `book:<id> §… ¶…`; авторы, название и год разрешаются по `book_id` через `sources/book_evidence_*.csv`, но в самих строках их нет.
