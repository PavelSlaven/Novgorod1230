# Этап 12. Аудит персонажа игрока

## 1. Назначение этапа

Аудит персонажа игрока — это gate-этап после генерации `player_character_dossier` и до материализации G5-сцены.

Его задача — проверить, что персонаж:

* исторически допустим;
* социально допустим;
* соответствует выбранному региону;
* соответствует выбранному году, сезону и времени суток;
* совместим со стартовым местом;
* использует только разрешённые social roles;
* использует только разрешённые occupations;
* не имеет невозможного статуса;
* не имеет невозможных предметов;
* не имеет предметов вне разрешённых item profiles;
* не имеет имущества без property/access model;
* не знает невозможного;
* не содержит скрыто созданных NPC, сцены, G5 или событий;
* может быть безопасно передан в следующие этапы.

Короткая формула:

```text
player_character_dossier
+ normalized_request
+ historical_frame
+ selected_start_node
+ start_place_audit
+ regional_context_package
+ npc_candidate_set
+ item_profile_candidate_set
→ player_character_audit
```

Этот этап не улучшает персонажа художественно. Он проверяет, можно ли допустить персонажа к стартовой G5-материализации.

## 2. Главное правило этапа

Аудит не исправляет персонажа молча.

Если персонаж невалиден, этап возвращает:

```text
pass=false
+ список ошибок
+ evidence
+ repair_route
```

Запрещено:

* процедурно менять статус персонажа;
* процедурно менять биографию;
* процедурно убирать или добавлять предметы;
* процедурно менять навыки;
* процедурно менять здоровье;
* процедурно переписывать цель;
* подменять невозможную заявку “похожим” персонажем без LLM repair;
* пропускать персонажа к G5, если есть hard block.

Код проверяет структуру и ссылки.
LLM проверяет смысловую совместимость.
Repair делает LLM отдельным этапом по конкретным ошибкам.

## 3. Место этапа в pipeline

```text
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит выбора стартового места
11. Генерация персонажа игрока
12. Аудит персонажа
13. Материализация стартовой G5-сцены
```

Этап 12 должен быть обязательным. Без него нельзя переходить к G5, visible context или narrator.

## 6. Общий принцип аудита

Аудит делится на два слоя.

Первый слой — code precheck. Он проверяет:

```text
JSON schema
required fields
enum
range
ID existence
candidate set membership
status values
source IDs
absence of forbidden downstream fields
```

Второй слой — semantic audit. Он проверяет:

```text
историчность
социальную правдоподобность
связь статуса, занятия, вещей и стартового места
знания персонажа
причины, цели, ограничения и риски
```

Если code precheck уже обнаружил hard block, semantic LLM audit можно не запускать. Ошибка сразу уходит в repair route.

## 7. Проверка историчности

Проверяется, что персонаж не содержит:

* современных профессий;
* современных социальных категорий;
* современной психологии как факта мира;
* современных правовых понятий;
* современных предметов;
* современных денег, документов, оружия или одежды;
* будущих знаний;
* терминов и мотиваций, не адаптированных к эпохе.

Проверка:

```text
character.origin
character.social_status
character.occupation
character.inventory
character.knowledge
character.goals
character.relations
```

Ошибка:

```text
PLAYER_AUDIT_HISTORICAL_ANACHRONISM
```

Пример evidence:

```text
inventory contains object kind not present in item_profile_candidate_set
goal uses modern institutional concept not present in regional_context
occupation_id is not in regional occupations
```

## 8. Проверка региона

Персонаж должен быть совместим с выбранным регионом.

Проверяются:

```text
social_role_id
occupation_id
name pool
home region
language/cultural notes
known places
known routes
known authorities
inventory profiles
property rules
```

Если персонаж является чужаком, это допустимо, но должно быть явно оформлено:

```json
{
  "local_belonging": "outsider",
  "why_outsider_is_here": "string",
  "social_risks": []
}
```

Ошибка:

```text
PLAYER_AUDIT_REGION_MISMATCH
```

## 9. Проверка стартового места

Персонаж должен иметь причину находиться в выбранном стартовом месте.

Проверяются:

```text
start_place_connection.selected_candidate_id
start_place_connection.selected_node_id
start_place_connection.selected_place_template_id
reason_here
right_to_be_here
arrival_context
what_character_knows_about_place
why_cannot_ignore_situation
```

Требования:

1. `selected_candidate_id` совпадает с `selected_start_node`.
2. `selected_node_id` совпадает с `selected_start_node`.
3. `selected_place_template_id` совпадает с `selected_start_node`.
4. `reason_here` не пустой.
5. `right_to_be_here` совместим с social status.
6. `arrival_context` совместим с clock/time_of_day.
7. персонаж не должен знать о месте больше, чем допускает его роль/опыт.

Ошибки:

```text
PLAYER_AUDIT_START_PLACE_ID_MISMATCH
PLAYER_AUDIT_NO_REASON_HERE
PLAYER_AUDIT_RIGHT_TO_BE_HERE_CONFLICT
PLAYER_AUDIT_CLOCK_START_REASON_CONFLICT
```

## 10. Проверка социального статуса

Социальный статус должен быть выбран из разрешённых `social roles`.

Проверка:

```text
character.social_status.social_role_id ∈ regional_context_package.social_context.allowed_social_roles
```

Также проверяются:

```text
freedom_status
wealth_band
local_belonging
rights
obligations
protector_or_guarantor
authority_over_character
who_can_punish_character
social_risks
```

Статус должен быть совместим:

* с заявкой игрока;
* с выбранным местом;
* с занятием;
* с инвентарём;
* с правом быть в месте;
* с правом носить вещи;
* с уровнем богатства;
* с отношениями и долгами.

Ошибки:

```text
PLAYER_AUDIT_SOCIAL_ROLE_NOT_ALLOWED
PLAYER_AUDIT_SOCIAL_STATUS_PLACE_CONFLICT
PLAYER_AUDIT_SOCIAL_STATUS_WEALTH_CONFLICT
PLAYER_AUDIT_SOCIAL_STATUS_INVENTORY_CONFLICT
PLAYER_AUDIT_SOCIAL_STATUS_PLAYER_REQUEST_CONFLICT
```

## 11. Проверка занятия

Занятие должно быть выбрано из `occupation_context`.

Проверка:

```text
character.occupation.occupation_id ∈ regional_context_package.occupation_context.allowed_occupations
```

Если `occupation_id=null`, должны быть заполнены:

```text
occupation_label
occupation_group
why_no_stable_occupation
```

Занятие проверяется против:

* social role;
* стартового места;
* навыков;
* инвентаря;
* знаний;
* seasonal pattern;
* body state;
* immediate need.

Ошибки:

```text
PLAYER_AUDIT_OCCUPATION_NOT_ALLOWED
PLAYER_AUDIT_OCCUPATION_SOCIAL_ROLE_CONFLICT
PLAYER_AUDIT_OCCUPATION_PLACE_CONFLICT
PLAYER_AUDIT_OCCUPATION_SKILL_CONFLICT
PLAYER_AUDIT_NULL_OCCUPATION_NOT_EXPLAINED
```

## 12. Проверка происхождения

Происхождение должно объяснять:

* статус;
* занятие;
* навыки;
* знания;
* стартовую причину;
* имущество;
* обязательства;
* страхи;
* ограничения.

Проверяются:

```text
birth_or_home_region
home_status
family_status
cultural_environment
usual_life
how_left_home_or_usual_place
why_origin_supports_current_status
unresolved_origin_unknowns
```

Ошибки:

```text
PLAYER_AUDIT_ORIGIN_STATUS_CONFLICT
PLAYER_AUDIT_ORIGIN_SKILL_CONFLICT
PLAYER_AUDIT_ORIGIN_INVENTORY_CONFLICT
PLAYER_AUDIT_ORIGIN_START_PLACE_CONFLICT
PLAYER_AUDIT_ORIGIN_TOO_EMPTY
```

Происхождение не обязано быть подробным романом, но должно быть причинным.

## 13. Проверка тела и состояния

Проверяются:

```text
health
satiety
vigor
active_conditions
condition_causes
mechanical_state_modifiers
body_prose
clothing_summary
```

Правила:

```text
health ∈ 0..100
satiety ∈ 0..100
vigor ∈ 0..100
active condition требует cause
state below 50 требует cause
state 0 означает критическое состояние
clothing_summary должен быть совместим с season, social status and inventory
```

Ошибки:

```text
PLAYER_AUDIT_BODY_STATE_OUT_OF_RANGE
PLAYER_AUDIT_BODY_STATE_WITHOUT_CAUSE
PLAYER_AUDIT_CONDITION_WITHOUT_EFFECT
PLAYER_AUDIT_CLOTHING_SEASON_CONFLICT
PLAYER_AUDIT_BODY_PROSE_NUMERIC_DUPLICATION
```

## 14. Проверка характеристик

Проверяются:

```text
strength
agility
endurance
reason
attention
influence
attribute_array_used
attribute_rationale
```

Рекомендуемое правило обычного старта:

```text
обычный массив: 14, 13, 12, 10, 9, 8
диапазон: 3–18
обычные люди: 8–13
15+ требует сильного основания
16+ только при особом основании
17–18 не выдаются обычному старту
```

Hard checks:

```text
all attributes ∈ 3..18
не больше двух характеристик 14+
нет 17–18 без explicit policy
high attribute has rationale
character not universally strong
```

Ошибки:

```text
PLAYER_AUDIT_ATTRIBUTE_OUT_OF_RANGE
PLAYER_AUDIT_ATTRIBUTE_ARRAY_MISMATCH
PLAYER_AUDIT_TOO_MANY_HIGH_ATTRIBUTES
PLAYER_AUDIT_HIGH_ATTRIBUTE_WITHOUT_BASIS
PLAYER_AUDIT_OVERPOWERED_CHARACTER
```

## 15. Проверка навыков

Проверяются все навыки:

```text
athletics
stealth
melee
ranged
craft
household
survival
riding
healing
observation
communication
custom_and_law
```

Правила:

```text
skill bonus ∈ 0..4
+0 — нет опыта
+1 — знаком
+2 — умелый
+3 — опытный
+4 — мастер
не больше одного +4
+4 требует сильного biography basis
боевые навыки выше +1 требуют военного/охотничьего/силового основания
каждый навык выше 0 должен иметь basis
```

Ошибки:

```text
PLAYER_AUDIT_SKILL_OUT_OF_RANGE
PLAYER_AUDIT_SKILL_WITHOUT_BASIS
PLAYER_AUDIT_TOO_MANY_MASTER_SKILLS
PLAYER_AUDIT_COMBAT_SKILL_WITHOUT_BASIS
PLAYER_AUDIT_SKILL_ORIGIN_CONFLICT
```

## 16. Проверка знаний

Знания персонажа проверяются против:

```text
origin
social status
occupation
home region
selected_start_node
knowledge_context
route_knowledge_rules
common_knowledge
rumors
```

Запрещено:

* знание скрытого состояния мира;
* знание будущих событий;
* знание полных карт;
* знание точных route IDs без основания;
* знание NPC, которые ещё не материализованы или не связаны с кандидатом;
* знание содержимого закрытых контейнеров;
* знание авторской информации из `hidden_state`.

Ошибки:

```text
PLAYER_AUDIT_PLAYER_KNOWLEDGE_LEAK
PLAYER_AUDIT_FUTURE_KNOWLEDGE_LEAK
PLAYER_AUDIT_HIDDEN_STATE_KNOWLEDGE_LEAK
PLAYER_AUDIT_ROUTE_KNOWLEDGE_WITHOUT_BASIS
PLAYER_AUDIT_KNOWLEDGE_PLACE_CONFLICT
```

## 17. Проверка инвентаря

Инвентарь — только то, что персонаж физически несёт при себе.

Для каждого предмета проверяются:

```text
character_item_id
item_profile_candidate_id
item_profile_id
title
item_kind
count
weight
size_band
condition
carried_where
quick_access
owner_model
holder
use
movement_hindrance
hands_occupied
social_or_legal_risk
property_rule_candidate_id
why_character_has_it
```

Hard checks:

```text
item_profile_candidate_id exists in item_profile_candidate_set
item_profile_id matches candidate
property_rule_candidate_id exists
weight is present
condition is present
carried_where is present
quick_access is present
owner_model is present
holder = player_character or explained
social_or_legal_risk is present
rare/restricted item has causal basis
```

Ошибки:

```text
PLAYER_AUDIT_INVENTORY_ITEM_NOT_ALLOWED
PLAYER_AUDIT_ITEM_PROFILE_MISMATCH
PLAYER_AUDIT_ITEM_PROPERTY_RULE_MISSING
PLAYER_AUDIT_ITEM_WEIGHT_MISSING
PLAYER_AUDIT_ITEM_CONDITION_MISSING
PLAYER_AUDIT_ITEM_ACCESS_MISSING
PLAYER_AUDIT_ITEM_OWNER_MISSING
PLAYER_AUDIT_RARE_ITEM_WITHOUT_CAUSAL_BASIS
PLAYER_AUDIT_INVENTORY_TOO_RICH_FOR_STATUS
PLAYER_AUDIT_INVENTORY_SEASON_CONFLICT
```

## 18. Проверка имущества вне инвентаря

Имущество вне инвентаря не должно быть выдано как доступный ресурс.

Проверяются:

```text
property_not_carried
borrowed_or_entrusted_items
disputed_items
accessible_resources
resources_not_currently_accessible
obligations_to_return
property_risks
```

Разделение:

```text
inventory = physically carried
property_not_carried = belongs/linked but not here
accessible_resources = can use under conditions
resources_not_currently_accessible = cannot use now
```

Ошибки:

```text
PLAYER_AUDIT_INVENTORY_PROPERTY_CONFUSION
PLAYER_AUDIT_REMOTE_PROPERTY_TREATED_AS_AVAILABLE
PLAYER_AUDIT_ACCESSIBLE_RESOURCE_WITHOUT_RULE
PLAYER_AUDIT_DISPUTED_ITEM_WITHOUT_RISK
```

## 19. Проверка веса и рук

Проверяются:

```text
inventory.total_weight
inventory.load_category
inventory.occupied_hands
load_effects
hands_occupied per item
movement_hindrance
```

Правила:

* total_weight должен соответствовать сумме carried_items;
* occupied_hands должен соответствовать предметам в руках;
* тяжёлый груз должен иметь effects;
* невозможно нести bulky/heavy items без последствий;
* quick access должен быть совместим с carried_where.

Ошибки:

```text
PLAYER_AUDIT_LOAD_NOT_CALCULATED
PLAYER_AUDIT_LOAD_CATEGORY_MISMATCH
PLAYER_AUDIT_HANDS_OCCUPIED_MISMATCH
PLAYER_AUDIT_BULKY_ITEM_WITHOUT_HINDRANCE
PLAYER_AUDIT_QUICK_ACCESS_CONFLICT
```

## 20. Проверка целей

У персонажа должна быть причина действовать.

Проверяются:

```text
immediate_need
long_term_desire
fear
obligation
reason_to_act_now
consequence_of_inaction
goal_visibility_to_player
```

Ошибки:

```text
PLAYER_AUDIT_NO_IMMEDIATE_NEED
PLAYER_AUDIT_NO_REASON_TO_ACT_NOW
PLAYER_AUDIT_NO_CONSEQUENCE_OF_INACTION
PLAYER_AUDIT_GOAL_NOT_COMPATIBLE_WITH_START_PLACE
PLAYER_AUDIT_GOAL_RAILROADS_PLAYER
```

Цель должна давать давление, но не должна превращать старт в жёсткую сюжетную рельсу.

## 21. Проверка отношений

Связи проверяются против `npc_candidate_set`.

Допустимые варианты:

1. связь с `npc_candidate_id`;
2. abstract background relation без конкретного NPC;
3. key seed relation, если есть valid key seed.

Запрещено:

* создавать конкретного NPC вне candidate set;
* давать NPC имя без name pool/materialization stage;
* создавать current action NPC;
* создавать диалог;
* создавать сцену встречи.

Ошибки:

```text
PLAYER_AUDIT_RELATION_NPC_CANDIDATE_NOT_FOUND
PLAYER_AUDIT_CREATED_NPC_OUTSIDE_CANDIDATES
PLAYER_AUDIT_CREATED_NPC_NAME_TOO_EARLY
PLAYER_AUDIT_CREATED_NPC_ACTION_TOO_EARLY
PLAYER_AUDIT_RELATION_TOO_CONCRETE_FOR_STAGE
```

## 22. Проверка запрета downstream-сущностей

В `player_character_dossier` не должно быть:

```text
visible_scene
intro_prose
g5_anchor_id
minilocation_id
scene_anchor
scene_graph
weather_event
npc_id outside candidates
concrete NPC action
container_contents not tied to inventory
hidden_world_event
```

Ошибка:

```text
PLAYER_AUDIT_CREATED_DOWNSTREAM_ENTITY
```

## 23. Code precheck

Перед LLM-аудитом код формирует:

```json
{
  "version": 1,
  "schema": "player_character_code_precheck",
  "pass": true,
  "checks": {
```

## 24. Работа LLM на этапе

LLM на этом этапе обязательна для semantic audit, потому что историчность, социальная допустимость, причинность биографии и связь вещей со статусом не сводятся только к FK-проверкам.

LLM-режимы:

1. `PlayerCharacterSemanticAuditor` — основной смысловой аудит.
2. `PlayerCharacterAuditRouter` — выбор маршрута repair при fail.
3. `PlayerCharacterAuditFormatRepairer` — исправление JSON-формата аудита.

LLM не имеет права:

* переписывать персонажа;
* исправлять статус;
* удалять предметы;
* добавлять причины;
* менять навыки;
* менять стартовое место;
* создавать альтернативного персонажа.

LLM только проверяет и возвращает audit.

## 29. Validation rules

Код обязан проверить `player_character_audit`:

3. `pass` является boolean.

5. `evidence` не пустой.

9. Если `pass=false`, все `commit_permission` false.
10. Все concern codes входят в enum.
11. Все severity входят в enum.
12. Audit не содержит изменённого персонажа.

14. Audit не содержит новой биографии.
15. Audit не содержит visible_scene.
16. Audit не содержит intro_prose.

18. Audit не содержит новых NPC.
19. `repair_route.return_to_stage` входит в допустимый enum.

20. Social role ID exists.

23. Property rule candidate IDs exist.
24. NPC candidate refs exist.
25. Health/satiety/vigor are 0..100.

## 32. Commit gate этапа

Этап считается успешным, если:

```text
player_character_audit.pass = true
и social_role_id допустим
и occupation_id допустим или null обоснован
и персонаж совместим с регионом, годом, сезоном, временем и стартовым местом
и инвентарь использует только разрешённые item profiles
и property/access rules есть
и характеристики и навыки валидны
и знания персонажа ограничены
и нет downstream-сущностей
и source_trace достаточен
```

После этого разрешается переходить к `PlayerCharacterGameProfileShaper` или сразу к G5 input, если dossier уже в игровом формате.

Если audit failed, pipeline не должен продолжать генерацию сцены.
