# occupations/occupations_additions.csv

**Что.** 18 новых занятий (occupation_id `occ_*`), закрывающих часть списка недостающих ремёсел из брифа коллектора `occupations-activities`. Каждая строка несёт все обязательные поля `approved-npc-runtime-basis.js` (4 сезонных расписания, 3 `how_to_materialize_*`, `typical_*`, `common_*`, `llm_adaptation_rules`, `llm_forbidden_uses`) плюс `status`, `confidence`, `source_refs`.

**Статус.** `status=candidate` во всех строках — коллектор не утверждает сам себя (правило проекта). Пины основного `novgorod_occupations_v1_enriched.tsv` не тронуты; это отдельный файл, перенос строк в pinned TSV и пересчёт нумерации — задача координатора/владельца.

**Метод.**
1. Скриптом (`scripts/build_occupations_additions.py`, keyword-поиск) найдены реальные строки в `sources/master-archive-v1/.../occupations/professions.csv` (479 кандидатских профессий) под каждое ремесло из списка брифа.
2. Для найденных — авторский перевод и адаптация полей под структуру `novgorod_occupations_v1_enriched.tsv` (это судебное/содержательное действие модели, не скрипт), с явной ссылкой на исходный `PRO####` id, его `historical_confidence` и `source_ids` (SRCxxx) из мастер-архива.
3. Для не найденных в professions.csv (красильщик) — источник взят из `costume-dataset-v1/data/materials_palette.csv` (палитра тканей, крашеная шерсть, confidence B), с явной пометкой разрыва в README.
4. Проверка (`scripts/check_occupations_additions.py`) повторяет acceptance-критерий брифа: все обязательные поля непусты, `confidence` ∈ {A,B,C}, `status=candidate`, у каждой строки `source_refs`.

**Счёт (по скрипту).** 18 строк написано, 18 строк прошли acceptance-проверку без ошибок.

Список покрытых занятий: ювелир-литейщик, косторез, токарь по дереву, скорняк, красильщик, верёвочник/канатчик, сетевязальщик, замочник, лучник-мастер (изготовитель луков), стрельник (изготовитель стрел), каменщик, известежог, иконописец, пивовар/медовар, мясник, хлебник (рыночный пекарь), рыботорговец, кормилица.

## Известные разрывы (gaps)

- **щитник (shieldmaker) — не закрыт.** Поиск по `professions.csv` (щит*, ...) не дал отдельной профессии-щитника; новгородская археология явно фиксирует щиты (умбоны, накладки) в статьях Медведева (МИА 65, оружие), но не как отдельную ремесленную специализацию, отличную от кузнеца/кожевника/плотника. Нужно либо решение владельца считать щит побочным продуктом кузнеца+плотника+кожевника (без отдельного occupation), либо целевой книжный/археологический поиск нового ремесла.
- **пряха/ткачиха отдельно от ткача — не закрыт.** В pinned TSV уже есть `ткач или работник ткани` = `ткач / пряха / суконный работник` (объединённая роль). Разделение на отдельные женскую (пряха) и мужскую/цеховую (ткач) роли требует решения владельца, не считается новым занятием без него.
- **красильщик** имеет confidence B через костюмный датасет, а не через прямую археологию красильных мастерских/чанов; отдельная археологическая проверка (МИА/Колчин по ремесленным мастерским) не выполнена в этом проходе — реальный gap, не самостоятельно закрыт до архивной проверки.
- Книжные свидетельства (`BOOK EVIDENCE` group на remote-машине) **не сверялись** в этом проходе для occupations — не было времени в рамках отведённого бюджета; отдельная задача должна прогнать `occupations`/`crafts` группу `.csv`/`.VERIFICATION.md` через эти 18 строк и добавить book-source_refs, где применимо.
- Разрешение `occupation_archetype_id` на реальный `occupation_archetypes` (15) не проверено против живой БД world_base (контейнер world-base-postgres-1 не запрашивался в этом проходе); используемые id (`archetype_urban_craftsman`, `archetype_rural_or_periurban_craftsman`, `archetype_church_craftsman`, `archetype_urban_or_household_craftsman`, `archetype_urban_trader`, `archetype_household_dependent`) — по аналогии с существующими паттернами TSV, не гарантированно совпадают с точными id из `world_base.occupation_archetypes`; координатор/аудитор должен сверить и, если нужно, переклассифицировать.
- Не выполнено: перевод 31 caution-занятия существующего TSV в approved (второй пункт брифа) — это отдельная, большая по объёму задача (проверка каждого из 31 занятия по всем обязательным полям), не начата в рамках этого прохода из-за бюджета; список 31 caution-занятия и недостающие поля нужно получить отдельным скриптом-diff по существующему `novgorod_occupations_v1_enriched.tsv` (`status=caution`) и заполнить по этой же схеме.
- `skill_catalog` (12 навыков) — отдельный домен `skills_competences` в этом же груп-брифе не проработан в этом проходе (см. верхнеуровневый отчёт коллектора); новые occupation-строки не привязаны к `required_skills` явно.
