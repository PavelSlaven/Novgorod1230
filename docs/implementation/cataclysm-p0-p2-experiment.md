# CDDA: спецификация изолированного эксперимента P0–P2

**Статус:** REFERENCE / DOMAIN GUIDE, исполняемая исследовательская спецификация.
**Дата:** 2026-10-18. **CR:** [#756](https://github.com/PavelSlaven/Novgorod1230/issues/756).
**План:** [вертикальный срез P0–P6](../plans/Novgorod1230_Cataclysm_Vertical_Slice_Implementation_Plan_2026-10-19.md).

Спецификация фиксирует начальные данные и пороги до native harness. Результаты
запусков записываются отдельно; перечисление критерия не означает PASS.

## Техническая fixture

Это синтетическая сцена, не исторически утверждённая карта Новгорода.
Координаты — native bubble map, z=0; начальный avatar `(60,60,0)`.
Перед измерениями native calendar устанавливается на полдень тестового дня;
после начала действия его меняет только штатный игровой цикл CDDA.
RNG seed запуска — `17`; другой seed применяется отдельным robustness прогоном.

| Данные | Начальное состояние |
| --- | --- |
| Фон | Native `t_dirt` |
| Двор | Native floor x=56…62, y=58…64 |
| Проход | Native floor x=63…66, y=60, закрытая native дверь `(63,60,0)` |
| Площадка | Native floor x=67…72, y=58…64 |
| Препятствие | Native стена `(60,59,0)`; `(61,60,0)` свободно |
| NPC | Три native `test_talker`: `(64,60,0)`, `(65,62,0)`, `(63,64,0)`; технические labels artisan/trader/guard |
| Предметы | Шесть native типов `rock`, `stick`, `2x4`, `string_36`, `rope_6`, `nail`; по одному экземпляру/начальному stack |

Native IDs NPC и предметов читаются после создания. Имена ролей не реализуют
профессии, распорядок или новый AI. Такие способности должны пройти P3.
Начальное native отношение NPC — `NPCATT_NULL`: шаблон `test_talker` по умолчанию
начинает UI-диалог. Нейтральные NPC сохраняют собственное штатное принятие решений.
Avatar носит native `debug_backpack`, чтобы тест pickup имел физическую вместимость;
это техническая оснастка, не исторический предмет. Bubble координаты могут сдвигаться
при перемещении карты; сравнение перемещения использует также native absolute position.
Перед измерениями выполняется штатный bootstrap tick нового мира; он не входит в
before/after операции. После него fixture задаёт полдень до первого before-снимка.
Для механических T01–T05 допустимы отдельные reset-сцены с теми же owners,
чтобы движение, pickup, activity и interrupt проверялись независимо.

T04 использует native `hacksaw` и `t_chainfence` на `(60,61,0)` в отдельной сцене.
`hacksaw_activity_actor` сам получает длительность из native data (12000 moves),
продвигает работу и превращает ограду в `t_dirt` с шестью `pipe` и native побочными
материалами. Проверяются промежуточный прогресс, завершение и количество ресурса.

## Критерии и измерения

P1: повторяемая pinned сборка; штатные focused native tests; реальное создание
трёх NPC, шести предметов и native карты с программным readback.

P2: T01–T05 основного плана через настоящий `game::do_turn()`; управляющий ввод
проходит `handle_action()`. Предметная операция может поставить штатную native
activity с проверенными native targets, как это делает UI; её effects исполняются
только общим игровым циклом, без вызова отдельного activity test helper.
Очередь seam подставляет только ввод; исчерпание очереди даёт явную ошибку.
Headless `cata_test` не запускает renderer lifecycle. Поэтому внутри существующего
input loop `do_turn`, перед его штатным `mon_info_update`, test mode с включённой
очередью обновляет только native map/visibility caches штатными методами `map`.
Без этого обнаружение новой угрозы запаздывало на дополнительный шаг (реальный
прогон `run-17-d`). Это подготовка cache, не второй perception owner: время,
движение, NPC, обнаружение угрозы и safe mode остаются в общем native loop.
Пустой ход не заменяет неисполненную операцию. После команды без расхода moves
тест может явно подать штатный pause, чтобы завершить игровой тик.

Unseen-equivalent native probe: другой свободный вектор движения и другой
ordinary предмет проходят тот же путь. Проверяются фактические координаты,
native стоимость и перенос/расход второго предмета без нового handler.

T05: отдельная reset-сцена, avatar `(60,60,0)`, native safe mode включён.
До before устанавливаются штатные desired и actual movement mode `run`. При ходьбе upstream
`avatar_action::move` использует AUTOPEEK и запрашивает выбор в `look_around`;
этот интерактивный вход текущей очередью действий не покрыт. Бег отключает только
AUTOPEEK, сохраняя штатную проверку safe mode; общий headless UX не заявляется.
Native `mon_zombie` уже существует в `(63,62,0)`, стена `(61,61,0)` закрывает
первоначальную прямую видимость. Предусловие проверяется native `sees`, не
предполагается по рисунку. Первый шаг на восток в `(61,60,0)` открывает видимость;
монстр может продолжить свой штатный ход. `mon_info_update()` обнаруживает новую
угрозу, а штатный safe-mode gate останавливает дальнейшее движение. Тест не
добавляет угрозу после before-снимка, не устанавливает `SAFE_MODE_STOP` и не
вызывает cancel вручную. Readback подтверждает initial invisibility, завершённую
первую часть, native visibility новой угрозы, отсутствие второго перемещения и
фактическую native причину остановки.
Safe mode блокирует и pause. Read-only observer фиксирует состояние после
отклонённого второго движения на границе следующего ввода. Затем явно подаются
native `IGNORE_ENEMY` и `PAUSE`, чтобы завершить текущий `do_turn`; второй шаг
при этом не повторяется. Snapshot остановки сохраняется отдельно от состояния
после этого подтверждения. Observer не меняет мир, часы, moves или safe mode.
Если этот native путь не срабатывает, T05 остаётся FAIL, а не заменяется отсутствием
движения возле стены. Опасный NPC/monster присутствует только в этом тесте.

Readback: native position, moves, elapsed seconds, item UID/type/count/location,
NPC ID/position/activity, фактическое завершение или прерывание. Это исследовательский
readback, не player-safe API. Прямая правка состояния допустима только при создании
fixture, до before-снимка.

UID читается как scalar через `item.uid().get_value()`: копирование самого
`item_uid` по правилам upstream создаёт новую identity. Native pickup также
копирует предмет; поэтому исходный UID на земле и итоговый UID в контейнере
различаются. Readback сохраняет оба, а баланс и location проверяются отдельно.
Будущий adapter не может считать UID неизменным при любой предметной операции.

Пороги зафиксированы до реализации: action p95 ≤250 ms; 100 последовательных
native ticks ≤2 s; process RSS ≤8 GiB. Снимать минимум 100 измерений после пяти
прогревочных ходов; p50/p95 — nearest-rank. Startup/data loading учитываются отдельно.
90 минут сборки — диагностический бюджет, не доказательство непригодности движка.

Исторически исполнитель назначил будущему P4 save+reload p95 ≤5 s и
20 измерений после одного прогрева; этого порога на операцию не было в исходном
плане среза. Задание 02 / D215/D216 отменяет его. Штатные критерии владельца:
save при запущенной игре ≤5 s, полный запуск/восстановление ≤20 s, поколение
≤512 MiB; матрица и разделение P4a/P4b — в исправленном плане среза.
Речевые T11/T12 проверяются на настоящем результате P3 до P6.

P3 holdout выбирает независимый проверяющий после реализации. P0/P2 не содержат
LLM вызовов и не доказывают семантическую свободу. Прототип не допускается к
P5/P6 при незакрытом P4. Изменение критерия требует явного обновления CR с причиной.
