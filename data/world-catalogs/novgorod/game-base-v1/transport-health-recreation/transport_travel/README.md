# transport_travel — суда, сани, телеги, переправы, ночлег (candidate)

## Что здесь

- `route_modes.csv` — 16 строк, прямая деривация из скопированного чернового источника `data/world-catalogs/novgorod/sources/nov-region-audit-v1/novgorod_region_route_guidance.tsv` (region_id = region_novgorod_land, status в источнике `draft`, здесь помечено `candidate`). Все виды пути региона: дорога, тропа, колейный путь, лесной ход, переход без дороги, гать, зимник, брод, паром/перевоз, мост, волок, речной ход, озёрный ход, сегмент коридора, вьючная тропа. Это единственный существующий носитель `route_template_refs` для видов транспорта. **Правка 2026-09-26** (см. `../VERIFICATION.md`): `confidence` для всех 16 строк — `C` (источник — неаудированный LLM-черновик `status=draft`, а внешняя типология для самой классификации — Historic England «Pre-industrial roads», аналогия для не-английского региона, не B); восстановлены колонки источника `is_allowed`, `compatible_landscape_template_ids`, `limits_ru`, `sources`; JSON-массивы (`allowed_edge_types`, `compatible_*_ids`, `sources`) больше не содержат сломанного двойного CSV-кавычения — валидный JSON; `generation_weight` (8…85) сопровождается колонкой `generation_weight_basis=unverified_llm_draft_no_stated_rule` — частоты перенесены из черновика без заявленного основания и не должны использоваться как готовое правило генерации до отдельного утверждения.
- `transport_entities.csv` — 63 сущности, агрегированные скриптом из верифицированной книжной доказательной базы (`../sources/book_evidence_transport_health_recreation.csv`, домен `transport_travel`, 83 факта). Одна строка на сущность: суда и их части (ладья, струг, насад, ушкуй, учан, челн-долблёнка, плот, весло, уключина, черпак — 18), сани и волокуша (6), телега и колесо (3), упряжь (хомут, дуга, оглобля — 3), лыжи/коньки (2), переправы (паром/перевоз 3, брод/мост 3, волок 3), опасности порогов и лоцманы (2), мыт (1), гостеприимство в пути (2), дорожное право (Устав о мостех, суд над вором в пути — 2), прочее (цена коня, подводы, гости — 4+7).

## Метод

1. `scripts/build.cjs` парсит `novgorod_region_route_guidance.tsv` (TSV, кавычки JSON-массивов) и книжный CSV (RFC4180 с многострочными quote-полями) собственным детерминированным парсером (`../scripts/lib.cjs`).
2. Сущности книжной базы группируются по `entity_ru`; для каждой — список фактов (`fact_type: value`), объединённые `source_refs` в формате `book:<book_id> §<section_path> ¶<para_no>`, и консервативная (худшая) `confidence` среди фактов сущности (A > B > C).
3. `kind` — классификация по регулярным выражениям на названии сущности (детерминированное правило, см. `KIND_RULES` в скрипте), не суждение модели по каждой строке.
4. `hazard_keywords` — те же факты, отфильтрованные по словам лёд/половодье/разбой/порог/тонуть/шторм.

## Критик (из брифа) и как это на него отвечает

- Критик указал, что приоритет M3 ошибочен и водный транспорт/переправы должны быть в M2c: подтверждается напрямую составом сущностей (18 судовых + 6 переправных/переходных против 4 дорожных) и тем, что стартовая территория v17 — речные плёсы и пристани. Решение приоритета — за владельцем/утверждающим, не за сборщиком.
- Строки v16 traversal (risk 3, hazards 10, checks 2), упомянутые как потерянные, в текущем checkout и в скопированных источниках не найдены (не проверялось напрямую в PR #98 worktree дальше `route_guidance`); `hazard_keywords` восстанавливает только то, что явно есть в книжных фактах (лёд, пороги), это не замена утраченных строк.

## Пробелы (для владельца/следующего прохода)

- Нет структурированных полей `capacity`, `speed_band_by_season`, `required_animals` на уровне отдельного судна/саней — книжные факты дают качественные описания (вместимость учана, насада по типу применения), но не сведены в единую шкалу скорости по сезону; это требует авторского прохода (не скрипта), сверенного с `spatial_v3 movement costs` (не читался в этой сессии — вне read-only зоны без DB).
- `hospitality_rules` — только 2 сущности (гостеприимство в пути, странноприимница); мало для готовой механики ночлега. Семейство WK `hospitality-travel` отмечено в брифе как `missing (partial)` и не закрывается этим проходом.
- `route_template_refs` для конкретных `tr_id` не проставлены построчно (нет автоматического сопоставления сущность↔route_template без модельного суждения о типе пути); оставлено на авторский проход.
- `ладья` как отдельный вопрос брифа («проверить») — подтверждена книжными фактами как речное судно (`ладья речная`, `ладья наёмная`, `морская ладья`), присутствует.
