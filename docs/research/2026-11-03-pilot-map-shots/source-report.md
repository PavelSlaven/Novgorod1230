## 1. Что снимать исполнителю (вставлять в задание части дословно)

Это раздел для «11» и распорядителя: он копируется в задание каждой части пилота окрестности (природный слой, поле, гумно и овин, сенокос и выгон, опушка, люди за делом) без правок. Снимки нужны, чтобы владелец увидел результат части с телефона; по ним, прогону и числам пробы прогулки часть принимается.

### 1.1. Общие правила захвата

1. Захват делается в терминальной сборке CDDA на servak тем же способом, что в части 1: сессия `tmux` с окном 140×48 (`tmux -S <сокет> new-session -d -s <имя> -x 140 -y 48 <команда>`), игра запущена с `LC_ALL=C.UTF-8 TERM=xterm-256color`. Размер окна, шрифт и раскладку интерфейса между захватами и между прогонами «до» и «после» не менять: инструмент вырезает кадр вокруг героя по фиксированной позиции (строка 24, колонка 48).
2. Каждый кадр снимается двумя командами подряд, без ввода игре между ними:
   - с цветом: `tmux capture-pane -t <сессия> -p -e > <метка>.txt`;
   - без цвета: `tmux capture-pane -t <сессия> -p > <метка>-plain.txt`.
   Допустимо снимать скриптом части 1 (`.p1/tmp/p1c-play.py`, команда `snap <сессия> <метка>`): он пишет оба файла.
3. Перед захватом закрыть меню и диалоги (`Esc`), на экране — обычный вид местности с боковой панелью и журналом сообщений. Кадр с открытым меню, инвентарём или текстом ожидания не годится.
4. Все файлы кладутся в одну папку `<out>/shots/` задачи. Туда же кладутся три служебных файла (1.3).
5. Герой идёт по маршруту пробы прогулки, который не менялся с части 1 (`omt-path.txt`: ход входа в каждый OMT). Прогон «до» делается на сборке без этой части, прогон «после» — с ней, оба по одному маршруту и с одним набором ходов.

### 1.2. Какие кадры

**Момент съёмки.** Кадр сцены снимается на 5-м ходу пребывания героя в этой сцене: ход входа в OMT из `omt-path.txt` плюс 4. Если герой пробыл в сцене меньше 5 ходов — на последнем ходу сцены. Номер хода записывается в манифест.

**Какие сцены.** Первая сцена каждого нового или изменённого части пояса. Ниже — по частям.

| Часть | Кадры (имя `NN-<сцена>`) | «До» нужно? |
|---|---|---|
| Природный слой | каждая сцена маршрута, где слой добавил хотя бы одну новую примету по пробе прогулки (двор, огород, поле, выгон, гумно, сенокос, опушка, лес) | да, для каждого кадра |
| Поле в конце жатвы | `NN-поле` (первая сцена поля). Если в нём видны меньше 4 из 5 примет части (жнивьё, снопы, яровое на корню, прясло, птицы) — ещё кадры `NN-поле-<примета>` на ходах, где остальные приметы впервые восприняты (ход — по записи восприятия) | да |
| Гумно и овин | `NN-гумно`; и `NN-поле-дым` — кадр из сцены поля, на котором виден дым овина (проверка «дым виден с поля»), на первом ходу, где дым в кадре | да для `NN-гумно`; для `NN-поле-дым` — нет |
| Сенокос и выгон | `NN-сенокос`, `NN-выгон` | да |
| Опушка | `NN-опушка` | да |
| Люди за делом | `NN-<сцена>`, где человек за делом впервые воспринят; в журнале сообщений (строки 40–47 кадра) должен быть виден звук работы | да |

**«До».** Для кадра с признаком «да» исполнитель снимает ту же сцену на том же ходу маршрута в прогоне до части; файл — `NN-<сцена>-до.txt` и `NN-<сцена>-до-plain.txt`. Для части, которая ничего не меняет в сцене, «до» не снимается.

**Глобальная карта.** Один раз на часть, если часть меняет набор типов OMT вокруг двора (часть 1 меняла; остальные части — только если добавляют новый `overmap_terrain`). Открыть карту мира (`m`) на старте, курсор на клетке двора плотника (27,33,0) в центре, и снять `00-глобальная.txt`, `00-глобальная-plain.txt`. Вместе с ней — `omt-grid-<часть>.txt` в формате `omt-grid-p1c.txt` (центр двора, столбцы x=-2..2, строки y=-2..2, у каждой клетки `<id> | <русское название>`). Если OMT не менялись, снимки глобальной карты не нужны.

### 1.3. Служебные файлы и манифест

В `<out>/shots/` обязательны:

- `omt-path.txt` — ход входа и OMT по маршруту (формат части 1: `<ход> → <место> | OMT (x, y, z)`);
- `omt-grid-<часть>.txt` — только вместе с `00-глобальная` (см. выше);
- `shots.tsv` — манифест: первая строка — заголовок, дальше по строке на кадр, поля через табуляцию:

```
id	capture	kind	turn	place	new	before	grid
00-глобальная	00-глобальная	global	0	карта мира у двора плотника	вокруг двора поле, огород, выгон, сенокос, опушка, лес	omt-grid-p2.txt
01-поле	01-поле	screen	74	поле	жнивьё, снопы полосой, грачи на стерне	01-поле-до
```

- `id` — имя файла результата без расширения (`NN-<сцена>`);
- `capture` — имя файла захвата без `.txt` и без `-plain`;
- `kind` — `global` или `screen`;
- `turn` — номер хода игры по маршруту;
- `place` — русское название места;
- `new` — что нового видно на кадре, одной фразой, по приметам части, без домыслов и без слов, которых нет на экране;
- `before` — имя захвата «до» без `.txt` или пусто;
- `grid` — только для `global`: имя файла `omt-grid`.

Проверка полноты — на стороне принимающего: файлы из манифеста есть, пары с цветом и без цвета на месте, номера ходов совпадают с `omt-path.txt`. Нет кадра из таблицы 1.2 — часть не принимается.

## 2. Формат снимков

### 2.1. Что видит владелец

Одна страница `index.html` на часть (`codex-direct/map-shots/pilot-<часть>/`), снимки сверху вниз:

1. **Глобальная карта** (если часть меняет набор типов OMT): врезка 17×31 OMT вокруг курсора на дворе плотника, рамка 5×5 вокруг двора, под ней легенда — образец символа в цвете карты и русское название.
2. **Экран у героя** на первой сцене каждого нового или изменённого пояса: врезка 27 строк × 49 колонок по центру героя (строка 24, колонка 48 кадра), без боковой панели. Ссылка «весь кадр» ведёт на полный экран 140×48 с панелью и журналом.
3. **«До» и «после» рядом** для части, меняющей существующее место: две картинки в одном ряду, на узком экране друг под другом, у каждой подпись текстом.
4. **Подпись в одну строку**: `<место> · ход <N> · <день>, <время суток> — <что нового видно>`. День и время суток инструмент берёт из боковой панели самого кадра («Дата», «Время»), не из манифеста. Подпись есть и полосой в PNG, и текстом `<figcaption>` на странице.

### 2.2. Инструмент и команда сборки

`codex-direct/land1230/scripts/shots/render_shots.py`; тест — `test_render_shots.py` рядом (12 тестов, зелёные; Pillow 12.2.0, шрифты Consolas и Arial из `C:/Windows/Fonts`). Субкоманды: `shot` (врезка с подписью), `full` (весь кадр), `global` (карта с легендой), `build` (по манифесту).

```
python -I codex-direct/land1230/scripts/shots/render_shots.py build codex-direct/map-shots/pilot-p1
python -I codex-direct/land1230/scripts/shots/test_render_shots.py
```

В `DIR/` лежат `shots.tsv` и `captures/<имя>.txt` (с цветом); `build` пишет `<id>.png`, `<id>-full.png`, `<id>-до.png` (если задано `before`) и `index.html`. Формат манифеста и состав файлов — раздел 1.3. Страница без JavaScript и внешних ресурсов, `viewport` задан, фон тёмный.

### 2.3. Проверка на части 1

Страница `codex-direct/map-shots/pilot-p1/` (8 кадров: глобальная карта, двор, огород, выгон, гумно, сенокос, опушка, лес). Открыта во встроенном браузере при ширине 375×812 (эмуляция телефона), затем возвращена на desktop.

Что увидела:
- Горизонтальной прокрутки нет (`scrollWidth` 375 = `clientWidth` 375); 8 `<figure>`, все 8 картинок загружены; подписи — текст 16 px, переносятся по словам.
- Глобальная карта: символы и цвета различимы, рамка 5×5 вокруг двора на месте, легенда читается.
- Экранные кадры: точки местности, `@` героя, строения (рамки жёлтая/красная), грядки `#` читаются; контраст на тёмном фоне достаточный.
- Сравнение с PNG 02.11 (`1-двор-развилка`, `2-выгон-развилка`, `3-лес-конец`, `4-глобальная`): по читаемости и контрасту не хуже; добавились подпись, легенда и ссылка на полный кадр.

Замечания:
1. На экранных кадрах нет легенды глифов CDDA (`#`, `.`, `/`, `+`): владелец должен догадываться, что есть что. Легенда есть только у глобальной карты.
2. Подпись дублируется на странице: полосой в PNG и `<figcaption>` (на телефоне выглядит как две одинаковые строки).
3. На глобальной карте пары (символ, цвет) неразличимы: `F` зелёный — лес и опушка; `,` зелёный — сенокос и выгон; `#` жёлтый — место гумна с овином и двор плотника. Легенда сводит их в «A / B» и пишет предупреждение в stderr (3 предупреждения при сборке части 1). Различить места на карте по символу нельзя.
4. На телефоне экранный кадр 539 px сжимается до 359 px: точки местности мелкие, но читаются; чтобы разглядеть, нужен «весь кадр» или увеличение пальцами.
5. Глиф `⇗` в Consolas рисуется «тофу».
6. У части 1 нет пар «до/после»: «до» не снимали.
7. Кадры части 1 сняты на развилках и в конце сцен, а не на 5-м ходу пребывания (правило 1.2 введено после); значения «ход» в подписях — ход развилки.
8. Время во всех подписях части 1 одинаковое («20 Авг, раннее утро») — сцены лежат внутри одного утра.

### 2.4. Что не проверено и почему

- Реальный телефон и приложение Remote Control: проверена только эмуляция 375×812 во встроенном браузере; перенос шрифтов, масштаб и контраст на экране телефона не видела.
- Вид «до/после» рядом на странице: построение проверено тестом (`build` с `before`), на данных части 1 пар нет, глазами не смотрела.
- Страница `file://`: встроенный браузер не открывает её как страницу (снимок статичен, смена ширины недоступна). Проверка шла через временный локальный http-сервер `127.0.0.1:8765` (остановлен). Владельцу страница нужна по http-адресу или как набор PNG.
