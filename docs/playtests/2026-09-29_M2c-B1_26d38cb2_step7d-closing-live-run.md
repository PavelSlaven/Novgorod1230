#### Что пришлось исправить по пути (каждое найдено живым прогоном)

1. **Причина исходного «не удаётся достичь цели»** (то, что просил `A-B1-03`) — серверный `reason_code` из `prepareTraversal`: `SCENE_ENTITY_PERCEPTION_DATA_GAP`, `reason: current_local_edge_admission_required`. Это **мой дефект шага 2**: `localDisclosure()` бросал ошибку для видимого ребра без строки admission, а reader admission отвечает только для закоммиченной позиции актёра (`WHERE l.scene_position_id=$3`) — при проекции назначения перехода (позиция ещё не закоммичена) строк нет по определению. Исправлено: без строки — ребро раскрывается без `destination_status`, без догадки и без ошибки. Падающий тест первым (`spatial-v3-current-visibility-provider.test.js`).
2. **`TURN_STEP_DOMAIN_BINDING_AMBIGUOUS` (500):** команда подхода и обычная локальная команда того же ребра оба претендовали на одну операцию (binding сверяет структуру, не описание). Подход теперь несёт `route_ref: exit_id` — структурно отличим; тест «ровно один binding претендует на каждую операцию» (в юнит-тестах подход и локальная команда раньше не создавались вместе — поэтому не ловилось).
3. **Подпись выхода для планировщика была нейтральной** («Продолжить путь — выход 1 — подход к переправе»): expansion runtime не передавал владельцу раскрытия карту `exit → slot` (`slotByExit`), поэтому описание «к руслу» шага 3 доходило только до экрана, не до операций. Исправлено, тест на карту.
4. Прежние прогоны 22:59–00:30 не двигались, потому что некоторые party стартуют в условиях, при которых не раскрывается ничего (см. наблюдение ниже), а не из-за кода перехода.
