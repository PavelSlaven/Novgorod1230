# Прозаический тест, третий прогон — сравнение стратегий подачи, 2026-09-27

Третий срез того же метода (`README.md`, `README-v2.md`): не «дать слабой модели полный пакет и
посмотреть», а сравнить несколько **детерминированных способов подать те же данные** одной и той же
модели (qwen 27B, домашний сервер, тот же провод `tools/qwen-chat.mjs`, thinking отключён). Дела —
только C1–C5 («первый приход на место»), без C6/C7. Судейство здесь не делается: это отдельный слепой
проход (см. задание владельца), этот прогон только производит тексты и объективные метрики.

## Пакеты

- Исходный пакет писателя не менялся: `build-v2/places/Cn-visible.json` (+`Cn-meta.json`, служебный,
  не для писателя).
- Новый **курированный пакет** — `tools/present.mjs` строит `build-v2/places/Cn-curated.json` (структура,
  для метрик) и `Cn-curated.txt` (обычный русский текст, подаётся моделям). Детерминированно: два
  запуска дают одинаковые байты (проверено). Что делает скрипт — см. комментарий в его шапке:
  - переводит все английские коды (`state`, `signs`, `where`) в русские слова по явному словарю;
    непереведённый код не показывается и попадает в `build-v2/places/present-log.json` (в C1–C5 таких
    не было — весь словарь кодов проверен заранее);
  - убирает `not_in_data` (CSV-пути, ppm, id правил) целиком;
  - убирает `ground_water` (дублирует то же самое, что уже говорят предложения `sensory.видно`);
  - убирает `fish` из курированного пакета (не из данных вообще — в списке рыбы нет признака явной
    видимости, в отличие от `animals.seen`; это один из findings README.md/README-v2.md, а не догадка
    curator'а);
  - делит `vegetation` на «деревья/кусты» и «травы» по `Cn-meta.json#counts.by_group` (массив уже
    собран builder'ом в этом порядке — не по словарю названий растений);
  - ранжирует по заметности (главные объекты → люди/явное «людей не видно» → сенсорные строки →
    крупные/заметные звери → видимые вещи с причиной, если есть → 3–5 растений → состояние воды) и
    укладывает в бюджет 12–18 деталей (реально вышло 12–18 во всех пяти делах, обрезка сработала
    только для C3 — было 21 после сборки зон, срезано 3);
  - группирует в зоны «главное», «вблизи», «звуки и запахи», «дальше/вокруг».

## Стратегии

Все инструкции — по-русски, короткие; литературный бриф («во втором лице, как в хорошей книге, только
данные, короче — не выдумывать») одинаковый везде (см. `prompts_used.BRIEF` в `MANIFEST.json`), кроме
A_full, где сознательно оставлена старая системная инструкция runs-v2 без изменений — она и есть
контроль.

| Стратегия | Вызовов | Что подаётся |
|---|---|---|
| `A_full` | 1 | Старый `runs-v2/Cn-visible.sys.txt` (как есть, с запросом «---»-списка) + полный JSON `Cn-visible.user.txt`. |
| `B_curated` | 1 | Общий BRIEF + курированный текст `Cn-curated.txt` вместо JSON. |
| `C_select_write` | 2 | Вызов 1: полный JSON → JSON `{"details":[...]}`, 10–15 фактов, скопированных из пакета, в порядке заметности. Вызов 2: BRIEF + только эти детали → текст. |
| `D_write_check_revise` | 3 | Вызов 1: BRIEF + курированный текст → черновик. Вызов 2: черновик + курированный текст → JSON `{"unsupported":[{quote,why}]}` (что в черновике не подтверждено данными). Вызов 3: черновик + unsupported → правка только этих мест. |
| `E_zones` | 5 | По вызову на зону курированного пакета (главное/вблизи/звуки и запахи/дальше и вокруг) → короткий фрагмент (1–3 предложения); 5-й вызов соединяет 4 фрагмента в текст без новых фактов. |

Финальный текст каждого сэмпла — **только сцена**, без служебной «---»-части (у A_full она, если
модель её всё же добавляет, вырезается перед сохранением — проверено, что в исходном ответе после неё
ничего важного не терялось для метрик). N=3 сэмпла на (дело, стратегию), температура 0.7 везде,
включая промежуточные JSON-вызовы.

Каждый qwen-вызов идёт через `tools/qwen-chat.mjs` как отдельный процесс (`spawnSync`) — этот скрипт
сам открывает файл настроек и никогда не печатает ключ; `tools/run-strategies.mjs` его не читает и не
видит. Retry — до 3 попыток на HTTP/сетевую ошибку; на невалидный JSON промежуточного вызова — один
повтор с уточнением, затем честный fallback с записью в лог (в этом прогоне ни retry, ни fallback не
понадобились — все 75 запусков (5 дел × 5 стратегий × 3 сэмпла) прошли с первой попытки, 0 сетевых
ошибок, 0 невалидных JSON).

## Файлы

- `Cn/<strategy>-<k>.txt` — финальный текст (то, что оценивать в слепом судействе).
- `Cn/<strategy>-<k>.callN.sys.txt` / `.callN.user.txt` / `.callN.out.txt` — точный промпт и сырой
  ответ каждого вызова конвейера (для C/D/E это несколько вызовов на один финальный текст).
- `run-log.jsonl` — по строке на каждую попытку вызова: `case,strategy,sample,call,purpose,attempt,ok,ms,usage`.
- `run-summary.json` — по записи на (дело, стратегию, сэмпл): `ok, calls, fallbacks, total_ms, final_file`.
- `metrics.json` — детерминированные метрики `tools/metrics.mjs`: на каждый текст — длина, доля
  упомянутых курированных деталей (нестрогое сопоставление по псевдо-основе слова), стоит ли явное
  «людей нет» там, где в пакете нет людей, число утечек английских слов, плюс сводки по стратегии и по
  делу (вызовы, суммарная и средняя задержка).
- `MANIFEST.json` — дела, стратегии, использованные системные инструкции текстом, итоговые числа.

## Как воспроизвести

```
node tools/present.mjs               # строит Cn-curated.json/.txt из Cn-visible.json
node tools/run-strategies.mjs --samples=3   # прогоняет qwen, пишет runs-v3/*
node tools/metrics.mjs               # runs-v3/metrics.json + таблица в консоль
```

Каждый шаг детерминирован, кроме собственно ответов qwen (temperature 0.7 — это единственный источник
недетерминизма во всём конвейере).

Точные числа и разбивка по делам — `metrics.json`. Два наблюдения, которые видны из самих чисел (не из

в русский текст — это не утечка кода из пакета, а собственная оговорка модели, метрика её честно
поймала (`english_leak_samples` в `metrics.json`).
