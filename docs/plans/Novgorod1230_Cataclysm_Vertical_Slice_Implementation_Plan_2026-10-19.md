## 1. Решение и цель

**Задача первого среза:** не построить весь Новгород и не портировать прежнюю игру на новый стек, а **на работающем движке доказать один сквозной причинный цикл**:

```text
свободное намерение игрока
→ существующая semantic boundary Novgorod (@rus/turn)
→ проверенная native операция и исполнение CDDA
→ фактический результат, игровое время и состояние NPC
→ согласованное состояние живого процесса CDDA
→ player-safe readback
→ существующие narration/presentation и отдельный журнал CDDA
→ по запросу игрока или раз в игровой час: game::save() → целое принятое поколение
```

**Главные четыре результата, необходимые для решения о пригодности CDDA:**

1. Novgorod1230 может направлять действия в **настоящую** симуляцию CDDA и получать readback, не запускающий вторую физику.
2. Общий semantic planner может интерпретировать **новые, не предусмотренные примерами** физически осмысленные попытки, не упираясь в whitelist demo-команд; недостающий общий native primitive становится явным техническим gap.
3. CDDA и семантика Novgorod сохраняются одним целым поколением **в точках сохранения** по D215. Повтор запроса отсекается внутри живой сессии; штатного журнала exactly-once на диске нет. После аварии восстанавливается последнее целое сохранение по D216.
4. Игрок видит подтверждённые результаты в прозе, на карте и в коротком журнале без раскрытия скрытого состояния, фантазий нарратора и посекундных LLM-вызовов.

Не выполнять интеграцию с текущим production runtime, не конвертировать существующие party/saves, не менять active bindings/profiles до отдельного P7. **Стоп при невыполнении любого критического условия**, а не обход проблемы описанием от LLM.

**P3 — решающая продуктовая проверка направления.** Если на согласованном локальном Qwen не проходят свободная фраза и ordinary-материализация T06/T07/T20 либо ответ NPC из собственного знания T19, итог — `REVISE_APPROACH` для направления CDDA, а не локальное закрытие P3 по зелёным unit tests. Пересмотр обсуждает владелец; автоматической смены движка нет.

### D215/D216: что значит сохранённый результат

В целевом режиме живой CDDA — единственный физический owner. После каждого действия он продолжает из фактического состояния в памяти. По запросу игрока и каждый игровой час родной `game::save()` записывает физику вместе с семантикой, затем принимается целое поколение. Сохранение каждого хода, operation IDs на диске, квитанции и побитовый RNG replay нужны только отладке.

При аварии между успешными сохранениями теряется прогресс после последнего целого сохранения — при штатном успешном часовом автосохранении до часа игры. Ошибка сохранения видима игроку: обещать предел в час после такой ошибки нельзя. При запуске до продолжения показываются игровой момент восстановленного мира и предупреждение, что более поздние действия, реплики и последствия могли исчезнуть. Прочитанная игроком проза об этом прогрессе также не доказывает его наличие после восстановления.

Принятое сохранение не переписывается и его исходы не пересчитываются: rollback выбирает прежний целый мир, а не переигрывает committed исход. Однако отнесение «committed» только к точке сохранения — **целевое изменение**, не толкование действующей нормы задним числом. AI §13–14, §28.6 и active narration/conversation/persistence contracts требуют persisted причинность и переживание restart/retry. Публикация прозы о live, ещё не сохранённом результате расходится с прежним правилом «проза после durable». D215/D216 задают требуемый продуктовый режим, но этот reference-план не меняет защищённые нормы: до игрового пути необходимы решение владельца и Contract Auditor по этим расхождениям. Для промежуточной dev-пробы результат явно помечается «черновик, не сохранено»; это не production `TurnScreen`.

## 3. Размер и содержимое среза

**Минимальная тестовая сцена, не историческая реконструкция готового Новгорода:**

| Состав | Ограничение первого игрового среза |
| --- | --- |
| Пространство | Один двор → участок улицы → маленькая торгово-ремесленная площадка; три связанные игровые зоны. Сначала разместить в **одном или нескольких native OMT** без собственной геометрии; выбор размеров зависит от проверенного mapgen |
| Персонаж игрока | Один actor; свободный текст как основной режим ввода |
| NPC | Три уникальных: ремесленник, торговец, стражник. ID и физическое состояние — native; не декорации и не три отдельные scripted AI |
| Вещи | Ориентир 6–12 ordinary предметов с осмысленным назначением, количеством, массой/контейнерами; один случай расхода или физического изменения |
| Поведение | Одно нативное занятие/обязательство NPC, одна реакция на обстоятельства, один свободный разговор и одна существенная новая decision boundary |
| Время | Перемещение, короткая речь, одна продолжительная native activity и одно прерывание; общий clock |
| UI | Свободный ввод, утверждённая проза, минимальная карта из CDDA, **отдельная** панель CDDA journal |
| Сохранение | Запрос игрока, часовая точка, целое поколение и восстановление с сообщением об откате на временном мире |
| Игровой прогон | Ориентир 15–20 минут **наблюдаемой игровой демонстрации**, не ограничение длительности игровой сессии |

Исторически одобренные данные обязательны **до заявления о достоверном Новгороде 1230 года**. На P1 можно использовать явно помеченную временную fixture-карту. Не выдавать произвольную геометрию за точное расположение исторической улицы или здания.

**Сквозной UX-пример:** герой выходит во двор, идёт к ремесленнику через улицу, встречает прохожего, пытается взаимодействовать с дверью/вещью, произносит свободную реплику, наблюдает работу NPC, начинает длительное действие, сталкивается с реальным прерыванием, читает журнал и художественный итог, сохраняет игру и продолжает после загрузки. Это **проверочный маршрут**, а не scripted последовательность обязательных игровых команд. В другой формулировке и в другом порядке должны действовать те же общие механизмы.

**Обязательный контроль свободы:** кроме привычных «иду», «беру», «говорю» — незнакомая заранее парафраза и одна новая ordinary-трансформация/необычное использование существующей вещи. Отсутствие точного рецепта **не равняется физической невозможности**; если общего класса native исполнения действительно нет — фиксировать недостаток и минимально расширять CDDA либо останавливать квалификацию, но не вводить сценарный `switch`/template.

### Подмножество `turn_step_plan_v1` для CDDA

Источники формы: `packages/turn/src/turn-step-contracts/plan-schema.js:28–115`, `constants.js:4–6`. Это план будущего admission у adapter, не уже внесённая правка shared schema.

- Сохраняются identity/revision/step поля, `interpretation`, `clarification`, ссылки и `continuation`; они не создают физических фактов.
- `resolution=domain_request`: `request_discovery`, `request_container_access`, `request_movement`, `request_item_use`, `request_activity`, `emit_interaction`, `request_world_process` передают запрос соответствующему native owner. Конкретная capability допускается после native gap-test, не на основании одного наличия поля схемы. Непокрытый класс останавливает квалификацию и пополняет reuse/gap ledger.
- `resolution=direct` — только уже подтверждённое actor-safe наблюдение или отсутствие изменения мира, с пустым `operations`. `player_utterance`/`emit_interaction` не доказывают доставку: текст и адресаты идут в native speech path. `clarification_required` не меняет мир.
- `direct_operation` (`create_entity`, `move_entity`, `change_entity_facts`, `set_entity_mechanics`, `retire_entity`, `apply_body_event`) запрещён для всех CDDA-owned физических полей. Новый предмет создаёт native materialization/action owner после проверки причинного основания, не generic JS write.
- `resolution=generic_check` и ненулевой `check` по CDDA-owned результатам запрещены: никакого второго d20. В этом срезе отдельный Novgorod check-owner для иной области не вводится. `goal_result` модели — ожидание, actual outcome даёт CDDA.
- Физическое время — `activity.owner=domain`; `duration_class`, `effort`, `additional_activity` и числа в `mechanics` не списывают время, массу, moves или ресурс вторым кодом. Качественный `action_production` — предложение native owner, не полномочие изменять item state.

**Работы:**

1. Снять реальный список всех файлов, кэшей, autosave effects и побочных данных, которые пишет [`game::save()`](https://github.com/CleverRaven/Cataclysm-DDA/blob/0d8843f1c500052c3e026e3da6f8edaf5e00b626/src/game_io.cpp#L734-L783). Одного JSON персонажа недостаточно.

Фильтровать debug/hidden/не воспринимаемое; не реконструировать engine truth парсером строк.
4. Выбрать один самый узкий player-safe map transport: штатный viewport capture **если он реально доступен** или native клеточная проекция. Screenshot API требует SDL/TILES renderer и не является готовым headless transport. В браузере не пересчитывать LOS или карту мира.
5. Сохранить действующий UI invariant: `TurnScreen` только с **approved narration**; `FactualTurnDeliveryScreen v1` — ограниченное degraded recovery, **не** обычный «беспрозовый ход». Если нужны тихие microstep обновления, сначала отдельный scoped presentation proposal и audit; не обходить active contract.
6. Соблюдать clock policy, установленную уже в P3; проверить её также на UI ожидании и чтении прозы.
7. Ошибка/повтор narration никогда не исполняет физическое действие или реплику заново.

**Evidence:** UI screenshot/read model, журнал и narrator на той же подтверждённой границе, hidden-state leaks tests, счётчик вызовов LLM и сравнение native clock.  
**DoD / GO:** журнал, карта и проза согласованы; одна activity не даёт десятки prose calls; hidden facts не раскрыты, несохранённый прогресс не выдан за durable.
**STOP:** UI поддерживает только фальшивую карту, вытягивает правду из локализованного CDDA журнала или публикует unapproved/неподтверждённую прозу.

### P6 — Сквозная приёмка на временном мире

**Зависит от:** P1–P5; все critical gates закрыты.  
**Работы:** независимый воспроизводимый test run на целевом runtime, а не только unit tests/harness. Старт → свободный путь → препятствие → предмет → NPC и разговор → работа → interrupt → журнал/карта/проза → save → kill/reload → продолжение. Отклонение от предложенного маршрута не должно ломать механику.

**Evidence:** каждый проведённый **настоящий** gameplay run документируется по [WR §24.1](../../docs/governance/WORKFLOW_RULES.md) как отдельный санитизированный файл в `docs/playtests/` **в PR этого запуска**: exact SHA, ввод и видимый результат, mechanical outcomes, commit/persistence/readback, findings и verdict. Failed run не переписывать под green.

**DoD:** законченная acceptance matrix §6 и P4b; замер полного хода на локальном Qwen (все роли, native работа, сохранение на save-ходе отдельно от обычного); слепая оценка прозы с `dislike/improve/missing_facts` и доступными судьям исходными фактами. Владелец сам играет **15–20 минут**, его «да/нет» входит в решение. Историческая сцена явно отделена от технической fixture с modern CDDA content. Реальные метрики/ограничения и `GO_FOR_P7 / BLOCKED / REVISE_APPROACH` не заменяют отдельное разрешение на P7/cutover.

## 7. Fault-injection matrix: штатное сохранение и отдельная отладка

| Точка остановки | Допустимое наблюдение после recovery | Режим |
| --- | --- | --- |
| Авария между сохранениями, в том числе после native effect/прочитанной прозы | Последнее целое сохранение; игрок видит его игровой момент и потерю более позднего прогресса. Непринятые действия не replay-ятся автоматически | Штатный D215/D216 |
| В середине последовательного `game::save()` по запросу или часовому триггеру | Не принимается смесь карты, NPC и семантики; доступно предыдущее целое поколение | Штатный |
| Native save завершён, но копия/fsync/current ещё не завершены | Старое либо новое **полное** поколение, независимого semantic commit нет | Штатный |
| После принятия целого сохранения, до сообщения об успехе | Восстанавливается принятое сохранение; сообщение можно повторить без переисполнения мира | Штатный |
| Отказ записи, неполный/неразбираемый кандидат, заполнение диска | Старое сохранение доступно, ошибка видима; новое не выдаётся за принятое. `/dev/full` — инъекция ошибки, не доказательство полного физического диска | Штатный |
| Autosave попадает в окно создания поколения / совпадает с запросом игрока | Единственный native save owner, сериализованные точки сохранения, без второго writer и без смешанных файлов; инвентаризированы все autosave side effects | Штатный |
| Повторное падение во время восстановления | Ни recovery, ни очистка не уничтожают current/previous; вновь открывается целое сохранение | Штатный |
| Длительная activity/сон пересекает час, затем crash | Сохранён реальный partial progress; после reload продолжение не выдано за завершение; проверяется наступление часового save | Штатный |
| Незавершённые временные файлы / авария очистки | Временный кандидат не принят; current/previous сохранены | Штатный |
| Ошибка/повтор нарратора в живой сессии | Не повторяет действие; при crash применяется общий rollback, а не обещание сохранить каждый показанный ход | Штатный |
| До/после native effect, до/после operation receipt; неизвестный outcome | Проверки operation identity, uncertain и повторной доставки старого стенда | Только отладочный operation режим |
| Два координатора одновременно | Один writer экспериментального current, второй не портит результат; coordinator не становится штатным игровым owner | Только отладочный coordinator |
| Kill+retry pickup/consume, в том числе `mid_save` | Сверить точные количества/UID и реальное приращение времени; accepted operation не применяется повторно | Только отладочный operation режим |
| Pickup/consume до и после штатного save, затем kill | В принятом сохранении native баланс вещей и время соответствуют результату; несохранённый хвост целиком откатывается | Штатный |

Родной `game::save()` — основа и положительное доказательство штатной сериализации. Матрица проверяет только недостающую целостность **набора** и recovery вокруг него, не требует второго механизма сохранения. Если родного достаточно для проверяемого свойства — расширение не нужно. Если полный набор не восстанавливается, P4a = BLOCK; питание/переупорядочение записей отдельно **не проверены** и не обещаются.

## 9. Не входит в P0–P6 первого игрового среза

- Полная планировка Великого Новгорода, все концы/кварталы, население города, торговая экономика и многолетняя внепузырьковая жизнь каждого NPC.
