# Этап 15. Размещение стартовых NPC

## 1. Назначение этапа

Размещение стартовых NPC — это этап запуска новой партии, на котором LLM выбирает конкретных стартовых NPC только из заранее подготовленного `npc_candidate_set` и привязывает их к утверждённым G5-якорям.

Этот этап впервые может материализовать NPC как сущности партии, но только в пределах:

* выбранного региона;
* выбранной исторической рамки;
* выбранного G4;
* утверждённой G5-сцены;
* допустимых G5-якорей;
* региональных социальных ролей;
* региональных занятий;
* NPC-архетипов;
* именных пулов;
* правил видимости, доступа и риска.

Короткая формула:

```text id="ltx9oe"
g5_scene_graph
+ g5_scene_audit
+ npc_candidate_set
+ player_character
+ historical_frame
+ selected_start_node
→ initial_npc_placement_draft
```

LLM не придумывает людей “по ощущению сцены”. Она выбирает и материализует только разрешённые NPC-кандидаты.

## 2. Главное правило этапа

NPC может появиться в стартовой сцене только если:

```text id="y6crlc"
npc_candidate_id существует в npc_candidate_set
и npc_candidate совместим с выбранным place_template
и npc_candidate совместим с G5-якорем
и npc_candidate совместим с временем суток
и npc_candidate совместим с социальным порядком места
и причина присутствия объяснена
```

Запрещено:

* создавать NPC вне `npc_candidate_set`;
* создавать новую социальную роль;
* создавать новый NPC-архетип;
* создавать новую профессию;
* создавать новый именной пул;
* размещать NPC на несуществующий G5-якорь;
* размещать NPC на anchor, который не поддерживает NPC;
* размещать NPC в закрытую/скрытую зону без причины и access model;
* давать NPC невозможные знания;
* давать NPC предметы вне будущих item/property правил;
* писать диалог;
* писать стартовую прозу;
* менять G5-сцену для удобства размещения NPC.

## 3. Место этапа в pipeline

```text id="o7j2tx"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит стартового места
11. Генерация персонажа
12. Аудит персонажа
13. Материализация стартовой G5-сцены
14. Аудит G5-сцены
15. Размещение стартовых NPC
16. Размещение стартовых предметов
17. Проверка времени и света
18. Формирование visible context
```

Этап 15 идёт после G5-аудита, потому что NPC должен быть поставлен в конкретную точку сцены.

## 6. Что считается размещением NPC

Размещение NPC — это создание конкретной записи NPC партии и привязка этой записи к G5-якорю.

Минимальная формула:

```text id="gllsly"
npc_candidate_id
+ profile_level
+ g5_anchor_id
+ visibility
+ current_presence_reason
+ initial_attention
+ witness capability
→ npc_instance
```

Размещение не равно диалогу.
Размещение не равно квесту.
Размещение не равно полному биографическому архиву.

## 7. Типы NPC на этом этапе

### 7.1. Фоновый NPC

Фоновый NPC создаётся для видимости сцены, атмосферы, шума, порядка, свидетелей и бытового движения.

Фоновому NPC нужны:

```text id="x5l8gk"
краткая роль
видимый признак
текущее занятие
позиция на G5-якоре
видимость для персонажа
способность заметить действие
базовое настроение
отношение к порядку сцены
примерный режим ухода/движения
```

Фоновому NPC не нужны:

```text id="j0p8ff"
полная биография
тайный мотив
полные характеристики
полный инвентарь
долговременные отношения
имя, если оно не нужно
диалог
```

### 7.2. Сценический NPC

Сценический NPC создаётся, если в стартовой сцене должен быть адресный участник взаимодействия.

Сценическому NPC нужны:

```text id="0imxs9"
имя или краткое описание
роль и статус
причина быть здесь
текущее действие
отношение к игроку или чужаку
отношение к месту и порядку
знания в пределах роли
ближайшая цель
страх или ограничение
границы доступа
релевантные навыки, только если нужны
```

Сценический NPC не должен получать полный жизненный архив.

### 7.3. Ключевой NPC

Ключевой NPC создаётся только если:

```text id="9wxso1"
есть key_npc_seed
или npc_candidate_set разрешает key_seed profile
и стартовая сцена требует долговременной памяти
и G5/место поддерживает его присутствие
```

Ключевой NPC нужен, если он должен помнить игрока, контролировать ресурс, влиять на будущие последствия или быть связан с долгом, обещанием, тайной, конфликтом, зависимостью, властью или повторной встречей.

На стартовом размещении ключевой NPC всё ещё не должен превращаться в энциклопедическую биографию.

## 8. Источники данных

### 8.1. `npc_candidate_set`

Главный allowlist.

Используются:

```text id="tc6c9t"
npc_candidate_id
profile_level
npc_archetype_id
social_role_id
occupation_id
name_pool_ids
allowed_candidate_place_template_link_ids
allowed_place_template_ids
allowed_start_candidate_ids
game_function_candidates
time_and_season_compatibility
key_seed
source_trace
```

Если NPC-кандидата нет в `npc_candidate_set`, NPC не может быть создан.

### 8.2. `g5_scene_graph`

Используются:

```text id="zc8pi2"
g5_anchors
g5_edges
player_start_position
visibility_model
access_model
npc_materialization_slots
```

NPC может быть привязан только к существующему `anchor_id`.

Anchor должен поддерживать NPC:

```text id="oeu185"
anchor.supports.can_hold_npc = true
```

Если G5 содержит `npc_materialization_slots`, предпочтительно использовать их.

### 8.3. `historical_frame.clock`

Время суток и свет ограничивают NPC.

Проверяются:

```text id="o9lr83"
time_of_day
light_profile
season
hour
minute
```

Если `time_of_day=night/deep_night`, нельзя размещать дневную толпу, дневную торговлю, дневных чиновников, активный рынок или обычную дневную работу без специального основания.

### 8.4. `player_character`

Используется для:

```text id="yqma8c"
видимости NPC для игрока
знает ли персонаж NPC
является ли NPC своим/чужим
может ли NPC быть свидетелем
может ли NPC контролировать доступ
имеет ли NPC основание заметить персонажа
```

Персонаж игрока не должен автоматически знать имя, статус и скрытые мотивы NPC.

### 8.5. `item_profile_candidate_set`

На этом этапе item set используется только для будущих ресурсов NPC.

NPC может иметь указание:

```text id="l7epyp"
may_control_item_profiles_later
may_hold_item_profiles_later
may_guard_container_profiles_later
```

Но конкретные вещи NPC не создаются, если policy запрещает.

## 9. Алгоритм этапа

### 9.1. Проверить вход

Код проверяет:

```text id="r2vji2"
g5_scene_audit.pass = true
player_character_audit.pass = true
npc_candidate_set.selection_status = ready
g5_scene_graph.g5_anchors не пуст
```

Если NPC-кандидатов нет, но `allow_empty_scene_if_place_supports_it=true`, этап может вернуть `empty_allowed`.

Если место требует NPC, но кандидатов нет, этап блокируется.

### 9.2. Построить индекс NPC-кандидатов

Код строит:

```json id="n35kmx"
{
  "npc_candidate_by_id": {},
  "npc_candidates_by_profile_level": {},
  "npc_candidates_by_place_template_link_id": {},
  "npc_candidates_by_anchor_function": {},
  "npc_candidates_by_can_witness": {},
  "npc_candidates_by_can_control_access": {},
  "npc_candidates_by_can_trade": {},
  "npc_candidates_by_can_guide": {},
  "npc_candidates_by_can_share_knowledge": {}
}
```

### 9.3. Построить индекс G5-якорей

Код строит:

```json id="yq38qe"
{
  "anchor_by_id": {},
  "anchors_supporting_npc": [],
  "visible_anchor_ids": [],
  "audible_anchor_ids": [],
  "reachable_anchor_ids": [],
  "permission_required_anchor_ids": [],
  "hidden_anchor_ids": [],
  "npc_slots_by_anchor_id": {}
}
```

### 9.4. Отфильтровать NPC по месту

NPC-кандидат допустим для сцены, если:

```text id="rwcr7r"
selected_candidate_place_template_link_id ∈ npc_candidate.place_compatibility.allowed_candidate_place_template_link_ids
или selected_place_template_id ∈ npc_candidate.place_compatibility.allowed_place_template_ids
или selected_start_candidate_id ∈ npc_candidate.place_compatibility.allowed_start_candidate_ids
```

Если связи с выбранным местом нет, NPC-кандидат не размещается.

### 9.5. Отфильтровать NPC по времени суток

Проверка:

```text id="xosh6z"
npc_candidate.time_and_season_compatibility.time_of_day_match = true
```

Дополнительно LLM проверяет смысл:

```text id="db8gte"
может ли такой NPC находиться здесь именно сейчас
не является ли его занятие дневным
не требует ли его присутствие открытого дневного режима места
не нарушает ли ночной/закрытый доступ
```

Если NPC дневной, а сцена ночная:

```text id="99m7xj"
NPC_PLACEMENT_TIME_OF_DAY_CONFLICT
```

### 9.6. Отфильтровать NPC по сезону

Проверка:

```text id="ftktsi"
npc_candidate.time_and_season_compatibility.season_match = true
```

Если занятие NPC сезонно невозможно, кандидат отклоняется.

### 9.7. Отфильтровать G5-якоря

NPC можно поставить только на anchor, где:

```text id="kxe4zg"
anchor.supports.can_hold_npc = true
anchor.access.access_state != forbidden
anchor exists in g5_scene_graph.g5_anchors
```

Если NPC должен быть видимым, anchor должен быть видимым или слышимым по visibility model.

Если NPC должен быть скрытым или offscreen, anchor должен поддерживать hidden/offscreen presence.

### 9.8. Выбрать количество NPC

LLM выбирает количество NPC в пределах policy.

Правила:

```text id="p3j4xs"
не заполнять сцену людьми без необходимости
не добавлять толпу, если G5 маленькая
не добавлять ключевого NPC без key_seed
не добавлять сценического NPC без функции взаимодействия
не делать пустую сцену, если place/access logic требует присутствия человека
```

Если место может быть пустым, возвращается:

```json id="p13gh3"
{
  "placement_status": "empty_allowed",
  "npc_instances": []
}
```

### 9.9. Выбрать profile level

LLM выбирает уровень каждого NPC по необходимости:

```text id="ywqlrk"
background — видимость, шум, свидетель, быт
scene — адресное взаимодействие, доступ, помощь, препятствие, информация
key_seed — долговременные последствия, память, ресурс, власть, долг, конфликт
```

Нельзя повышать NPC до ключевого только потому, что он “интересный”.

### 9.10. Сформировать NPC instance

Для каждого выбранного NPC создаётся `npc_instance`.

Минимум:

```text id="2j8z82"
npc_instance_id
npc_candidate_id
profile_level
social_role_id
occupation_id
npc_archetype_id
g5_anchor_id
visibility_state
current_activity
presence_reason
attention_state
witness_capability
schedule_state
```

### 9.11. Назначить имя

Имя задаётся только если нужно.

Правила:

```text id="wtxkp0"
background NPC может быть unnamed
scene NPC может иметь имя, прозвище или visible label
key NPC должен иметь identity или stable label
name_pool_id обязателен для named NPC
player does not automatically know full name
```

Если имя неизвестно персонажу игрока, в visible layer позже должен попасть label, а не полное имя.

### 9.12. Назначить текущее действие

Текущее действие NPC должно быть:

* совместимо с ролью;
* совместимо с занятием;
* совместимо с G5-якорем;
* совместимо с временем суток;
* совместимо с сезоном;
* не создавать новую сцену.

Примеры допустимого формата:

```json id="6kl4cj"
{
  "current_activity": {
    "activity_type": "work | watch | rest | pass_through | wait | guard | trade | speak_to_someone | avoid_attention | sleep | unknown",
    "short_label": "string",
    "activity_basis": "string",
    "can_be_interrupted": true,
    "time_until_change_minutes": 10
  }
}
```

Нельзя писать длинную прозу или диалог.

### 9.13. Настроить видимость NPC

Для каждого NPC:

```text id="r1dg6p"
visible_to_player
audible_to_player
known_to_player
identified_by_player
requires_attention_check
requires_approach
hidden_from_player
```

Если `clock.light_profile=dark`, NPC может быть:

```text id="2gnpdb"
слышен, но не различим
виден как силуэт
заметен только близко
не виден без света
```

Нельзя показывать имя, статус и намерения NPC, если персонаж их не знает.

### 9.14. Настроить внимание и свидетельство

NPC должен иметь состояние внимания:

```text id="avspqy"
focused_elsewhere
watching_player
watching_area
busy
asleep
distracted
alert
afraid
drunk
injured
absent_minded
```

И способность быть свидетелем:

```text id="fbw8og"
can_witness_player_action
can_hear_conversation
can_identify_player
can_notice_theft
can_notice_violence
can_call_others
can_block_access
```

Это нужно для честных последствий.

### 9.15. Настроить доступность NPC

Для сценического NPC:

```text id="h8ig9q"
can_be_addressed_now
requires_approach
requires_permission
will_ignore_if_busy
will_react_to_threat
will_react_to_theft
will_react_to_player_identity
```

Для фонового NPC обычно достаточно witness/attention state.

### 9.16. Настроить память NPC

Фоновый NPC:

```text id="xx9ozu"
обычно не имеет долговременной памяти
может стать witness memory только если увидит значимое действие
```

Сценический NPC:

```text id="gwvdxx"
имеет краткую память текущего взаимодействия
может быть повышен до key при последствиях
```

Ключевой NPC:

```text id="3djyib"
имеет persistent memory profile
но только если key_seed или policy это разрешает
```

### 9.17. Не создавать предметы NPC

На этом этапе запрещено создавать полный NPC inventory.

Разрешено только:

```json id="urqsg7"
{
  "npc_resource_hints": {
    "may_control_item_profile_candidate_ids": [],
    "may_hold_item_profile_candidate_ids": [],
    "may_guard_container_profile_candidate_ids": [],
    "requires_item_placement_later": true
  }
}
```

Конкретные вещи NPC создаются на этапе предметов или при взаимодействии, через item profile и property rules.

## 14. Работа LLM на этапе

На этом этапе LLM обязательна, потому что размещение NPC — это смысловая материализация людей в конкретной сцене.

LLM выбирает:

* каких NPC-кандидатов материализовать;
* сколько NPC нужно;
* какой у каждого profile level;
* на какой G5-якорь поставить NPC;
* виден ли NPC игроку;
* слышен ли NPC игроку;
* чем NPC занят;
* может ли NPC быть свидетелем;
* может ли NPC взаимодействовать сейчас;
* какие ограничения и риски создаёт его присутствие.

LLM не выбирает:

* новые социальные роли;
* новые профессии;
* новые архетипы;
* новые именные пулы;
* новые G5-якоря;
* новые предметы;
* диалог;
* стартовую прозу;
* скрытый сюжет.

## 15. LLM-параметры

### 15.1. `InitialNpcPlacer`

Назначение: выбрать стартовых NPC из `npc_candidate_set` и привязать их к G5-якорям.

```json id="m96iye"
{
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "thinking": {
    "type": "enabled"
  },
  "reasoning_effort": "high",
  "temperature": null,
  "top_p": null,
  "max_tokens": 9000,
  "response_format": {
    "type": "json_object"
  },
  "context_budget": {
    "target_input_tokens": 90000,
    "hard_input_limit_tokens": 220000,
    "reserve_output_tokens": 9000
  }
}
```

Используется `deepseek-v4-pro`, потому что размещение NPC требует смыслового выбора между ролями, anchor-доступностью, видимостью, временем суток, социальным порядком и будущими последствиями. DeepSeek API поддерживает `deepseek-v4-pro`, `deepseek-v4-flash`, `thinking` и `reasoning_effort`; для сложных запросов используется `reasoning_effort: "high"`.

Код обязан проверить:

1. `schema === "initial_npc_placement_draft"`.
2. `version === 1`.
3. `placement_status` входит в enum.
4. Каждый `npc_instance_id` уникален.
5. Каждый `npc_candidate_id` существует в `npc_candidate_set`.
6. Каждый `profile_level` входит в enum.
7. `profile_level` не выше разрешённого candidate.
8. Каждый `social_role_id` совпадает с candidate.
9. Каждый `occupation_id` совпадает с candidate или null допустим.
10. Каждый `npc_archetype_id` совпадает с candidate.
11. `key_npc_seed_id` существует для key NPC.
12. Каждый `g5_anchor_id` существует.
13. Каждый `g5_minilocation_id` существует.
14. Anchor supports `can_hold_npc=true`.
15. Anchor belongs to selected G4.
16. NPC совместим с selected place template.
17. NPC совместим с season.
18. NPC совместим с time_of_day.
19. Visibility NPC совместима с anchor visibility.
20. NPC не видим, если anchor hidden and no reason.
21. Name pool exists for named NPC.
22. Background NPC не имеет excessive profile.
23. Scene NPC имеет interaction state.
24. Key NPC имеет persistence basis.
25. NPC knowledge не содержит hidden/player-only facts.
26. NPC resource hints не создают concrete items.
27. Нет `item_id`.
28. Нет `dialogue`.
29. Нет `visible_scene`.
30. Нет `intro_prose`.
31. Нет `hidden_event`.
32. `source_trace` не пустой, если require_source_trace=true.
33. `audit_self_check.evidence` не пустой.
34. Если `audit_self_check.pass=false`, concerns не пустой.
