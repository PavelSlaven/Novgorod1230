1. **Заявка игрока**
   Игрок пишет свободно: кто он примерно, где хочет начать, какой тон игры, без точных игровых сущностей.

2. **Нормализация заявки**
   LLM превращает заявку в структурированный запрос: эпоха, регион, желаемый тип персонажа, ограничения, неизвестные места.
   
3. **Выбор исторической рамки**
   Фиксируются год, сезон, время суток, регион, политическая/социальная обстановка. Без сцены и NPC.

4. **Загрузка регионального контекста из `world_base`**
   Код достаёт : профиль региона, timeline, social roles, occupations, place rules, route rules, weather, item profiles, NPC pools.

5. **Подбор допустимых стартовых G1–G4 кандидатов**
   Код выбирает не одно место, а список разрешённых стартовых узлов из карты и региональных ограничений.

6. **Подбор допустимых place templates**
   Для кандидатов подтягиваются только разрешённые типы мест: двор, усадьба, погост, пристань, торг, дорога и т.п.

7. **Подбор допустимых NPC-кандидатов**
   Из региональных социальных ролей, занятий, NPC-архетипов и именных пулов формируется ограниченный список возможных NPC.

8. **Подбор допустимых предметных профилей**
   Подтягиваются item/container/property rules для выбранного типа места. Предметы не возникают из желания игрока.

9. **LLM выбирает стартовый узел из candidate set**
   LLM не придумывает место, а выбирает один допустимый G4/G3/G2/G1-кандидат и объясняет причину выбора.

10. **Аудит выбора стартового места**
    Проверяется: место есть в `world_base`, подходит по региону, сезону, времени суток, социальному статусу и заявке игрока.

11. **Генерация персонажа игрока**
    LLM создаёт персонажа внутри выбранной рамки: происхождение, статус, навыки, здоровье, вещи, цель, ограничения.

12. **Аудит персонажа**
    Проверяется историчность, социальная допустимость, соответствие региону, отсутствие невозможных предметов и статусов.

13. **Материализация стартовой G5-сцены**
    LLM разворачивает выбранную G4-локацию в минилокации и G5-якоря только по допустимым G5-шаблонам.

14. **Аудит G5-сцены**
    Проверяется, что все anchors, проходы, видимые объекты, закрытые зоны и риски допустимы для выбранного G4-типа.

15. **Размещение стартовых NPC**
    LLM выбирает NPC только из допустимых региональных ролей/архетипов и привязывает их к G5-якорям.

16. **Размещение стартовых предметов**
    LLM материализует только причинно обоснованные предметы из item/container/property profiles выбранного места.

17. **Проверка времени и света**
    Отдельный gate сверяет `clock`, `season`, `weather`, `light`, `visible_scene`. Ночь не может пройти как “короткий световой день”.

18. **Формирование карты знаний персонажа**
    Изолированный Builder/Auditor/Repair-блок формирует `character_knowledge_map`, `known_nearby_paths`, независимый audit и write projection. Live party-state не записывается.

19. **Формирование полного hidden state**
    Сохраняется полная сцена: скрытые NPC-мотивы, закрытые двери, чужие вещи, риски, события, но без вывода игроку.

20. **Формирование visible context package**
    Из hidden state выбирается только видимое/слышимое/известное персонажу. Этот пакет получает narrator.

21. **Аудит visible context**
    Проверяется отсутствие утечек скрытой информации и соответствие времени, месту, G5-якорям, NPC и предметам.

22. **Генерация стартовой прозы narrator**
    Narrator пишет вводную сцену только из `visible_context_package`, без добавления фактов.

23. **Аудит стартовой прозы**
    Проверяется, что narrator не добавил новых NPC, предметов, дверей, угроз, времени суток или знаний.

24. **План записи в party-базу и независимый аудит**
    Формируется атомарный write plan, включая root/snapshot/normalized knowledge layer и проверку полноты проекции. На этом этапе live-state не пишется.

25. **Commit gate и атомарный commit**
    Код проверяет схемы, FK, hashes, knowledge projection, idempotency и rollback, выполняет dry-run и только затем атомарно пишет старт партии.

26. **Первый игровой экран**
    Игрок получает стартовую прозу, текущую позицию, видимые варианты внимания/действий и может сделать первый ход.
