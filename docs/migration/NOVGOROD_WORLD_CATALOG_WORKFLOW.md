# Новгородская карта: staging, очередь G1 и импортные границы

Дата: 2026-07-12  
Статус: реализованный технический контур, историческая G1-маска ожидает утверждения.

## 1. Область изменения

Добавлены:

- `@rus/world-catalog-workflow`;
- JSON-контракты regional map revision, G1 mask, G1 queue, G1 package и boundary contract;
- staging-каталог Новгородской земли;
- manifest неизменяемого baseline v6;
- исследовательская ревизия `novgorod_1230_research_revision_001`;
- очередь из 70 legacy G1;
- подготовленный входной snapshot первой legacy-ячейки `gn_nov_g1_00_06`.

## 2. Архитектурная граница

Инструмент выполняет только технические операции:

```text
входные файлы
→ структурная проекция
→ валидация
→ детерминированная очередь
→ dry-run
```

Он не назначает:

- политический статус;
- субрегион;
- долю суши и воды;
- историческую доказательность;
- игровую пригодность;
- названия;
- места или маршруты.

Отсутствующее смысловое значение остаётся `null` и блокирует запись.

## 3. Текущий статус v6

`novgorod_v6_legacy_baseline` зарегистрирован только как:

```text
read_only_legacy
id_preservation_source
historical_approval = false
```

Baseline включает SHA-256 для G1–G4, полного графа, naming register, scale register и G1-источниковых таблиц.

## 4. Ревизия исследования

`novgorod_1230_research_revision_001`:

- исторический горизонт: 1230 год;
- размер G1: 32 × 32 км;
- родитель: v6 legacy baseline;
- ID сохраняются только для той же сущности;
- статус: `staging`;

## 5. Результат проверки G1-маски

Legacy-проекция сохраняет координаты и ссылки, но не подставляет новые смысловые поля.

Поэтому 70 G1 имеют блокировки:

```text
missing_control_status
missing_subregion_id
missing_land_fraction
missing_water_fraction
missing_playability_status
```

Это ожидаемый результат. Он доказывает, что код не превратил старую 70-ячеечную карту в утверждённую историческую маску автоматически.

## 6. Очередь

Порядок фиксирован:

```text
ORDER BY global_grid_y DESC, global_grid_x ASC
```

Первая legacy-запись:

```text
gn_nov_g1_00_06
```

Она пока имеет `work_status = blocked`. Её snapshot подготовлен для будущего аудита, но смысловая работа не начинается до утверждения глобальной маски.

## 7. Первая ячейка

Подготовленный legacy snapshot содержит:

```text
18 G2
16 G3
146 G4
181 узел текущей ветви
490 рёбер, касающихся ветви
```

Snapshot является доказательством старого состояния, а не утверждённым результатом.

## 8. Knowledge-source

Актуальные документы Новгородской земли подготовлены как отдельный import candidate. Production corpus не заменён автоматически, поскольку действующий knowledge-source связывает corpus с approved graph snapshot и точным RAG embedding snapshot.

До переключения обязательны:

1. semantic graph update;
2. новые RAG embeddings для изменённых chunks;
3. `knowledge:generate`;
4. `knowledge:check`;
5. полный regression;
6. аудит критика.

Старый corpus оставлен работоспособным. Это сознательная fail-closed граница, а не пропуск работы.

## 9. Следующее действие

Следующий смысловой этап:

```text
реконструкция и утверждение расширенной G1-маски 1230 года
```

После её утверждения:

1. staging mask заменяется новой ревизией;
2. очередь пересобирается;
3. первая полная запись получает `unprocessed`;
4. запускается изолированный cell pipeline.
