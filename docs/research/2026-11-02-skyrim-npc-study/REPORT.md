## Метод

Для глубокого чтения следовало выбрать от 4 до 8 наиболее подходящих проектов, остальные занести в список с причиной исключения ([task-skyrim.md](task-skyrim.md):39). Вопросы были разделены на В1–В8: промпт, ответ и действия, задержка, память, восприятие, поводы вызова модели, проверка выдумок и известные провалы ([task-skyrim.md](task-skyrim.md):45, 101). Исходники и страницы разрешалось читать, но запрещалось запускать или собирать моды и проекты; размер итогового отчёта ограничивался 80 000 байт ([task-skyrim.md](task-skyrim.md):58, 64, 65, 66, 67, 73, 98).

## Результаты

Отчёт содержит 11 находок итога, ответы на В1–В8, таблицу соответствия из 31 строки (находка → проект и источник → что взять → как у нас → чего не брать) и 9 пунктов «чего не брать вообще» ([report-skyrim-llm.md](report-skyrim-llm.md), разделы 1, 3, 4, 5).

Находки итога:

1. Вход модели раскладывают под кэш префикса: неизменное (личность, правила, формат, список действий) — в начале, изменчивое этой реплики — в последнем сообщении; окно истории начинается с «якорного» события, чтобы начало истории не сдвигалось на каждой реплике (SkyrimNet).
2. Рабочие промпты NPC малы: шаблон Mantella около 200 токенов плюс биография, system мода 194492 около 500 токенов (оценка); наш образец D357 (около 1,5 тыс. токенов) в том же классе.
3. Модель зовут последней, после кодовых «ворот»: не идёт ли уже ответ, пауза после прошлого вызова, предусловия мира, есть ли из чего выбирать (NarrativeEngine). События мира сами модель не зовут, а копятся до ближайшей реплики (Mantella).
4. Решения — отдельными малыми запросами: модель выбирает из вариантов, перечисленных кодом, и вариант «никто / ничего» есть всегда (SkyrimNet).
5. Список допустимых действий строит код на каждый момент; модель дописывает одну строку действия после речи; неизвестное действие отвергается, один повтор, потом отказ; после ответа код заново проверяет условия мира и исполняет действие сам; итог или отказ возвращается NPC событием.
6. «Deterministic» мода 194492 — проверяющий код вокруг недоверенного предложения модели: состояние квеста меняет только код. Текст речи не проверяет никто: ни один из семи проектов не проверяет опору сказанного.
7. Во вход идёт только изменение (место, время, погода, люди рядом, новые события — по умолчанию не больше 5); однородные события склеиваются; реплики помечены «сказано тебе» или «подслушано».
8. Допуск NPC к знаниям решает код без модели: у статьи знаний — классы, у NPC — теги, ответ «подробно / кратко / отказ», во вход — не больше 3 статей (CHIM).
9. Память NPC — личные записи от первого лица с типом, важностью и игровой датой; во вход — отобранные записи, отбирает код (CHIM) или модель с обязательным «ничего» (SkyrimNet).
10. Измеренной задержки почти нигде нет. Единственные числа — у автора мода 194492 (дообученная модель около 2B): медиана 0,98 с, P95 по его же CSV — 4,9 с, а не 1,25 с, как в README. Общие меры: потоковая выдача, вывод по предложениям, короткий ответ, вызов функций модели выключен, потому что замедляет ответ.
11. Знания по теме подбирает код: постоянные записи плюс записи по ключевым словам последних сообщений, с бюджетом в токенах (SillyTavern, World Info). SillyTavern ставит сработавшие знания в начало промпта и этим ломает кэш при смене темы; знания по теме должны идти в конец.

## Выводы

Для Novgorod1230 из отчёта следует:

- порядок частей входа NPC под кэш префикса и знания по теме в конце — дополнение к образцу промпта D357 и к #827;
- момент вызова модели решает код (ворота), модель выбирает из списка, построенного кодом, с вариантом «ничего» — это ложится на эскалацию реакции NPC #966 (D352) и решение владельца D363;
- исполняет действие код по закрытому словарю, отказ возвращается NPC событием; словарь в движке уже есть — родные эффекты диалога CDDA (`src/npctalk.cpp:8777-8847`);
- во вход NPC — только изменения со склейкой однородных событий; родная склейка повторов есть в журнале сообщений CDDA (`src/messages.cpp:142`);
- допуск к знаниям и отбор памяти делает код — устройство переносится на знания мира по сословию, ремеслу и месту;
- проверка опоры сказанного остаётся нашей: готового решения нет ни у одного из семи проектов;
- задержку нужно мерить на нашей локальной Qwen стендом (D41): чисел, применимых к нашей модели и железу, отчёт не даёт.

Не брать ([report-skyrim-llm.md](report-skyrim-llm.md), раздел 5): речь без проверки опоры; кодовые заглушки вместо ответа (#220); выдумывание моделью людей и событий мира; выбор поступка за NPC кодом; вызов модели по таймеру при неизменной обстановке (D352); молчаливую правку и пропуск; облачные модели и дообучение; раздутую постоянную часть ради озвучки; английский промпт (D289).
