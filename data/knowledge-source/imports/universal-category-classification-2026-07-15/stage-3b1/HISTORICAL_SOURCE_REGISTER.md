# Этап 3B-1 — реестр исторических оснований предметного каталога

**Статус:** `editorial_source_register_not_applied`
**Дата:** `2026-07-15`
**Регион:** `region_novgorod_land`
**Целевая дата:** около 1230 года

## 1. Назначение

Реестр поддерживает упрощённую историческую проверку каталога из 120 предметных и контейнерных типов. Проверка отвечает только на вопрос:

```text
мог ли объект этого общего типа встречаться
в Новгородской земле около 1230 года
и не является ли он явным анахронизмом?
```

Она не доказывает автоматически точную археологическую типологию, массу, размеры, частотность, стоимость, социальную распространённость, материал каждого экземпляра или конкретную конструкцию.

Все записи каталога остаются `draft`. Этот реестр не является production source dataset и не создаёт `approved` regional permission.

## 2. Классы исторического основания

| Код | Смысл | Допустимое использование | Что нельзя утверждать |
|---|---|---|---|
| `direct_novgorod` | тип непосредственно засвидетельствован материалами Новгорода или Новгородской земли | общий тип допустим как региональный authoring candidate | точную форму, дату каждого экземпляра, частотность и социальную норму без узкого источника |
| `direct_novgorod_or_rus_period` | тип поддерживается новгородской археологией либо надёжной древнерусской аналогией XII–XIII веков | общий функциональный template может быть подготовлен для Новгорода | локальную распространённость и специфически новгородскую конструкцию |
| `rus_period_with_novgorod_context` | тип обычен для материальной культуры Руси периода и не конфликтует с новгородским контекстом | черновой региональный кандидат с `medium` confidence | объявлять его характерным, частым или обязательным для Новгорода |
| `comparative_period` | тип засвидетельствован в сопоставимой северо- или восточноевропейской средневековой культуре | только `needs_review`, если нет регионального подтверждения | выдавать сравнительную аналогию за прямую новгородскую находку |

## 4. Решение об источниках для текущего каталога

1. Для широкого типа достаточно одного подходящего source family и отсутствия известного анахронизма.
2. Каждая строка получает `evidence_class`, `source_family` и `limits`.
3. `direct_novgorod_or_rus_period` не маскируется под `direct_novgorod`: точное основание уточняется перед присвоением `approved`.
4. Сравнительные материалы допускаются только как вспомогательные.
5. Источник не задаёт packing slots, массу, quantity, commonness, цену, equipment role или ownership policy.
6. Узкое утверждение требует отдельной проверки: точный археологический тип, конкретный материал, конструкция, размер, техника производства, распространённость или социальное право.

## 5. Evidence gaps

| Gap | Значение | Влияние |
|---|---|---|
| `HISTORICAL_PRESENCE_EVIDENCE_REQUIRED` | для строки не найдено даже общего основания присутствия в регионе/периоде | строка не переводится выше `needs_review` |
| `NARROW_TYPOLOGY_EVIDENCE_REQUIRED` | требуется точная конструкция, разновидность или датировка | общий template может остаться draft, узкая разновидность блокируется |
| `COMMONNESS_NOT_ESTABLISHED` | источник не доказывает частотность | запрещено задавать исторический materialization weight как частотность |
| `PHYSICAL_PARAMETER_EVIDENCE_REQUIRED` | неизвестны размеры или масса | параметры не выдумываются; требуется отдельная игровая процедура или источник |
| `CONTAINER_COMPATIBILITY_TOO_COARSE` | пригодность зависит от материала, конструкции, закрытия и состояния | content profile не создаётся из одной формы контейнера |
| `CANONICAL_LEGACY_ROWS_UNAVAILABLE` | tracked bundle не содержит старых item/container rows | migration inventory для внешней базы остаётся deferred |

## 6. Проверки этого реестра

Выполнена редакторская проверка:

- каждый source family имеет устойчивый ID;
- исторические и проектные источники разделены;
- общий факт присутствия отделён от узких утверждений;
- сравнительные данные не объявлены прямыми новгородскими находками;
- ни один source family не создаёт runtime permission;
- все нерешённые вопросы выражены как gaps или limits.

Этот реестр сам по себе не служит исполняемым dataset. В supplemental bundle 15 agriculture/fishing item templates имеют FK-normalized `item_template_source_bindings` на существующие `src_novgorod_agriculture` и `src_novgorod_promysly`: `claim_scope = historical_presence`, `status = draft`, `review_status = needs_review`. Параллельные `record_sources` links с `support_type = background` сохраняют аудитный след. Их presence проверяется в digest-pinned parent source archive. Ни binding, ни record_sources не создают regional permission и не разрешают promotion до reviewed evidence. Остальные 105 templates сохраняют `SOURCE_RECORD_REQUIRED`/`HISTORICAL_PRESENCE_EVIDENCE_REQUIRED`.
