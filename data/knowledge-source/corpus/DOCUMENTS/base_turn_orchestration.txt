# Базовая оркестрация хода

## Статус и граница миграции

Этот документ задаёт production v3 command sequence. Принятое историческое P28
evidence не переключало composition; последующий `versioned production
activation cutover` release `spatial-v3-production-v1` сделал v3 sole
production path. Документ не разрешает partial activation, dual write,
first-entry fallback или смешанный request path.

Temporal World v4 дополняет sequence профильным нормативом
`temporal_world_and_interruptible_activities.md` (status `active`). Target
turn сначала строит candidate post-change state; code-owned projector создаёт
и проверяет player-safe candidate, включая hidden-leak validation. Затем
factual state, exact clock/effects, `VisiblePackagePersistenceEnvelope` и
presentation-pending metadata сохраняются одним atomic commit. Narrator
вызывается после commit только из persisted package и не входит в factual
write plan.

## 1. Границы оркестратора

Player input — намерение, не факт. Orchestrator загружает pinned factual state и player-safe knowledge projection, классифицирует команду, получает deterministic proposals, валидирует command и передаёт один approved combined write plan единственному commit writer. LLM может интерпретировать/создавать prose лишь в bounded protocol; он не создаёт topology, G5/G6, route, endpoint или state change.

Ни stage не читает hidden global state и не делает скрытый DB/filesystem/network/LLM call. Каждый stage имеет typed input/output/errors и не запускает соседний stage.

## 2. Явная последовательность команд

```text
1. parse/normalize intention (без признания нового world fact)
2. load factual + knowledge context и expected versions
3. classify: immediate_action | timed_activity | timed_traversal | topology/preparation command
4. resolve proposal и mechanical readiness
5. если required: отдельно commit topology/frontier resolution ИЛИ target preparation
6. выполнить новую path query; выбрать только ready executable option
7. validate exact endpoints, pins, capability, locks и idempotency
8. create immutable plan + planned execution
9. dispatch one explicit action/activity/traversal child command
10. apply proposals to an immutable candidate post-change projection
11. include append-only history/events and exactly-once time integration in that candidate
12. project the candidate into a factual player-safe package
13. validate the candidate package against the hidden-information boundary
14. build one combined write plan from validated facts and visible package
15. atomically commit facts, visible package and presentation-pending metadata
16. after commit, invoke narrator from that persisted package only
17. build the final screen projection from persisted package and narration
```

Topology/frontier resolution и preparation не перемещают traveller, не продвигают time и не превращают old option в ready. Нужна новая query с `derived_from_option_id`.

## 3. Отдельные стадии выполнения

- `immediate_action`: atomic action units; no time, no continuous progress.
- `timed_activity`: exact rational elapsed, activity attempt/history; no physical segment progress.
- `timed_traversal`: ровно один pinned physical segment; interval state machine и exact progress.

Cross-G4 movement больше не является atomic «first entry materialization + movement». Generated G5 topology разрешается только явной topology command из approved finite frontier; endpoint scenes materialизуются только target preparation. Ordinary traversal использует уже готовый exact endpoint и не создаёт semantic data.

## 4. Commit и single writer

Resolvers/materializers/validators не пишут состояние и не выбирают option при commit. Commit validator проверяет versions, endpoint snapshots, dependency pins, readiness, capability, state-machine transition, idempotency и lock order. Единственный commit component применяет approved write set в одной транзакции, создаёт immutable plan/history/change set и clock update максимум один раз.

При data gap, empty candidate set, missing terminal target/route/endpoint/preparation или invalid pin commit fail-closed с typed error. Нет semantic fallback, teleport, nearest endpoint, free time или v3→v2 fallback.

## 5. Порядок для time и carriers

Time-bearing command передаёт exact rational elapsed только в time owner. Во время root transport travel один synchronized slice владеет общим clock; carrier-local results не обновляют его отдельно. Root/attached ownership change завершает current plan на exact handoff endpoint; следующий movement — new plan, не transfer active execution.

## 6. Player projection

Factual visible package формируется кодом из разрешённого
knowledge/perception слоя и сохраняется в том же commit, что и state change.
После commit presentation читает именно этот pin-bound package. Factual hidden
route, candidates, diagnostics, unselected options и internal errors не
попадают в prose/UI. Presentation и narrator не создают factual topology,
temporal effect или consequence.
