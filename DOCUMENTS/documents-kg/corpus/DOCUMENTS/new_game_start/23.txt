# Этап 23. Аудит стартовой прозы narrator

## 0. Нормативная редакция 3: изолированный Stage 23

Этот раздел имеет приоритет над редакцией 2 и всеми более старыми формулировками ниже при любом противоречии.

Stage 23 является отдельным изолированным audit-блоком. Он получает только точный `narrator_prose_audit_input`, не читает global context, stage registry, mutable pipeline state, outputs других этапов, hidden state, raw character knowledge, Stage 22 diagnostics, repair logs или полный Stage 21 audit.

```text id="stage23-isolated-contract-v3"
exact narrator_prose_audit_input
→ narrator_prose_code_precheck
→ NarratorProseSemanticAuditor
→ NarratorProseAuditFormatRepairer только при format error
→ повторный auditor / SeniorNarratorProseSemanticAuditor
→ NarratorProseAuditRouter при pass=false
→ code validation repair route
→ stage23_narrator_prose_audit_result
→ strict Stage 24 handoff
```

Код проверяет структуру, digests, permissions, reference integrity, enum и совместимость маршрута. Семантическое решение о новых фактах, hidden leaks, слухах и противоречиях принимает LLM-аудитор. Код не фабрикует findings и не маскирует Stage 23 findings под Stage 21 audit.

Подмена готового Stage 23 output и произвольный `options.input` запрещены во всех окружениях. Тесты подменяют только role executors.

### 0.3. Role boundaries

`NarratorProseSemanticAuditor` и senior auditor получают только exact input и output contract. Они не получают context или скрытые источники.

Role config:

```text id="stage23-role-config-v3"
NarratorProseSemanticAuditor: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
NarratorProseAuditFormatRepairer: deepseek-v4-flash, thinking disabled, reasoning low, JSON mode
SeniorNarratorProseSemanticAuditor: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
NarratorProseAuditRouter: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
```

Format repairer исправляет только JSON-формат audit output. Он не имеет права менять semantic pass, изобретать concerns/evidence или выбирать маршрут.

### 0.4. Strict audit contract

Audit обязан содержать все нормативные check-блоки, непустой массив строк `evidence`, валидные concern objects и согласованные permissions.

При `pass=true`:

```text id="stage23-success-invariants-v3"
concerns = []
repair_route = null
can_show_to_player = true
can_write_player_visible_message = true
can_mark_opening_scene_presented = true
```

При `pass=false`:

```text id="stage23-failure-invariants-v3"
concerns.length > 0
evidence.length > 0
repair_route после Router обязателен
все commit permissions = false
```

Concern code и severity входят только в утверждённые enum. Audit не может содержать `prose`, `new_prose`, `modified_prose`, `narrator_starting_prose`, `modified_action_options`, `visible_context_package`, `full_hidden_scene_state`, `character_knowledge_map`, `hidden_state` или `repair_payload`.

### 0.5. Router и совместимость маршрутов

Semantic auditor возвращает findings. При `pass=false` отдельный `NarratorProseAuditRouter` выбирает:

```json id="stage23-route-v3"
{
  "version": 1,
  "schema": "narrator_prose_audit_route",
  "request_id": "string",
  "return_to_stage": "narrator_prose_format_repair | narrator_prose_semantic_repair | visible_context_semantic_repair | visible_context_audit | time_light_semantic_repair | character_knowledge_map_semantic_repair | full_hidden_state_semantic_repair | blocked",
  "repair_kind": "string",
  "reason": "string",
  "supporting_concern_codes": []
}
```

Код проверяет enum, наличие supporting concern codes и совместимость concern→route. Код не заменяет выбранный Router `repair_kind` своим семантическим значением.

### 0.6. Upstream repair request

Stage 23 findings не превращаются в фиктивный Stage 21 audit. Для upstream repair формируется отдельный transport object:

```json id="stage23-upstream-repair-v3"
{
  "version": 1,
  "schema": "stage23_upstream_repair_request",
  "request_id": "string",
  "source_stage": 23,
  "target_stage": 17,
  "repair_route": {},
  "concerns": [],
  "evidence": [],
  "visible_context_package_digest": "sha256:<digest>",
  "narrator_starting_prose_digest": "sha256:<digest>"
}
```

### 0.7. Repair cycles

Format и semantic repair строго разделены:

```text id="stage23-repair-separation-v3"
narrator_prose_format_repair
→ NarratorProseFormatRepairer Stage 22
→ повтор Stage 23

narrator_prose_semantic_repair
→ NarratorProseSemanticRepairer Stage 22
→ повтор Stage 23
```

Pipeline выполняет initial audit и максимум три полных цикла `repair → re-audit`. Последний repair без последующего Stage 23 audit запрещён. Repair signature включает route, repair kind, concern codes, evidence digest, package digest и prose digest.

### 0.9. Strict Stage 24 handoff

Stage 24 запускается только если одновременно верны:

```text id="stage23-stage24-gate-v3"
Stage 23 result schema/version/request_id valid
Stage 23 pass = true
Stage 23 precheck pass = true
Stage 23 audit pass = true
evidence non-empty
repair_route = null
all three output permissions = true
visible package digest matches current Stage 20
prose digest matches current Stage 22
Stage 22 and Stage 23 request IDs match current request
```

Устаревшие примеры ниже, где Stage 23 получает отдельные `historical_frame`, `weather_state`, `current_position` или полный `visible_context_audit`, не применяются. Эти данные доступны только через утверждённый `visible_context_package` и safe approval.


## 0. Нормативная редакция 2: handoff и repair loop Stage 22→23

Этот раздел имеет приоритет над всеми более старыми формулировками ниже, если между ними есть противоречие.

Stage 23 получает только:

```text id="stage23-exact-boundary-v2"
approved visible_context_package
+ visible_context_package_digest
+ visible_context_audit_approval
+ narrator_starting_prose из Stage 22 result bundle
+ audit_policy
```

Stage 23 не получает Stage 22 diagnostics/generation history, полный Stage 21 audit, hidden state, raw character knowledge или global pipeline context.

Exact input:

```json id="stage23-input-v2"
  "visible_context_approval": {
    "version": 1,
    "schema": "visible_context_audit_approval",
    "pass": true,
    "visible_context_package_digest": "sha256:<canonical-json-digest>"
  },
  "narrator_starting_prose": { "version": 1, "schema": "narrator_starting_prose", "prose_status": "drafted" },
  "audit_policy": {
    "compare_only_against_visible_context_package": true,
    "reject_added_facts": true,
    "reject_added_npcs": true,
    "reject_added_items": true,
    "reject_added_containers": true,
    "reject_added_doors_or_exits": true,
    "reject_added_threats": true,
    "reject_added_time_of_day": true,
    "reject_added_character_knowledge": true,
    "reject_hidden_leaks": true,
    "reject_private_motives": true,
    "reject_closed_container_contents": true,
    "reject_future_events": true,
    "reject_unknown_true_ownership": true,
    "reject_rumor_as_fact": true,
    "reject_uncertainty_as_fact": true,
    "reject_action_labels_using_hidden_truth": true,
    "reject_raw_json_or_debug_text": true,
    "reject_time_light_conflict": true,
    "reject_position_conflict": true,
    "require_must_include_coverage": true,
    "require_must_not_include_compliance": true,
    "require_evidence": true,
    "require_repair_route_on_fail": true
  }
}
```

Digest пересчитывается кодом. Stage 23 не запускается, если Stage 22 result bundle, Stage 22 precheck, handoff permission или digest invalid.

Успешный и проваленный audit обязаны иметь непустой `evidence`. При `pass=true` repair route равен null и все permissions true. При `pass=false` concerns и repair route обязательны, все permissions false.

Repair routing:

```text id="stage23-routing-v2"
narrator_prose_format_repair / narrator_prose_semantic_repair
→ targeted Stage 22 repair по concerns/evidence
→ повтор Stage 23

visible_context_semantic_repair / visible_context_audit
→ Stage 20 repair
→ Stage 21
→ Stage 22
→ Stage 23

time_light_semantic_repair
→ Stage 17→20→21→22→23

character_knowledge_map_semantic_repair
→ Stage 18→19→20→21→22→23

full_hidden_state_semantic_repair
→ Stage 19→20→21→22→23

blocked
→ hard stop
```

Повторный одинаковый repair signature запрещён. Максимум три repair cycles. Старый положительный Stage 22/23 result после любого upstream repair не переиспользуется.

Provided Stage 23 audit запрещён в production pipeline; тесты подменяют auditor executor.

## 1. Назначение этапа

Аудит стартовой прозы narrator — это gate-этап между генерацией стартовой прозы и выводом текста игроку.

Этап проверяет, что narrator:

* не добавил новых NPC;
* не добавил новые предметы;
* не добавил новые двери, проходы, ворота, дороги, окна, здания, звуки, запахи или угрозы;
* не изменил время суток;
* не изменил сезон, погоду или свет;
* не изменил текущую позицию персонажа;
* не дал персонажу знания, которых нет в `character_knowledge_map`;
* не раскрыл hidden state;
* не раскрыл скрытые мотивы NPC;
* не раскрыл закрытые контейнеры;
* не раскрыл будущие события;
* не превратил слухи и неопределённость в факты;
* не использовал action labels, основанные на скрытой правде;
* не вывел raw JSON, schema, audit, repair или debug.

Короткая формула:

```text
narrator_starting_prose
+ visible_context_package
+ visible_context_audit
+ narrator_policy
→ narrator_prose_audit
```

Главный вопрос этапа:

```text
Можно ли показать этот текст игроку без утечки hidden state, без новых фактов и без противоречия утверждённой сцене?
```

## 2. Главное правило этапа

Аудит стартовой прозы не исправляет текст молча.

Если narrator добавил новый факт, раскрыл скрытое или нарушил время/место, аудит возвращает:

```text
pass=false
+ concerns
+ evidence
+ repair_route
```

Запрещено:

* молча удалить ошибочную фразу;
* молча переписать время;
* молча заменить NPC;
* молча удалить предмет;
* молча изменить action options;
* пропустить prose игроку при hard violation.

Исправление выполняется только отдельным repair-этапом.

## 3. Место этапа в pipeline

```text
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит стартового места
11. Генерация персонажа
12. Аудит персонажа
13. Материализация G5-сцены
14. Аудит G5-сцены
15. Размещение стартовых NPC
16. Размещение стартовых предметов
17. Проверка времени и света
18. Формирование карты знаний персонажа
19. Формирование полного hidden state
20. Формирование visible context package
21. Аудит visible context
22. Генерация стартовой прозы narrator
23. Аудит стартовой прозы narrator
24. Вывод игроку
```

Без успешного этапа 23 стартовая проза не выводится игроку.

## 4. Что именно проверяет аудит

Аудит проверяет не “красоту текста”, а его допустимость.

Классы проверки:

```text
1. Формат результата narrator.
2. Соответствие visible_context_package.
3. Отсутствие добавленных фактов.
4. Отсутствие hidden leaks.
5. Соответствие времени, свету, сезону и погоде.
6. Соответствие текущей позиции.
7. Соответствие G5-якорям.
8. Соответствие NPC.
9. Соответствие предметам и контейнерам.
10. Соответствие карте знаний персонажа.
11. Безопасность action options.
12. Отсутствие технического текста.
```

```md
- visible_context_package
- narrator_prose_audit.concerns
- narrator_prose_audit.evidence

# Правила ремонта

Если prose добавила NPC:
- удалить NPC из prose.

Если prose добавила item/container:
- удалить item/container из prose.

Если prose добавила door/exit/route:
- удалить или заменить только на visible exit из visible_context_package.

Если prose добавила threat:
- удалить или заменить только на visible risk hint из visible_context_package.

Если prose изменила time/light/weather:
- вернуть формулировку к frame из visible_context_package.

Если prose раскрыла hidden state:
- удалить раскрытие;
- заменить только на safe hint, если он есть в visible_context_package.

Если rumor стал фактом:
- вернуть слуховую формулировку.

Если uncertainty стала фактом:
- вернуть неопределённую формулировку.

Если action label раскрывает hidden truth:
- заменить на нейтральное действие из available_actions_context.

- добавлять новые детали;

- менять время;
```

## 27. Validation rules

Код обязан проверить `narrator_prose_audit`:

1. `schema === "narrator_prose_audit"`.
2. `version === 1`.
3. `pass` является boolean.
4. `checks` присутствует.
5. `evidence` не пустой.
6. Если `pass=false`, `concerns` не пустой.
7. Если `pass=false`, `repair_route` заполнен.
8. Если `pass=true`, `commit_permission.can_show_to_player=true`.
9. Если `pass=false`, все `commit_permission` false.
10. Все concern codes входят в enum.
11. Все severity входят в enum.
12. Audit не содержит изменённый narrator text.
13. Audit не содержит новую prose.
14. Audit не содержит hidden state beyond evidence.
15. `repair_route.return_to_stage` входит в enum.

Код также валидирует `narrator_starting_prose`:

16. `schema === "narrator_starting_prose"`.
17. `version === 1`.
18. `prose_status === "drafted"`.
19. `prose` не пустая.
20. `prose` не содержит raw JSON.
21. `prose` не содержит audit/repair/debug/system language.
22. `prose` не содержит raw IDs, если UI запрещает.
23. `prose` не содержит private motives.
24. `prose` не содержит closed container contents.
25. `prose` не содержит future timers.
26. `prose` не содержит hidden ownership.
27. `prose` не добавляет NPC.
28. `prose` не добавляет item.
29. `prose` не добавляет container.
30. `prose` не добавляет anchor.
31. `prose` не добавляет route.
32. `prose` не добавляет threat.
33. `prose` не меняет time_of_day.
34. `prose` не меняет light_profile.
35. `prose` не меняет weather.
36. `prose` не меняет season.
37. `prose` не меняет current_position.
38. Все action target refs существуют.
39. Action labels не раскрывают hidden truth.
40. Action labels не обещают outcome.
41. `self_constraints_check.used_only_visible_context=true`.
42. `self_constraints_check.did_not_add_new_world_facts=true`.
43. `self_constraints_check.did_not_reveal_hidden_state=true`.

## 30. Commit gate этапа

Этап считается успешным, если:

```text
narrator_prose_audit.pass=true
и narrator_starting_prose валиден
и prose использует только visible_context_package
и prose не добавляет NPC
и prose не добавляет items/containers
и prose не добавляет doors/exits/routes
и prose не добавляет threats/sounds/weather
и prose не меняет clock/light/weather/season
и prose не меняет current_position
и prose не добавляет знания персонажу
и prose не раскрывает hidden state
и action options безопасны
и evidence не пустой
```

После этого текст можно передать на финальный вывод игроку.

Если gate не пройден, текст не показывается.
