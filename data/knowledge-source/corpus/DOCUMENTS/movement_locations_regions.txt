# Перемещение, локации и регионы

## Статус и граница миграции

Этот документ фиксирует **target materialization v3**. До атомарного activation gate P28 единственным active production path остаётся materialization v2. Документ не разрешает частичную активацию, dual write, v3→v2 fallback или использование target-контрактов production runtime.

Temporal duration и interruption дополнительно регулирует active target-норматив
`temporal_world_and_interruptible_activities.md`. Movement владеет только
sealed segment/method/environment inputs и progress proposal; exact rational
arithmetic, timestamp comparison и boundary ordering принадлежат
`@rus/time-events-history`. Traversal interval не округляет duration и не
использует gameplay `TIMESTAMPTZ`.

После P28 пространственная модель: canonical G0–G5 в `world_base`; party G5 overlay/generated G5, G6 и `scene_position` — в `party_runtime`. G7/G8 не вводятся. Factual topology, знание персонажа и player projection — независимые слои.

## 1. Авторитетное положение и носители

Положение не выводится из UI-координат и не хранится как generic `current_position`. Единственный factual source — versioned `movement_endpoint_ref` и снимок позиции владельца путешествия.

```text
movement_endpoint_ref = scene_position
                      | site_connection_endpoint
                      | world_route_endpoint
                      | transit_anchor
                      | route_anchor_scene
                      | stranded_state
```

`stranded_state` допускается только источником утверждённого rescue/repair/migration plan, никогда обычной целью. У attached субъекта world location производна от carrier attachment; у него не может быть второй root world location. Фактическая топология не заменяется предполагаемым игроком направлением или известным ему названием.

## 2. Топология и сегменты

G4 владеет traversal profile, directional exits и expansion profile. Route topology authored явно: route состоит из одной конечной непрерывной цепочки ordered physical segments с versioned source/target endpoint binding. Site connection не пересекает G4; world traversal проходит ровно один physical segment за один `timed_traversal` step. Несколько допустимых выходов — options, а не ambiguity.

Каждый segment имеет pinned factual context, orientation, environment, approved method/cost и recheck contract. Переход G-ancestor, boundary или смена context не создаёт времени сам по себе. Boundary crossing требует matched exact contract; layout не создаёт topology.

## 3. Path query и готовность

Path query получает journey owner/scope, factual start endpoint, ровно один `target_request` **или** `intended_direction_id`, knowledge scope, capability context и expected state versions. Игровое знание не подменяет factual ID: resolver отдельно pin-ит factual resolution.

```text
mechanical_readiness = ready | requires_frontier_resolution
                     | requires_preparation | temporarily_blocked | data_gap
knowledge_visibility = visible | hidden | misidentified
```

Только `ready` option с непустыми steps executable. `requires_frontier_resolution` возвращает topology proposal; `requires_preparation` — preparation proposal. Их commit не меняет старый option, не перемещает носитель и не продвигает время; затем выполняется новая path query. Empty candidate set, missing route/endpoint/context/cost или неоднозначный mandatory binding — typed hard block, без nearest/first-row/semantic fallback.

## 4. Неизменяемые планы

Ready option становится `party_route_plan` только после resolution endpoint refs, полной dependency pinning, capability checks, completed preparation и canonical digest validation. План хранит owner, scope, source snapshot, original target/direction, factual resolution, ordered steps и static dependency pins. Payload/steps immutable; lifecycle только `ready|superseded|retired`.

```text
world_travel  = root world location или segment progress
carrier_local = действие/сцена внутри attached carrier; без world-route traversal
```

Смена root/attached ownership или scope завершает текущий план на exact handoff endpoint; продолжение начинается отдельным plan/execution. Нельзя незаметно заменить corridor/segment, carrier или method в уже выбранном плане.

## 5. Исполнение движения

`party_route_plan_execution` — единственная mutable journey-state строка; history и events append-only. Статусы: `planned`, `active`, `waiting_at_anchor`, `suspended_at_scene`, `stranded_in_transit`, `completed`, `aborted`, `superseded`.

Step kinds строго разделены:

- `immediate_action`: action cost, без segment progress и game time;
- `timed_activity`: тратит время, но не продвигает physical segment;
- `timed_traversal`: progress ровно одного physical segment.

Traversal start валидирует exact departure endpoint, pinned segment/context, carrier, capability, method и readiness. Block до старта не создаёт travel state. Interval атомарно: snapshot → deterministic checks → один terminal outcome → append-only result/time/progress/consequences. Допустимы только `progressed`, `segment_completed`, `paused_in_transit`, `interrupted_at_anchor`, `stranded`, `blocked_before_progress`.

При завершении segment носитель ставится на exact arrival endpoint; смена route-point context выполняется в pinned phase и имеет нулевую собственную стоимость. Interruption требует approved anchor; иначе результат — `stranded`. В stranded нет teleport, nearest endpoint или обычного движения.

## 6. Разделение ответственности

Resolver/materializer/validator возвращают proposals и reports. Единственный commit component валидирует approved write set и атомарно применяет его; он не выбирает альтернативу. Movement не создаёт semantic data: topology/frontier resolution и target preparation — явные отдельные команды перед plan activation. LLM не создаёт маршрут, endpoint или factual topology.

## 7. Traceability

Target источники: `spatial_architecture_standard_g0_g6.md` §§4, 8–10, 11. До P28 active v2 сохраняется только как migration source; v3 runtime-заявка не читает и не пишет v2 fallback.

# Перемещение по локациям и регионам

## Нормативная актуализация materialization v2

G0–G4 читаются из активной world revision. При первом успешном входе в нематериализованный G4 код детерминированно создаёт party G5, NPC/items/containers по утверждённому profile и фиксирует baseline в той же транзакции, что и перемещение. Ошибка, gap или пустой required candidate set откатывают весь переход. Повторный вход использует сохранённый baseline; LLM не материализует маршрут, место или содержимое.

Перемещение меняет положение персонажа, время, видимую сцену и, если путь значимый, состояние тела, NPC, места и мира.

Главная цепочка:

```text
заявка → определить текущую позицию → выбрать маршрут или курс → можно ли пройти → сколько времени прошло → нужен ли риск → расход состояния → обновление мира → новая сцена
```

Короткая формула:

```text
перемещение = позиция + путь + время + риск + расход + последствия + новая сцена
```

Перемещение не должно создавать мир заново при каждом шаге. Игра хранит уже созданные места, связи между ними, известные персонажу пути, пройденные маршруты, исторические якоря и состояние посещённых мест.

## 1. Положение персонажа

Положение персонажа определяется не координатами, а устойчивой иерархией места.

Формула позиции:

```text
позиция = регион → место → локация → минилокация → точка сцены
```

Пример:

```text
Новгородская земля
→ погост у реки
→ двор постоялого двора
→ навес у конюшни
→ рядом с санями купца
```

Минимально у текущей позиции фиксируются:

```text
current_position:
  region_id
  place_id
  location_id
  minilocation_id
  anchor_id
  last_route_id
```

Где:

1. **region_id** — крупная земля или регион.
2. **place_id** — конкретное место: город, деревня, погост, монастырь, брод, лесной стан, берег, зимовье.
3. **location_id** — часть места: двор, ворота, рынок, изба, берег, пристань, лесная опушка.
4. **minilocation_id** — точная сценическая зона: у печи, за телегой, у двери, под навесом, возле костра.
5. **anchor_id** — ближайшая опорная точка сцены: дверь, колодец, мостки, сундук, костёр, повозка.
6. **last_route_id** — путь, по которому персонаж сюда пришёл.

Игрок не обязан видеть техническую позицию полностью. В прозе показывается то, что персонаж воспринимает:

```text
Ты стоишь во дворе постоялого двора, под навесом у конюшни. За воротами темнеет дорога к реке.
```

## 2. Карта мира как граф

Карта игры — это не точная географическая сетка, а граф сохранённых мест и связей.

```text
узел = регион, место, локация, минилокация или точка сцены
связь = проход, дорога, тропа, река, брод, ворота, дверь, зимник или иной маршрут
```

Каждый созданный узел получает постоянный идентификатор и не пересоздаётся при возвращении.

Короткая формула карты:

```text
карта = сохранённые узлы + связи между ними + известность путей + журнал движения + исторические якоря
```

Для каждого маршрута фиксируются:

```text
route:
  id
  from_id
  to_id
  scale
  type
  base_time
  access
  conditions
  risk
  known_to_character
  known_to_player
  seasonal_rule
  reverse_route_id
  last_used_at
```

Пример:

```text
route_042:
  from: двор постоялого двора
  to: ворота постоялого двора
  scale: между минилокациями
  type: проход
  base_time: 5 минут
  access: открыт, если ворота не заперты
  risk: низкий
  reverse_route_id: route_043
```

Пример дальнего маршрута:

```text
route_117:
  from: погост у реки
  to: соседняя деревня за лесом
  scale: между местами
  type: зимник
  base_time: 5 часов
  access: известен местным
  conditions: работает зимой, опасен в оттепель
  risk: средний
  reverse_route_id: route_118
```

Если персонаж возвращается в уже созданное место, оно не создаётся заново. Система берёт прежнее состояние места и обновляет его по прошедшему времени, погоде, действиям NPC, следам, слухам и последствиям.

Формула возвращения:

```text
возвращение = сохранённое место + известный маршрут + прошедшее время + обновлённое состояние места
```

## 3. Видимая и фактическая карта

Фактическая карта партии и карта знаний персонажа различаются.

```text
фактическая карта = что существует в мире
карта знаний персонажа = что персонаж видел, проходил, слышал, помнит или может предположить
```

Игроку нельзя показывать всё, что хранится в скрытой карте. Он получает только доступные персонажу сведения.

Типы знания пути:

| Тип знания            | Значение                                                         |
| --------------------- | ---------------------------------------------------------------- |
| Известный путь        | Персонаж знает дорогу или уже ходил по ней                       |
| Примерное направление | Персонаж знает, куда примерно идти, но не знает точного маршрута |
| Слух о пути           | Персонаж слышал о дороге, броду, городе или переправе            |
| Неизвестный путь      | Персонаж может искать путь, но рискует ошибиться                 |
| Ложное знание         | Персонаж уверен в неверном направлении или устаревшем слухе      |

Формула доступности маршрута:

```text
доступность маршрута = существует ли путь + знает ли персонаж путь + можно ли пройти сейчас
```

Если путь существует, но персонаж о нём не знает, он не может выбрать его как точный маршрут. Он может искать дорогу, расспрашивать, идти по признакам или двигаться по направлению.

## 4. Масштаб перемещения

Используются четыре масштаба перемещения.

| Масштаб                   | Пример                                  | Базовое время |
| ------------------------- | --------------------------------------- | ------------: |
| Внутри минилокации        | подойти к двери, спрятаться за телегой  |     0–5 минут |
| Между минилокациями       | комната → двор, двор → ворота           |    5–15 минут |
| Внутри места              | пройти по деревне, рынку, монастырю     |   15–60 минут |
| Между местами / регионами | дорога, лес, река, брод, соседняя земля |    часы / дни |

Если перемещение короткое, безопасное и очевидное, оно происходит без броска.

Примеры без броска:

```text
подойти к двери;
перейти через двор;
выйти из избы;
подойти к знакомому человеку;
дойти до видимых ворот при отсутствии препятствий.
```

Если есть риск, препятствие, неизвестный путь, запрет, опасная среда или значимый расход состояния, используется полная обработка пути.

## 5. Можно ли пройти

Перед движением проверяются три вещи:

```text
проход + доступ + условия
```

1. **Проход** — существует ли физический путь.
2. **Доступ** — может ли персонаж пройти по праву, силой, тайно, через договор или обход.
3. **Условия** — не мешают ли погода, темнота, рана, груз, стража, закрытая дверь, вода, лёд, лес, болото, чужой двор или запрет.

Если прохода нет — персонаж не проходит.

Если проход неизвестен — персонаж может искать путь.

Если доступ закрыт — нужно просить, обманывать, вскрывать, лезть, ждать, искать обход, платить, ссылаться на право или идти силой.

Формула:

```text
можно пройти = есть проход + есть способ доступа + условия не делают путь невозможным
```

## 6. Время пути

Базовая формула:

```text
итоговое время = базовое время × множитель условий × множитель нагрузки
```

Множитель условий выбирается один общий. Если условий несколько, берётся худшее. Не нужно перемножать всё подряд.

| Условия                                                      | Множитель |
| ------------------------------------------------------------ | --------: |
| Лёгкий путь                                                  |        ×1 |
| Грязь, снег, темнота, толпа, плохая дорога                   |      ×1.5 |
| Лес, болото, глубокий снег, скрытное движение, поиск пути    |        ×2 |
| Метель, гололёд, опасный брод, тяжёлая ноша, раненый спутник |        ×3 |

Нагрузка учитывается отдельно, если персонаж несёт значимый вес.

| Нагрузка   |                  Множитель |
| ---------- | -------------------------: |
| Лёгкая     |                         ×1 |
| Средняя    |                      ×1.25 |
| Тяжёлая    |                       ×1.5 |
| Предельная | ×2 или движение невозможно |

Пример:

```text
базовое время дороги = 4 часа
условия = снег и плохая дорога → ×1.5
нагрузка = тяжёлая → ×1.5

итоговое время = 4 × 1.5 × 1.5 = 9 часов
```

Если точность не важна, время можно округлять:

```text
несколько минут → полчаса → час → часть суток → день
```

## 7. Когда нужен бросок

Бросок нужен только при риске.

Риск есть, если персонаж:

1. идёт скрытно;
2. спешит;
3. идёт в темноте;
4. идёт по опасной местности;
5. несёт тяжесть;
6. ранен, болен, голоден, замёрз или устал;
7. проходит через охрану или запрет;
8. ищет неизвестный путь;
9. переходит брод, лёд, болото, бурелом;
10. может быть замечен, задержан или сбиться с дороги;
11. идёт без понятных ориентиров;
12. движется по слуху или неверному направлению;
13. пытается вернуться, но условия изменились.

Формула проверки:

```text
d20 + бонус характеристики + бонус навыка + модификатор состояния + модификатор снаряжения + обстоятельства >= сложность
```

Бросок не нужен, если путь известен, безопасен, короток и нет значимого последствия.

## 8. Характеристика для перемещения

Характеристика выбирается по способу действия.

| Действие                                     | Характеристика |
| -------------------------------------------- | -------------- |
| Долго идти, терпеть холод, голод, усталость  | Выносливость   |
| Пролезть, пройти тихо, удержать равновесие   | Ловкость       |
| Тащить, толкать, нести, выбраться силой      | Сила           |
| Найти путь, заметить след, не сбиться        | Внимание       |
| Вспомнить дорогу, понять маршрут             | Разум          |
| Уговорить пустить, расспросить, договориться | Влияние        |

## 9. Навык для перемещения

Навык выбирается по ситуации.

| Ситуация                           | Навык            |
| ---------------------------------- | ---------------- |
| Дорога, лес, вода, погода, следы   | Выживание        |
| Бег, подъём, тяжёлое движение      | Атлетика         |
| Незаметное движение                | Скрытность       |
| Лошадь, сани, повозка              | Верховая езда    |
| Охрана, обычай, запрет, чужой двор | Обычай и закон   |
| Расспросы, просьба, уговор         | Общение          |
| Поиск следов, дороги и опасности   | Наблюдательность |

## 10. Сложность

Сложность определяется не количеством модификаторов, а тем, насколько трудно или опасно действие именно сейчас.

| Сложность | Когда использовать        |
| --------: | ------------------------- |
|         5 | почти нет риска           |
|        10 | обычное препятствие       |
|        15 | заметный риск             |
|        20 | опасная ситуация          |
|        25 | почти предел возможностей |
|        30 | почти невозможно          |

Формула:

```text
сложность = опасность + трудность + неопределённость ситуации
```

Не нужно считать десятки мелких поправок. Достаточно выбрать честную сложность по сцене.

## 11. Итог броска

После броска считается разница:

```text
разница = результат − сложность
```

|    Разница | Итог                            |
| ---------: | ------------------------------- |
| +10 и выше | получилось хорошо, без цены     |
|       0…+9 | получилось                      |
|      −1…−4 | получилось с ценой              |
|      −5…−9 | не получилось, есть последствие |
| −10 и ниже | тяжёлый провал                  |

Цена или последствие выбирается по ситуации:

1. потеря времени;
2. шум;
3. следы;
4. усталость;
5. ухудшение сытости или бодрости, активные состояния жажды/холода/промокания или вред здоровью;
6. повреждение вещи;
7. внимание NPC;
8. подозрение;
9. неверный путь;
10. травма;
11. опасная сцена;
12. потеря ориентира;
13. выход не туда, куда персонаж рассчитывал.

Провал не всегда значит “не дошёл”. Часто это значит:

```text
дошёл позже;
дошёл громче;
дошёл заметнее;
дошёл слабее;
дошёл не туда;
дошёл с новой проблемой.
```

## 12. Обычный маршрут между местами

Для движения между местами достаточно знать:

```text
откуда → куда → тип пути → сезон → погода → известность → риск
```

Тип пути влияет просто.

| Тип пути                      | Особенность                                            |
| ----------------------------- | ------------------------------------------------------ |
| Дорога                        | быстрее, но заметнее                                   |
| Тропа                         | медленнее, меньше людей                                |
| Лес                           | выше риск заблудиться                                  |
| Река                          | нужна лодка, береговой путь или перепр…3287 tokens truncated… реальной истории рядом был город, это не значит, что персонаж знает точную дорогу.

Система разделяет:

```text
знание игрока ≠ знание персонажа
```

Если игрок заявляет, что персонаж знает о месте, система проверяет основание:

1. происхождение персонажа;
2. социальное положение;
3. род занятий;
4. опыт дороги;
5. торговые или служебные связи;
6. слухи;
7. родню;
8. грамотность;
9. местную известность объекта;
10. предыдущие события партии.

Если основание есть, место добавляется в карту знаний персонажа как известный ориентир.

Если основания нет, место остаётся в фактической карте мира, но персонаж знает только смутно или не знает вовсе.

Пример:

```text
Ты слышал, что севернее есть большой торг у реки, но не знаешь, какой дорогой туда идут зимой.
```

Если игрок называет исторически невозможное место, система не должна подстраивать мир под ошибку. Возможные решения:

1. персонаж ошибается;
2. слух неверный;
3. название относится к другому месту;
4. место существует, но не там;
5. в эту эпоху места ещё нет;
6. место уже разрушено или называется иначе.

## 18. Региональный переход

При переходе в другой регион дополнительно проверяется:

1. есть ли связанный путь;
2. знает ли персонаж направление;
3. как относятся к чужим;
4. есть ли власть, стража, пошлина или обычай;
5. меняются ли язык, цены, слухи и опасность;
6. есть ли у персонажа право, проводник, спутники или причина идти;
7. не мешают ли война, запрет, сезон, река, лес, болото или погода;
8. какие исторические события влияют на дороги и власть.

Формула риска:

```text
риск пути = опасность места + плохие условия + чужой статус − защита
```

Где защита — проводник, спутники, знание дороги, право прохода, хорошая одежда, лошадь, оружие, местная поддержка или убедительная причина идти.

Шкала риска:

| Риск        | Значение |
| ----------- | -------: |
| Низкий      |      0–4 |
| Средний     |      5–9 |
| Высокий     |    10–14 |
| Критический |      15+ |

Риск нужен не для обязательной драки, а для выбора осложнений.

При достижении края региона сцена не должна говорить технически: “вы достигли края региона”. Вместо этого появляются признаки переходной зоны:

1. меняется говор;
2. меняется власть или обычай;
3. дороги становятся иными;
4. появляются чужие люди;
5. растёт подозрительность;
6. появляются пошлины или запреты;
7. меняются цены;
8. NPC называют другие земли;
9. меняется ландшафт;
10. появляются слухи соседнего региона.

## 19. Дорожное событие

Если путь долгий или опасный, проверяется дорожное событие.

Формула:

```text
d20 + риск пути >= 20
```

Если проверка прошла, возникает осложнение.

| Результат | Осложнение |
| --------: | ---------- |
|     20–24 | малое      |
|     25–29 | значимое   |
|       30+ | опасное    |

Осложнение должно вытекать из пути.

Возможные осложнения:

1. погода;
2. стража;
3. путники;
4. следы;
5. усталость;
6. потеря дороги;
7. отказ в ночлеге;
8. поломка вещи;
9. слух;
10. болезнь;
11. погоня;
12. конфликт;
13. переправа закрыта;
14. волки, разбойники или военные люди;
15. ложная тропа;
16. социальная претензия;
17. встреча с чужими слугами или сборщиками пошлины.

Дорожное событие не обязано быть боем. Оно должно создавать выбор, цену или новую информацию.

## 20. Следы движения

Если движение может оставить след, система фиксирует его заметность.

Формула:

```text
заметность следа = условия земли + погода + вес + число людей − маскировка − прошедшее время
```

Следы могут быть:

1. следами ног;
2. следами копыт;
3. следами саней или телеги;
4. сломанными ветками;
5. примятой травой;
6. грязью;
7. золой;
8. кровью;
9. потерянной вещью;
10. запахом дыма;
11. слухом от свидетелей.

Следы могут заметить NPC или сам игрок при осмотре. Следы могут привести к погоне, слуху, подозрению, повторной встрече или будущему событию.

## 21. Расход состояния

Состояние меняется только при значимом пути, долгом времени, тяжёлой нагрузке или опасных условиях.

Формула:

```text
новое состояние = старое состояние − расход + восстановление − вред
```

Простой расход:

| Путь                        |                     Расход |
| --------------------------- | -------------------------: |
| Короткий безопасный переход |                          0 |
| Обычный путь                |                        1–3 |
| Долгий путь                 |                        3–6 |
| Тяжёлая дорога              |                       5–10 |
| Опасная среда               | 10+ или активное состояние |

Что тратится:

| Причина                               | Что ухудшается |
| ------------------------------------- | -------------- |
| долгий путь, бег, тяжёлая работа      | Бодрость       |
| долгий путь без еды                   | Сытость        |
| жара, бег, долгий путь без питья      | активная жажда; при продолжении — Здоровье |
| холод, дождь, ветер, снег, вода       | холод/промокание; при продолжении — Здоровье |
| падение, бой, болезнь, переохлаждение | Здоровье       |

Если причина не затрагивает состояние, оно не меняется.

Формула расхода при дороге:

```text
расход состояния = базовый расход + нагрузка + плохие условия − помощь
```

Помощь может быть:

1. лошадь;
2. сани;
3. проводник;
4. хорошая одежда;
5. ночлег;
6. еда и вода;
7. попутчики;
8. знание дороги;
9. хорошая погода;
10. отдых.

## 22. Перемещение и инвентарь

Вес и доступность предметов влияют на перемещение.

Формула общего веса:

```text
общий вес = вес одежды + вес оружия + вес вещей + вес контейнеров + вес содержимого
```

Формула нагрузки:

```text
лёгкая нагрузка = Сила × 2
тяжёлая нагрузка = Сила × 4
предельная нагрузка = Сила × 6
```

Нагрузка влияет только там, где вес реально мешает:

1. бег;
2. скрытность;
3. лазание;
4. долгий путь;
5. переход через брод;
6. движение по болоту;
7. движение по глубокому снегу;
8. бегство;
9. погоня;
10. перенос раненого или тяжёлой вещи.

Чужой, заметный или ценный предмет также может повысить социальный риск дороги.

Формула риска предмета:

```text
риск предмета = чужой статус + заметность + ценность + свидетели − право персонажа
```

## 23. Возвращение в уже посещённое место

Если персонаж возвращается туда, где уже был, система использует сохранённый узел карты.

Возвращение может быть трёх типов:

| Тип                      | Значение                                                 |
| ------------------------ | -------------------------------------------------------- |
| Назад по последнему пути | используется обратный маршрут last_route_id              |
| К известному месту       | система ищет путь через карту знаний персонажа           |
| К месту по памяти        | нужна проверка, если путь сложный или условия изменились |

Формула возврата:

```text
возврат = target_place_id + known_route_chain + elapsed_time + обновление состояния места
```

Если персонаж говорит “вернуться назад”, система берёт последний маршрут и использует обратную связь.

Если персонаж говорит “вернуться к тому постоялому двору”, система ищет сохранённый `place_id`.

Но тот же путь не обязан остаться прежним. Могли измениться:

1. время суток;
2. погода;
3. вода или лёд;
4. стража;
5. ворота;
6. NPC;
7. следы;
8. слухи;
9. опасность;
10. последствия действий игрока.

Формула:

```text
тот же маршрут + другое время + новые условия = новая обработка пути
```

## 24. Обновление места после отсутствия

После возвращения место обновляется, а не пересоздаётся.

Формула:

```text
состояние места = прежнее состояние + прошедшее время + погода + действия NPC + последствия
```

Проверяются:

1. кто ушёл;
2. кто пришёл;
3. что закрыто или открыто;
4. что испортилось;
5. что заметили NPC;
6. какие слухи распространились;
7. изменились ли цены, порядок, страх или доступ;
8. сохранились ли следы;
9. сработали ли отложенные события;
10. изменилась ли историческая или региональная обстановка.

Если персонаж оставил вещь, след, долг, обещание, врага, слух или повреждение, это должно учитываться при возвращении.

## 25. Прибытие

После перемещения фиксируется:

1. новая позиция;
2. прошедшее время;
3. изменённые состояния;
4. текущая погода и свет;
5. кто рядом;
6. что видно;
7. какие выходы доступны;
8. какие последствия пути уже проявились;
9. какие следы остались;
10. что могло измениться в мире за это время;
11. насколько персонаж уверен, где находится;
12. какие маршруты теперь известны.

Формула прибытия:

```text
прибытие = новая позиция + время + состояние + видимая сцена + последствия + доступные выходы
```

В прозе прибытие должно отвечать на вопросы:

1. где персонаж оказался;
2. что он видит;
3. изменилось ли состояние тела;
4. сколько примерно прошло времени;
5. есть ли рядом люди, опасности, следы или ориентиры;
6. какие очевидные выходы или действия доступны.

## 26. Материализация новых мест

Система не создаёт всю карту заранее. Она создаёт только то, что стало нужно партии.

Новое место может быть создано, если:

1. персонаж туда пришёл;
2. персонаж видит его;
3. персонаж услышал о нём;
4. персонаж получил указание;
5. место является историческим якорем направления;
6. место нужно как результат дорожного события;
7. место причинно вытекает из региона, дороги, реки, власти или хозяйства;
8. место является ближайшим логичным узлом пути.

Новое место не должно появляться как ответ на желание игрока без основания.

Формула допустимости места:

```text
допустимость места = регион + эпоха + путь + экономика + власть + ландшафт + причина появления
```

Если место создано, оно получает постоянный `place_id` и дальше существует в памяти партии.

## 27. Ограничения генерации перемещения

При обработке перемещения запрещено:

1. пересоздавать уже посещённое место как новое;
2. менять уже зафиксированный маршрут без причины;
3. автоматически вести персонажа к историческому городу только потому, что он идёт в его сторону;
4. создавать пустоту там, где должны быть дороги, люди, власть, реки, поселения или следы хозяйства;
5. показывать игроку скрытые исторические якоря как точное знание персонажа;
6. считать направление точным маршрутом;
7. считать знание игрока знанием персонажа;
8. игнорировать усталость, груз, погоду и темноту при долгом пути;
9. давать бросок там, где нет риска;
10. требовать бросок для каждого короткого безопасного шага;
11. превращать дорожное событие только в бой;
12. забывать следы, слухи, NPC и последствия после ухода персонажа;
13. считать возвращение автоматическим, если персонаж заблудился или условия сильно изменились;
14. позволять дальнему курсу бесконечно продолжаться без прогресса, ориентира, препятствия, события или переходной зоны.

## 28. Главное правило перемещения

Перемещение должно отвечать на пять основных вопросов:

1. **Где персонаж был и где оказался?**
2. **Можно ли было пройти?**
3. **Сколько времени прошло?**
4. **Что потратилось, изменилось или ухудшилось?**
5. **Что теперь видно, доступно и опасно?**

Для дальнего движения добавляются ещё три вопроса:

1. **Держит ли персонаж направление?**
2. **Что он знает о местности, а что только предполагает?**
3. **Какие исторические, природные и дорожные опоры влияют на пространство вокруг него?**

Короткая формула обычного пути:

```text
путь = доступ + время + риск + расход + новая сцена
```

Короткая формула дальнего курса:

```text
дальний курс = направление + прогресс + отклонение + ориентиры + исторические якоря + последствия
```

Короткая формула карты:

```text
карта = сохранённые места + связи + известность + журнал движения + скрытые якоря
```

Главное правило:

```text
персонаж всегда находится в конкретном сохранённом узле мира,
а любое перемещение переводит его в другой узел, по известному маршруту,
найденному пути или рискованному дальнему курсу.
```

Исторический якорь не ведёт персонажа автоматически. Он только не даёт миру стать неправдоподобным.

```text
город существует, но найти его надо через знание, путь, признаки, проводника или успешную навигацию.
```
