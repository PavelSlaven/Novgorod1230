# price_bands — относительные ценовые полосы (candidate)

Домен группы `economy-trade-measures`, коллектор `collect-economy-trade-measures`. Статус: **candidate**. Приоритет по брифу — `later`, но famine-полосы (голод 1230-1231) собраны сейчас, так как это состояние мира на старте игры.

## Что здесь

- `price_bands.csv` (33 строки, по одной на товар из `novgorod_goods_prices_v1.tsv`) — только **относительные** полосы (`value_band` из закрытого словаря `low | low_to_ordinary | ordinary | ordinary_to_valuable | valuable | high_value`), сезонная/военная/дорожная/голодная поправка как направление, а не число, и непустой `basis`. **Ни одна ячейка не содержит абсолютной цены** — проверено скриптом (см. ниже) и требованием владельца («цены MASTER не использовать»).
- `compensation_reference.csv` (39 строк) — сырые, реально засвидетельствованные абсолютные числа (штрафы/возмещения Правды Русской, летописные голодные и военно-блокадные цены НПЛ) с явным флагом `is_market_price` (true/false) и полем `note`, объясняющим природу числа (штраф ≠ рыночная цена). Эта таблица — ТОЛЬКО основание для `price_bands.csv`, сама по себе она не публикуется как «цена товара» в игре.
- `scripts/derive_price_bands.mjs` — детерминированный генератор `price_bands.csv` из `tools/rus13-novgorod-regional-templates/novgorod_goods_prices_v1.tsv` (draft, project rule) + вычисленного из `compensation_reference.csv` голодного множителя (см. ниже). Скрипт **прерывается с ошибкой**, если случайно попытается записать абсолютную цену в `price_bands.csv`.
- `scripts/validate_price_bands.mjs` — реализует acceptance-критерий брифа буквально: закрытый словарь `value_band`, отсутствие абсолютных цен, непустой `basis`. Текущий результат: **PASS** (33/33 строк).

## Метод

1. Относительная полоса каждого товара (`value_band`) берётся из уже существующего draft-файла `tools/rus13-novgorod-regional-templates/novgorod_goods_prices_v1.tsv` (проектная региональная модель на основе карты G1-G4 и историко-бытовой правдоподобности, confidence medium) — это тот самый файл, который брифом назван кандидатом («65 относительных полос»).
2. Величина голодной поправки (`famine_modifier`) — НЕ придумана. Скрипт вычисляет реальное отношение из независимо проверенных летописных цен: кадь ржи 1228 г. (неурожайный, но не голодный год) → кадь ржи 1230-1231 гг. (пик голода, НПЛ) даёт множитель ×6.7; перекрёстная проверка кадь ржи 1215 г. (голод, блокада Ярославом Торжка) / 1170 г. (военная блокада Андрея Боголюбского) даёт ×2.5 — оба случая кризисные, но разной тяжести, что подтверждает направление роста без навязывания одного числа всем категориям. Множитель применяется только как *порядок величины* и только к категориям продовольствия (`food`, `grain`, `food_preserved`, `food_trade`, `preservation`, `fodder`); для прочих категорий (инструменты, ткань, посуда и т.п.) прямого летописного основания для голодного множителя нет — честно помечено как «направление без числа».
3. Летописные и правдовые числа взяты из book-evidence группы `economy-trade-measures` (домен `price_bands`, 27/244 строк), независимо проверенного на удалённой машине 26.09.2026 — проверяющий явно отметил: «Цены из Русской Правды — штрафные/возмещения, не рыночные» (см. `VERIFICATION.md`), это разграничение сохранено в `compensation_reference.csv#is_market_price`.

## Известные ограничения и gaps

- `item_category_ref` во всех строках — `gap:tsv_category.<category>`: категории самого tsv (food, grain, fur, cloth, tool, utensil...) не привязаны к `category_registry.csv` этого репозитория. Это тот же гап материалов/категорий, что и в `trade_goods_markets`; решение — будущий домен `materials_registry`/`category_parameters` (уже отмечено в сводке критика группы).
- Голодный множитель посчитан ТОЛЬКО для зерновых (рожь); для пшеницы/пшена/овса в летописи даны отдельные абсолютные голодные цены (40/50/13 гривен за кадь) без не-голодного базового года для сравнения — они использованы в `compensation_reference.csv`, но не превращены в собственный множитель (нет базовой точки), чтобы не подставлять чужое отношение под другую культуру.
- `tsv` (novgorod_goods_prices_v1.tsv) сам помечен `status=draft`, `requires_human_historical_audit_for_exact_prices` — это наследуется всеми строками `price_bands.csv` как confidence C для самой полосы.
- Не собраны полосы для услуг (`transport_service`, `service_lodging`, `labor` и т.п. категории того же tsv) — они относятся к домену `services_hire_labor` этой же группы, см. соседнюю папку.
