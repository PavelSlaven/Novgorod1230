# Этап 21. Аудит visible context

## 0. Нормативная редакция 2: изолированный audit block

Этот раздел имеет приоритет над всеми более старыми формулировками ниже, если между ними есть противоречие.

Этап 21 является отдельным изолированным блоком. Он получает только точный `visible_context_audit_input`, не читает global context, stage registry, mutable pipeline state или произвольные outputs других этапов и не изменяет `visible_context_package`.

```text id="stage21-isolated-contract"
exact visible_context_audit_input
→ independent visible_context_audit_code_precheck
→ VisibleContextSemanticAuditor
→ VisibleContextAuditFormatRepairer только при format error
→ SeniorVisibleContextSemanticAuditor при повторной semantic inconsistency
→ VisibleContextAuditRouter при pass=false
→ code validation repair route
→ stage21_visible_context_audit_result
```

Stage 21 не исправляет мир и не переписывает visible context. Локальная ошибка проекции направляется в targeted `VisibleContextSemanticRepairer` Stage 20 вместе с concerns/evidence. Upstream-ошибка направляется только в соответствующий Stage 13–19. После любого ремонта Stage 21 запускается заново.

Подмена готового результата Stage 21 запрещена во всех окружениях. Тесты подменяют только role executors.

`visible_context_package` связывается со Stage 21 и Stage 22 через SHA-256 digest канонического JSON. Narrator может получить только пакет, digest которого совпадает с digest, проверенным Stage 21.

Успешный audit обязан содержать непустой `evidence`. Пустой evidence запрещён и при `pass=true`.

## 0.1. Enum аудита и маршрутизации

Допустимые severity:

```text id="stage21-severity-enum"
warning
repairable
hard_block
upstream_block
```

Допустимые concern codes и их значения фиксируются кодом Stage 21. Произвольный code запрещён. Минимальный нормативный набор включает schema/request/digest conflicts, position/time/weather/light conflicts, invalid refs, unseen NPC/items, hidden leaks, rumor/uncertainty violations, knowledge boundary conflicts, new world facts, narrator prose, source trace и must_not_include failures.

## 1. Назначение этапа

Аудит `visible_context_package` — это gate-этап перед narrator.

Он проверяет, что пакет видимого контекста:

* не содержит утечек hidden state;
* не раскрывает скрытые мотивы NPC;
* не раскрывает закрытые контейнеры;
* не раскрывает будущие события;
* не раскрывает истинных владельцев, если персонаж этого не знает;
* не показывает невидимые предметы;
* не превращает слухи в факты;
* не превращает неопределённость в авторскую истину;
* не противоречит времени, свету и погоде;
* не противоречит текущей позиции персонажа;
* не ссылается на несуществующие G5-якоря;
* не ссылается на несуществующих NPC;
* не ссылается на несуществующие предметы и контейнеры;
* не создаёт новые факты мира;
* безопасен для передачи narrator.

Короткая формула:

```text id="8t3kum"
visible_context_package
+ full_hidden_scene_state
+ character_knowledge_map
+ time_light_consistency_audit
+ g5_scene_graph
+ NPC placement
+ item placement
+ current_position
→ visible_context_audit
```

Главный вопрос этапа:

```text id="7zpm5h"
Может ли narrator получить этот visible_context_package без риска раскрыть скрытую информацию, исказить время/место или добавить несуществующие факты?
```

## 2. Главное правило этапа

Аудит visible context не исправляет пакет молча.

Если пакет неверен, этап возвращает:

```text id="mmxb2t"
pass=false
+ concerns
+ evidence
+ repair_route
```

Запрещено:

* молча удалять скрытую утечку;
* молча менять время;
* молча менять позицию;
* молча менять NPC;
* молча менять предметы;
* молча переписывать visible_scene_dossier;
* пропускать пакет narrator при hard conflict.

Любое исправление должно идти через отдельный repair-этап.

## 4. Что именно проверяется

Этап проверяет три класса ошибок.

Первый класс — структурные ошибки:

```text id="7jxau0"
неверная schema;
нет version;
нет frame;
нет position;
битые ссылки на G5;
битые ссылки на NPC;
битые ссылки на item/container;
отсутствует evidence;
неверные enum;
пустой must_not_include при наличии hidden state.
```

Второй класс — смысловые ошибки:

```text id="lzxslq"
пакет показывает то, что персонаж не может видеть;
пакет показывает то, что персонаж не знает;
пакет раскрывает скрытую причину видимого намёка;
пакет превращает подозрение в факт;
пакет даёт точный маршрут, которого персонаж не знает;
пакет даёт точное имя NPC, если персонаж его не знает;
пакет раскрывает владельца предмета, если это не известно.
```

Третий класс — temporal/spatial mismatch:

```text id="zg0g87"
clock говорит ночь, visible context говорит день;
position указывает один anchor, visible context описывает другой;
G5 visibility запрещает объект, но пакет показывает его;
weather/light снижает видимость, но пакет показывает всё ясно;
visible exits указывают несуществующие anchors;
NPC находится в закрытой зоне, но описан как видимый.
```

```json id="9qcbyk"
  "pass": true,
```

```json id="stage21-result-bundle"
  "input_snapshot_digest": "sha256:<technical-input-digest>",

    "version": 1,
    "schema": "visible_context_audit_code_precheck",
    "pass": true
  },
  "visible_context_audit": {
    "version": 1,

  },
  "repair_route": null,
  "audit_history": [],
  "diagnostics": {
    "auditor_attempts": 1,
    "format_repair_attempts": 0,
    "senior_auditor_attempts": 0,
```

## 9. Проверка position consistency

Позиция в visible context должна совпадать с `current_position`.

Проверяются:

```text id="1932o9"
position.region_id
position.place_id
position.location_id
position.minilocation_id
position.anchor_id
```

Hard conflict:

```text id="03l2h2"
current_position.anchor_id = g5_anchor_001
visible_context.position.anchor_id = g5_anchor_009
```

Ошибка:

```text id="ldn0iu"
VISIBLE_CONTEXT_POSITION_MISMATCH
```

Также проверяется, что `visible_scene_dossier.summary` не описывает другую минилокацию или другой anchor.

Ошибка:

```text id="9xlg5o"
VISIBLE_CONTEXT_PROSE_DOSSIER_POSITION_CONFLICT
```

## 11. Проверка G5 anchor consistency

Каждый anchor в visible context должен существовать в `g5_scene_graph`.

Проверяются:

```text id="5y9qh9"
visible_anchors[*].anchor_id
visible_exits[*].anchor_id
visible_scene_facts[*].source_refs
available_actions_context[*].target_ref.anchor_id
audible_context[*].source_ref.anchor_id
```

Также проверяется, что anchor:

```text id="ukoxc8"
принадлежит выбранному G4;
не hidden_from_player;
допущен time/light constraints;
видим, слышим или известен персонажу;
не требует inspection, если подан как fully visible.
```

Ошибки:

```text id="0plrti"
VISIBLE_CONTEXT_ANCHOR_REF_NOT_FOUND
VISIBLE_CONTEXT_ANCHOR_OUTSIDE_CURRENT_G4

```

## 12. Проверка visible exits

Visible exit может быть показан только если он видим, слышим, известен персонажу или непосредственно доступен из текущего G5.

Проверяются:

```text id="ueg7a9"
anchor_id
exit_label
```



## 29. Validation rules

Код обязан проверить `visible_context_audit`:

1. `schema === "visible_context_audit"`.
2. `version === 1`.
3. `pass` является boolean.
4. `checks` присутствует.
5. `evidence` не пустой.
6. Если `pass=false`, `concerns` не пустой.
7. Если `pass=false`, `repair_route` заполнен.
8. Если `pass=true`, `commit_permission.can_send_to_narrator=true`.
9. Если `pass=false`, все `commit_permission` false.
10. Все concern codes входят в enum.
11. Все severity входят в enum.
12. Audit не содержит изменённый visible_context_package.
13. Audit не содержит narrator prose.
14. Audit не содержит hidden state details сверх evidence.
15. `repair_route.return_to_stage` входит в допустимый enum.

Код также валидирует сам `visible_context_package`:

16. `schema === "visible_context_package"`.

### Источник карты знаний до и после initial commit

На старте до общей транзакции этот этап получает утверждённый `character_knowledge_map` Stage 18 и его независимый audit через собственный input.

После initial commit и во время базового хода прямое использование стартового snapshot запрещено как источника текущего состояния. Оркестратор обязан передать read model, собранный из текущего `party_character_knowledge_layer`:

```text
party_character_knowledge_maps where is_current=true
+ active party_character_known_*
→ buildCurrentCharacterKnowledgeView()
→ строго определённый input этапа
```

Код при сборке read model только читает и преобразует утверждённые записи. Он не создаёт знания, не повышает confidence, не превращает слух в факт и не раскрывает forbidden knowledge.

`party_character_knowledge_snapshots` используется только для аудита, восстановления и сравнения версий, но не как mutable runtime-state.

## 32. Commit gate этапа

Этап считается успешным, если:

```text id="t25qd4"
visible_context_audit.pass=true
и visible_context_package валиден
и position совпадает с current_position
и clock/season/weather/light совпадают с authoritative frame
и все G5/NPC/item/container refs существуют
и hidden state не раскрыт
и private motives не раскрыты
и closed container contents не раскрыты
и future timers не раскрыты
и слухи не стали фактами
и uncertainty не стала фактом
и available actions не раскрывают hidden truth
и narrator_scope достаточно строгий
и visible_scene_dossier безопасен
и source_trace/evidence не пустые
```

После этого можно передать пакет narrator.

Если gate не пройден, narrator не запускается.
