# Sealed T06–T12: план, не разрешение на запуск

Этот документ фиксирует проверяемую матрицу и бюджет; он не является разрешением на sealed-run, результатом или приёмкой. Запуск T06–T12 остановлен до отдельного решения распорядителя. Текущий P3 case pack принимает только T06–T10; T11/T12 являются отдельными P4 save/reload и crash/retry checks. Не добавлять их в P3 pack.

Каждый вариант требует замороженных intent, fixture/build identity, revision входа/schema и ожидаемого физического predicate. Независимый reviewer предоставляет held-out тексты после фиксации адаптеров. Каждый reset получает отдельные world/userdir и operation ID; сохраняются все ошибки. Runner не вычисляет acceptance автоматически — PASS проверяется по полной модели, native readback и критериям ниже.

| Тест | Матрица | PASS predicate и недостающая подготовка |
|---|---|---|
| T06 — эквивалентные свободные intents | 4 варианта × 3 reset = 12 | Два author-authored и один независимый held-out equivalent intent дают один и тот же native west-passage эффект без exact-text веток; contrast «открыть дверь, оставаясь на месте» даёт другой эффект. Заморозить held-out, fixture и сравнение before/after. |
| T07 — обычное действие с предметом | 2 × 3 = 6 | Оба варианта проходят через общий native primitive, применяют доступный точный UID и подтверждают эффект readback. До запуска зафиксировать предмет, действие, target и наличие primitive; отсутствие seam — блокировка. |
| T08 — отказ/частичный эффект | 1 × 3 = 3 | Попытка у стены даёт native отказ либо частичный результат; позиция и эффект подтверждены readback, нет выдуманной сущности, лишнего RNG или narration об успехе. Зафиксировать fixture и ожидаемые поля. |
| T09 — NPC duty boundary | 1 × 3 = 3 | Реальный assigned NPC выбирает и выполняет действие; неизменный replay не создаёт вторую селекцию/операцию. Нужны native safety interrupt, сохранённые причина/status, reload/current observation и продолжение того же NPC на следующей semantic boundary без LLM между ticks и второго arbiter. Текущий runner этого interrupt/follow-up не проверяет. |
| T10 — речь и аудитория | 1 × 3 = 3 | Проверить точную фразу, фактическую слышимость ближайшим слушателем, исключение deaf listener, ровно 3 секунды native time и единственное последствие social owner только после доставки. Заморозить IDs и readback. Нынешнее `available/not_evaluated` не является PASS oracle; reviewer должен оценить owner outcome. |
| T11 — физическое и семантическое save/reload (P4) | отдельный follow-up, не P3 pack | Одно и то же поколение после reload сохраняет position, time, NPC, items, utterance и executed IDs. Зафиксировать до/после состояние и сверить весь набор полей. |
| T12 — crash/retry до и после commit (P4) | отдельный follow-up, не P3 pack | Состояние после восстановления — целиком старое либо целиком новое; отсутствуют повторные expense, movement и speech. Проверить crash/retry до и после commit с полным readback. Не объединять с T11 или P3 pack; зафиксировать отдельные failure points. |

P3 proposed pack: T06 4, T07 2, T08 1, T09 1, T10 1 — всего 9 entries × 3 resets = **27 базовых attempts**. Простое правило один repeat на каждый decision даёт **54**. По текущему NPC source path два разных repair-флага могут дать NPC structural repair, затем fresh semantic repair: при single-step intents получается условный расчёт **24 player resets × 2 + 3 NPC resets × 3 = 57**. Это расходится с протоколом one-repeat; до запуска нужно решение владельца (см. issue #773). Player boundary может обработать до 8 шагов, поэтому 57 — оценка только для зафиксированных single-step intents. Package hard cap — **72 attempts**, abort до 73-й.

Настройки роли по текущему профилю: `temperature=0`, `top_p=1`, timeout `120000 ms`; `max_tokens=20000` для planner/NPC и repair, `1000` для conversation responder и repair. Объявленное окно — 65,536; input ceiling — 45,536 при output 20,000 и 64,536 при output 1,000. Metadata подтверждает только trained context 65,536; runtime window неизвестно. Локальный provider должен использовать явно заданные settings, точный model/provider/mode, не логировать ключ и завершаться ошибкой при невалидной конфигурации.
