# Ономастический каталог Новгородской земли, 1230–1250

**Проект:** `PavelSlaven/Novgorod1230` / «Русь XIII век»  
**Назначение:** рабочий authoring-каталог личных имён и исторических форм именования для процедурной генерации NPC.  
**Период:** основной — 1230–1250; для расширения выборки используются новгородские материалы примерно 1160–1260 и, в специально помеченных случаях, более широкий корпус XI–XIV вв.  
**Репозиторная таксономия:** сверена с PR #98; HEAD на завершение исследования — `e8b1a1d27e53ad790121206dca3785a43337cc41`.  
**Статус:** исследовательский authoring input; сам документ не активирует runtime.

---

## 1. Что означает «полный перечень»

Ни один сохранившийся источник не позволяет восстановить математически полный именник всех жителей Новгородской земли 1230–1250 гг. Ниже дан **полный рабочий перечень по исследованному источниковому корпусу**, пригодный для игры:

1. непосредственно засвидетельствованные новгородские имена и формы;
2. имена ближайшего к игровому времени периода;
3. женский именник по специальному исследованию берестяных грамот;
4. княжеский и церковный именник по Новгородской первой летописи;
5. отдельные этнокультурные имена, зафиксированные в Новгороде;
6. имена западных купцов из современного игре балтийского торгового круга;
7. привязка ко всем `social_position_archetype_id` проекта.

**Главное правило:** обычное личное имя не является сословным классом. Один и тот же Иван, Фёдор, Борис, Мария или Анастасия мог принадлежать к разным слоям. Социальное положение влияет прежде всего на специальный пул (если он действительно существует), форму имени, прозвище, отчество, титул, указание на хозяина/двор/происхождение и на то, какую часть identity знает игрок.

Создавать искусственные таблицы «имена холопов», «имена рыбаков», «имена бояр» без источникового основания нельзя.

## 2. Уровни доказательности

| Код | Значение | Использование |
|---|---|---|
| **A1** | прямо засвидетельствовано в Новгороде/Новгородской летописи близко к 1180–1260 гг. или точно в игровом интервале | normal approved candidate |
| **A2** | засвидетельствовано в новгородском корпусе XI–XIV вв.; совместимо с регионом и периодом | approved с обычным/пониженным весом |
| **B1** | засвидетельствовано в Новгородской земле/Старой Руссе либо в непосредственно связанном балтийском мире того же времени | contextual |
| **B2** | исторически совместимо с Русью периода, но локальная опора слабее | rare / нужен дополнительный basis |
| **X** | недостаточно доказано для default 1230–1250 или форма заметно поздняя | не включать в default |

# 6. Историческая модель женского именования

Женщина могла именоваться:

1. личным именем;
2. именованием по мужу;
3. реже аналитически: `Фомина жена`, `Семёнова жена`.

Источниковые типы:

- `Давыжая` ← Давыд;
- `Павловая` ← Павел;
- `Васильевая` ← Василий;
- `Гюргиевая` ← Гюргий;
- `Иваняя / Ивановая` ← Иван;
- `Яршковая` ← Ярошко/Ярослав;
- `Путкова / Путьшина` ← Путко/Путьша;
- `Радоковая` ← Радко;
- `Нежаткиная` ← Нежата.

Это `display/name-reference strategy`, а не современная фамилия.

Особенно сильны для 1230-х:

- **Михаил** — князь Черниговский и новгородский;
- **Ростислав** — сын Михаила, посаженный в Новгороде в 1230;
- **Ярослав** — Ярослав Всеволодович;
- **Фёдор** и **Александр** — сыновья Ярослава, оставленные им в Новгороде;
- **Александр** — князь Новгородский;
- **Андрей, Василий, Константин** и др. — устойчивый династический именник ближайших поколений.

## 7.1. Двойные княжеские имена

Для княжеской среды возможна пара:

`родовое/династическое имя + крестильное имя`

Например:

- `Ростислав (Михаил)`;
- `Мстислав (Георгий)`.

**Не давать каждому князю случайную пару.** Она должна быть authored либо взята из отдельного approved dynastic pairing profile.

## 7.2. Княжеские женщины

Для процедурно созданной **неисторической** княгини безопаснее использовать доказанный женский календарный именник с:

- полными формами;
- отдельной dynastic/kinship identity;
- без грубых бытовых прозвищ без причины.

В русской княжеской среде близкого периода засвидетельствованы, в частности, **Мария, Елена, Евдокия, Александра**, но их локальную новгородскую частотность нельзя выводить из единичных династических примеров.

Реальные исторические княгини должны быть authored, а не процедурно переименованы.

# 9. Иноземные и этнокультурные пулы

Статус `foreign_privileged_merchant_outsider`, `captive_unfree_person`, `traveler_guide_itinerant` или `displaced_status_lost_outsider` **не определяет происхождение**.

Сначала нужен `origin/cultural-linguistic basis`, затем выбирается имя.

## 9.1. Готландский/скандинавский Новгород

Непосредственно на Немецком дворе в слое 1160–1170-х обнаружена руническая товарная бирка с именем:

- **Hæil(h)vatr / Хейльватр** — **A1**, специфически готландское имя.

Это сильный локальный кандидат для готландского купца/гостя. Русскому NPC его не выдавать.

## 9.2. Германо-готландский торговый круг около 1229 г.

Смоленский договор 1229 г. с Ригой и Готландом фиксирует современный Новгороду круг западных торговых людей. Это не список жителей Новгорода, поэтому уровень **B1**.

При подтверждённом происхождении допустимы:

**Regenbode (Регеньбоде), Dethard (Детхард/Детярт), Adam (Адам), Meinbern/Membern (Майнберн/Мемберн), Friedrich (Фридрих), Heinrich (Генрих/Хайнрих), Hildeger (Хильдегер), Konrad (Конрад), Johann (Иоганн), Bernhard (Бернхард), Volker (Фолькер), Ermbrecht (Эрмбрехт), Albrecht (Альбрехт), Walter (Вальтер), Rolf (Рольф).**

Не русифицировать их автоматически до православного имени.

## 9.3. Прибалтийско-финский слой

Прямо засвидетельствовано прибалтийско-финское по происхождению имя:

- **Иголанд** — A2/B1.

Одного имени недостаточно для полноценного карельского/ижорского/водского пула. Такой пул нужно исследовать отдельно, а не дополнять по звучанию.

## 9.4. Тюркский слой в новгородском мире

Исследования грамот и граффити связывают с тюркской антропонимией:

- **Кыяс**;
- **Гюлопа**;
- **Ильдята**;
- **Сандус**.

Гюлопа и его сын засвидетельствованы в новгородских грамотах; Ильдята связан с новгородским землевладением. Исследователи отмечают возможность включения таких людей в княжеское окружение и новгородскую элиту.

Это важный контрпример против правила `foreign name = low status`.

## 10.3. Ремесло

Источники не показывают отдельного ремесленного first-name pool.

# 13. Прозвища и вторые компоненты имени

## 13.1. По занятию

Допустимы при реальном causal basis:

`Кузнец, Рыбак, Лодочник, Плотник, Бортник` и иные существующие occupation labels.

Это может быть:

- описание неизвестного NPC;
- устойчивое прозвище;
- role label.

Не всякий кузнец автоматически становится `Иван Кузнец`.

## 13.2. По внешнему признаку

Исторически допустимый класс:

`Рыжий, Хромой, Кривой, Малой, Старый`.

Нужен observable/persisted basis. Нельзя выводить прозвище из hidden body state.

## 13.3. По происхождению

`Псковитин, Ладожанин, Заволочанин, Торжокский` и аналогичные формы допустимы только при установленном происхождении.

## 13.4. По хозяину/двору

`боярский человек`, `владычный человек`, `монастырский человек`, `человек такого-то двора`.

Это social identifier, не фамилия.

# 14. Отчества и родовые связи

Новгородская летопись около 1230 г. показывает развитые патронимические формы у политически заметных мужчин:

- `Семён Борисович`;
- `Степан Твердиславич`;
- `Иванко Тимощинич`;
- `Яким Влункович`.

Для генератора:

1. patronymic создаётся только при существующем/сгенерированном и сохранённом father relation;
2. нельзя случайно создать отчество без соответствующего родства;
3. player-facing отчество показывается только если оно известно герою;
4. современная обязательная трёхчастная ФИО-модель анахронична.

# 15. Что делать с поздними известными именами

**Онцифор** очень хорошо известен в Новгороде XIV века, но это не делает его хорошим default для 1230–1250.

Правило:

- не включать в основной target pool;
- разрешать как `B2/rare` только при дополнительном evidence;
- при расширении игры в XIV век пересмотреть applicability.

То же правило действует для любого позднего имени: древность имени сама по себе не доказывает нужную региональную частотность в 1230 г.

# 16. Рекомендуемая структура authoring data

Это пример организации данных, не новый runtime contract.

```yaml
name_entry:
  name_id: nov_name_male_tverdyata_v1
  canonical_display: Твердята
  sex_category: male
  cultural_pool: novgorod_rus
  name_class: noncalendar
  evidence_grade: A1
  valid_from: 1160
  valid_to: 1260
  social_applicability:
    mode: broad
    exclusions: []
  ecclesiastical_use: false
  dynastic_use: false
  source_refs:
    - gramoty:...
  variants: []
```

Selection context:

```yaml
name_selection_context:
  region
  year
  sex_category
  cultural_origin
  religion
  monastic_state
  dynastic_state
  social_position_archetype_id
```

Порядок:

```text
origin/region
→ sex
→ dynastic / monastic special case
→ applicable name pool
→ evidence/applicability
→ code-owned weighted selection
→ persisted identity
→ social reference form
```

Неправильно:

```text
occupation = fisher
→ выбрать имя из списка "рыбаков"
```

# 18. Имена старого draft, которые нельзя автоматически активировать

До нового evidence не делать обычными default:

`Василиса, Дарья, Матрёна, Прасковья, Онцифор`.

# 19. Критерий готовности имени для code-first generator

Имя готово для default materialization, если:

1. есть stable `name_id`;
2. есть нормализованная player-facing форма;
3. указан `sex_category`;
4. указан cultural/origin pool;
5. есть период применимости;
6. есть evidence grade A1/A2 либо explicit approved contextual B;
7. есть `source_ref`;
8. special-use (`dynastic`, `monastic`, `foreign`) не выводится из звучания;
9. имя само по себе не создаёт hidden biography;
10. выбранная identity сохраняется и не reroll-ится при reload/rephrase.
