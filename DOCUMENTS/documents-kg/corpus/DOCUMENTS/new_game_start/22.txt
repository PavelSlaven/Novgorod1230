# Этап 22. Генерация стартовой прозы narrator

## 0. Нормативная редакция 2: изолированный narrator block

Этот раздел имеет приоритет над всеми более старыми формулировками ниже, если между ними есть противоречие.

Stage 22 является отдельным изолированным блоком. Он получает только точный `narrator_start_input`, не читает global context, stage registry, mutable pipeline state, outputs других этапов, hidden state, raw character knowledge, repair logs или полный Stage 21 audit.

```text id="stage22-isolated-contract"
exact narrator_start_input
→ narrator_start_code_precheck
→ NarratorStartingProseWriter
→ strict structural/reference validation
→ NarratorProseFormatRepairer только при format error
→ SeniorNarratorStartingProseWriter при повторной structural failure
→ stage22_narrator_prose_result
→ Stage 23 semantic audit
```

Stage 22 не создаёт мир и не проводит окончательный semantic audit. Код проверяет структуру, digest, permissions, reference integrity, action targets и output contract. Добавленные факты, hidden leaks, слухи и смысловые противоречия проверяет Stage 23.

Подмена готового Stage 22 output запрещена во всех окружениях. Тесты подменяют только role executors. Произвольный `options.input` также запрещён.

## 0.3. Writer role boundary

`NarratorStartingProseWriter` получает только:

```text id="stage22-writer-boundary-v2"
visible_context_package
visible_context_package_digest
narrator_policy
output_contract
```

Writer не получает `visible_context_approval`, полный audit, precheck, hidden state, raw knowledge, world_base или pipeline context.

Role config:

```text id="stage22-role-config-v2"
NarratorStartingProseWriter: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode, max_tokens 5000
NarratorProseFormatRepairer: deepseek-v4-flash, thinking disabled, reasoning low, JSON mode
SeniorNarratorStartingProseWriter: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
NarratorProseSemanticRepairer: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
SeniorNarratorProseSemanticRepairer: deepseek-v4-pro, thinking enabled, reasoning high, JSON mode
```

## 0.4. Result bundle

Под ключом Stage 22 хранится не голая prose, а bundle:

```json id="stage22-result-v2"
{
  "version": 1,
  "schema": "stage22_narrator_prose_result",
  "request_id": "string",
  "pass": true,
  "visible_context_package_digest": "sha256:<canonical-json-digest>",
  "narrator_start_code_precheck": { "schema": "narrator_start_code_precheck", "pass": true },
  "narrator_starting_prose": { "schema": "narrator_starting_prose", "prose_status": "drafted" },
  "generation_history": [],
  "diagnostics": {
    "writer_attempts": 1,
    "format_repair_attempts": 0,
    "senior_writer_attempts": 0,
    "semantic_repair_attempts": 0,
    "last_error_codes": []
  },
  "handoff_permission": { "can_send_to_prose_audit": true }
}
```

Stage 23 получает только `narrator_starting_prose` из bundle, утверждённый visible package, тот же digest, safe approval и audit policy. Generation history и diagnostics Stage 23 не передаются.

## 0.5. Structural validator

Код обязан проверять version/schema/request_id, prose_status, drafted/blocked rules, action option enums, option_id uniqueness, limits, target refs, grounding в `available_actions_context`, used visible refs, self-check booleans, paragraph limit и отсутствие технических полей. Код не использует словарь смысловых слов для угадывания hidden leaks.

## 0.6. Format и semantic repair

Format repair исправляет только JSON-обёртку и не меняет prose по смыслу.

После failed Stage 23 audit:

```text id="stage22-repair-loop-v2"
Stage 23 concerns + evidence
→ NarratorProseSemanticRepairer
→ новый stage22_narrator_prose_result
→ повтор Stage 23
```

Semantic repair может менять только `prose`, `action_options`, `used_visible_context_refs`, `self_constraints_check`, `prose_status` и `block_reason`. Visible package, digest, approval и narrator policy неизменяемы.

Если Stage 23 указывает, что ошибка находится upstream, pipeline возвращается к Stage 20, 19, 18 или 17, затем повторяет Stage 21, Stage 22 и Stage 23.

## 1. Назначение этапа

Генерация стартовой прозы narrator — это этап, на котором LLM пишет первый player-facing текст партии.

Narrator получает только утверждённый `visible_context_package` и `visible_context_audit`.

Narrator не получает:

```text id="gy4vv2"
full_hidden_scene_state;
raw character_knowledge_map;
world_base целиком;
repair logs;
audit internals;
debug notes;
raw prompts;
source-only notes;
закрытые контейнеры;
скрытые мотивы NPC;
будущие события;
истинные владельцы, если персонаж их не знает;
скрытые маршруты;
точные причины событий, если они не видимы персонажу.
```

Короткая формула:

```text id="skh4k6"
visible_context_package
+ visible_context_audit.pass=true
+ narrator_constraints
→ narrator_starting_prose
```

Главный вопрос этапа:

```text id="7evkk7"
Как написать вводную сцену живым языком, не добавив ни одного нового факта и не раскрыв ничего за пределами visible_context_package?
```

## 2. Главное правило этапа

Narrator не создаёт мир.

Narrator только формулирует player-facing prose из `visible_context_package`.

Запрещено:

* добавлять новые NPC;
* добавлять новые предметы;
* добавлять новые пути;
* добавлять новые здания;
* добавлять новые события;
* объяснять скрытые причины;
* раскрывать мотивы NPC;
* раскрывать содержимое закрытых контейнеров;
* раскрывать будущие timers;
* менять время, свет, погоду, сезон;
* менять текущую позицию;
* улучшать сцену “для красоты” новыми деталями;
* превращать слух в факт;
* превращать неопределённость в истину;
* давать игроку выборы, основанные на hidden state.

Разрешено:

* художественно сформулировать уже видимые факты;
* сгруппировать видимое в читаемый вводный текст;
* передать телесное ощущение, если оно есть в visible context;
* передать видимые риски как намёки;
* передать неопределённость как неопределённость;
* завершить текст открытым вопросом или нейтральным приглашением к действию;
* дать 3–6 доступных вариантов действий, если они есть в `available_actions_context`.

## 3. Место этапа в pipeline

```text id="jywq3w"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит стартового места
11. Генерация персонажа
12. Аудит персонажа
13. Материализация G5-сцены
14. Аудит G5-сцены
15. Размещение стартовых NPC
16. Размещение стартовых предметов
17. Проверка времени и света
18. Формирование карты знаний персонажа
19. Формирование полного hidden state
20. Формирование visible context package
21. Аудит visible context
22. Генерация стартовой прозы narrator
23. Аудит narrator prose
24. Вывод игроку
```

Этап 22 не является последним gate. После него нужен отдельный аудит narrator prose, потому что даже narrator может случайно добавить факт, раскрыть hidden state или нарушить время/свет.

## 6. Что narrator обязан включить

Narrator должен включить только то, что есть в `visible_scene_dossier.must_include`.

Типовые обязательные блоки:

```text id="8b6b08"
1. текущая позиция персонажа;
2. время суток и свет;
3. погода или телесное давление, если оно есть;
4. ближайшие видимые G5-якоря;
5. видимые NPC как player-safe labels;
6. видимые предметы/контейнеры без скрытого содержимого;
7. видимые выходы или неопределённость выхода;
8. известные персонажу риски или социальные правила;
9. ближайшее давление/потребность, если оно есть в visible context.
```

Narrator не обязан включать всё из `may_include`.
Narrator не имеет права включать ничего из `must_not_include`.

## 7. Что narrator не имеет права включать

Narrator не должен включать:

```text id="giybfl"
закрытое содержимое контейнера;
истинного владельца, если персонаж его не знает;
скрытый мотив NPC;
скрытую эмоцию NPC, если она не видна;
скрытое знание NPC;
будущий таймер;
скрытую опасность без признака;
точное направление скрытого маршрута;
точное имя NPC, если identity_known_to_player=false;
точную функцию предмета, если exact_identity_known=false;
истинность слуха;
ошибочное знание как авторскую истину;
системную причину риска;
упоминание JSON, схем, аудитов, repair, pipeline.
```

## 8. Стиль стартовой прозы

Стартовая проза должна быть:

```text id="6gvjp9"
ясной;
короткой;
игровой;
второго лица или ограниченного третьего лица;
без энциклопедического описания;
без объяснения скрытых причин;
без перегруза деталями;
без длинной экспозиции;
с видимыми точками действия.
```

Рекомендуемый объём:

```text id="klpn89"
2–4 абзаца;
500–1200 знаков для первого вывода;
до 1800 знаков, если сцена сложная;
3–6 вариантов действий, если UI требует варианты.
```

## 9. Разрешённые формы фраз

### 9.1. Видимый факт

Можно:

```text id="kc4h4p"
Перед тобой закрытая дверь.
У стены стоит закрытый ларь.
У ворот виден человек.
В темноте различим только ближайший проход.
```

Нельзя:

```text id="01dehg"
За дверью прячется человек.
В ларе лежит серебро.
Человек у ворот скрывает, что следит за тобой.
Проход ведёт к тайному амбару.
```

### 9.2. Риск как видимый намёк

Можно:

```text id="17wfx8"
Брать чужое здесь может быть заметно.
Человек у ворот стоит достаточно близко, чтобы заметить резкое движение.
Сундук закрыт, и возиться с ним на виду рискованно.
```

Нельзя:

```text id="klxet0"
Если ты возьмёшь нож, хозяин позовёт стражу.
Этот человек обязательно тебя остановит.
Через пять минут придёт сторож.
```

### 9.3. Неопределённость

Можно:

```text id="o0nfjt"
Проход уходит в темноту; куда он ведёт, отсюда не понять.
Слышен глухой звук, но источник не различить.
Ларь выглядит закрытым; что внутри, не видно.
```

Нельзя:

```text id="278ma6"
Проход ведёт в сени.
За дверью стоит хозяин.
Внутри ларя лежит оружие.
```

### 9.4. Слух

Можно:

```text id="4xlupx"
Ты слышал, что эту дорогу считают опасной.
Говорят, здесь лучше не спорить с хозяевами.
```

Нельзя:

```text id="e2i4bd"
Эта дорога опасна.
Хозяева точно нападут, если спорить.
```

## 10. Структура стартового текста

Рекомендуемый порядок:

```text id="01lrvy"
1. Время, свет, тело.
2. Текущая точка сцены.
3. Ближайшие видимые объекты и NPC.
4. Видимые выходы/варианты.
5. Давление ситуации.
6. Вопрос или переход к действию.
```

Пример структуры без конкретного сеттинга:

```text id="rdpt69"
[Время и свет.] [Где ты стоишь.] [Что видно рядом.] [Кто рядом заметен.] [Что можно сделать.] [Что нельзя понять без действия.] [Что требует решения.]
```

## 11. Action options

Если `available_actions_context` передан, narrator может вернуть action options.

Правила:

```text id="b7tszi"
option label должен быть player-facing;
option label не должен раскрывать hidden truth;
option target_ref должен существовать;
option basis должен быть visible/audible/known/inferred;
risk_hint может быть только общим;
нельзя обещать результат действия;
нельзя писать outcome вместо action.
```

Допустимо:

```text id="1bmu88"
Осмотреть закрытый ларь.
Заговорить с человеком у двери.
Прислушаться к звуку за проходом.
Проверить тёмный выход.
Подождать и посмотреть, что изменится.
```

Недопустимо:

```text id="49171u"
Открыть ларь с серебром.
Убедить должника выдать тайну.
Пойти тайным проходом в амбар.
Подождать, пока войдёт сторож.
```

## 12. Работа LLM на этапе

LLM на этом этапе обязательна, потому что это собственно prose generation.

Но роль LLM здесь узкая:

```text id="rbwid2"
не world builder;
не simulator;
не hidden-state interpreter;
не author of new facts;
только verbalizer of visible context.
```

LLM делает:

```text id="devbng"
преобразует structured visible context в читаемую prose;
сохраняет ограничения must_include/must_not_include;
передаёт неопределённость;
передаёт видимый риск без hidden truth;
формирует action options из available_actions_context;
не добавляет новых сущностей.
```

LLM не делает:

```text id="8jx6hu"
не выбирает новый результат;
не двигает время;
не двигает персонажа;
не меняет сцену;
не меняет NPC;
не меняет предметы;
не раскрывает скрытую правду;
не создаёт последствия.
```

## 13. LLM-параметры

### 13.1. `NarratorStartingProseWriter`

Назначение: написать стартовую player-facing prose из `visible_context_package`.

```json id="5stttm"
{
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "thinking": {
    "type": "enabled"
  },
  "reasoning_effort": "high",
  "temperature": null,
  "top_p": null,
  "max_tokens": 5000,
  "response_format": {
    "type": "json_object"
  },
  "context_budget": {
    "target_input_tokens": 50000,
    "hard_input_limit_tokens": 140000,
    "reserve_output_tokens": 5000
  }
}
```

Почему `deepseek-v4-pro`: стартовая проза находится на границе между художественным текстом и строгими constraints. Модель должна сохранить время, свет, видимое, неопределённость и hidden boundary. Thinking mode используется для аккуратного соблюдения ограничений, но в пользовательский вывод reasoning не попадает.

## 19. Validation rules для результата narrator

Код проверяет:

1. `schema === "narrator_starting_prose"`.
2. `version === 1`.
3. `prose_status` входит в enum.
4. `prose` является строкой.
5. Если `prose_status=drafted`, `prose` не пустая.
6. `prose` не содержит JSON/debug/audit/schema language.
7. `prose` не содержит raw ids, если UI не должен их показывать.
8. `prose` не содержит слов из `must_not_include`.
9. `prose` не содержит private motives.
10. `prose` не содержит closed container contents.
11. `prose` не содержит future timers.
12. `prose` не содержит hidden ownership.
13. `prose` не содержит новых NPC.
14. `prose` не содержит новых предметов.
15. `prose` не содержит новых exits/routes.
16. `prose` не меняет time_of_day.
17. `prose` не меняет light_profile.
18. `prose` не меняет weather_state.
19. `prose` не меняет season.
20. `prose` не меняет current position.
21. Все `action_options.target_ref` существуют в `available_actions_context`.
22. `action_options.label` не раскрывает hidden truth.
23. `self_constraints_check.used_only_visible_context=true`.
24. `self_constraints_check.did_not_add_new_world_facts=true`.
25. `self_constraints_check.did_not_reveal_hidden_state=true`.
26. `used_visible_context_refs` ссылаются только на видимые refs.
