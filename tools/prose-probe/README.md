# Проба прозы

Инструмент готовит файлы запросов писателю и слепым судьям, затем сводит ответы. Нужен Node 22. Зависимостей и вызовов моделей нет; ответы в папку прогона кладёт распорядитель.

## Порядок прогона

Все команды используют одну папку `--dir`. Пути входных файлов задаются относительно текущего рабочего каталога. Запускайте из корня репозитория:

```sh
node tools/prose-probe/src/cli.mjs packets --dir run --recording perception.jsonl --moments moments.json --actions turns.jsonl --game-data data/mod
node tools/prose-probe/src/cli.mjs writer --dir run --moment M1
```

Распорядитель передаёт `run/M1.req.txt` писателю и сохраняет ответ в `run/M1.out.json`:

```json
{"prose": "Текст отрывка."}
```

Затем распорядитель повторяет `writer` и получение ответа для остальных моментов по порядку. После последнего ответа:

```sh
node tools/prose-probe/src/cli.mjs judges --dir run --anchors anchors.json --judges 3 --seed 7
```

Судьям передаются `judge1-pack.md`, `judge2-pack.md`, `judge3-pack.md` и схема `judge-response.schema.json`. Ключ `judge-key.json` судьям не передаётся. Распорядитель сохраняет их ответы как `judge1.json`, `judge2.json`, `judge3.json`, затем выполняет:

```sh
node tools/prose-probe/src/cli.mjs summary --dir run
node tools/prose-probe/src/cli.mjs summary --dir run --confirmations confirmations.json --baseline previous-run
```

Команды допускают повторный запуск с перезаписью выходов. При отсутствии обязательного входного файла команда сообщает его имя и не пишет выходы. Неполные поля существующего ответа судьи сохраняются в сводке; отсутствующий файл судьи является ошибкой команды.

## Моменты и пакеты

Моменты задаются массивом по порядку; границы — `native_turn`, включительно:

```json
[
  {"id": "M1", "title": "Во дворе", "from_turn": 5227200, "to_turn": 5227217},
  {"id": "M2", "title": "Вход под крышу", "from_turn": 5227218, "to_turn": 5227221},
  {"id": "M3", "title": "Под крышей", "from_turn": 5227222, "to_turn": 5227226}
]
```

`packets` копирует моменты в папку прогона и пишет `packets.json`. У момента сохраняются `id`, `title`, `from_turn`, `to_turn`; `parts` содержит последовательные части `{scene_id, scene_first, packet}`. Сцена меняется при изменении места, крыши, положения снаружи или OMT героя. Первая часть сцены содержит полную доступную сцену, следующие — перемены.

Поле «Место» определяется по OMT героя: один overmap terrain покрывает 24×24 клетки карты. Абсолютные координаты переводятся в OMT с делением вниз, в том числе для отрицательных координат, как в CDDA: `/srv/novgorod-work/scratch/task25-yard/native/src/coordinates.h:34–45` и `/srv/novgorod-work/scratch/task25-yard/native/src/map_scale_constants.h:14–17`. Нативный checkout сообщает версию `0d8843f-dirty` в `/srv/novgorod-work/scratch/task25-yard/native/src/version.h`, на коммите `0d8843f1c500052c3e026e3da6f8edaf5e00b626`; его рабочее дерево было изменено. Дальние ориентиры за пределами текущего OMT пока не передаются.

«Вещи вокруг», мебель и видимая местность ограничены текущим OMT. Существа с записанным `id` сопоставляются по нему; подтверждённая перемена их абсолютного положения передаётся как событие перемещения. У существа без `id` нельзя установить личность отдельного наблюдения: записи группируются по типу и признаку `inPlace` — находится ли существо в месте сцены. Поэтому переход границы места передаётся изменением двух групп, без утверждения, что удалось проследить конкретное животное. Положение двух существ без `id` не сопоставляется по отдельности. Виды местности передаются без числа клеток. Внутренние абсолютные координаты и типы нужны для сравнения и в текст не выходят. Изменение направления относительно героя само по себе переменой объекта не считается. Новые сведения о впервые увиденных предметах или местности помещаются в их разделы, а не в «События».

Начальные значения полей состояния для каждой сцены берутся из её первого кадра. Если погода, свет, пора суток или состояние героя впервые появляются в более позднем кадре, это позднее появление передаётся как событие, а не как исходное состояние сцены. Состояние хода устанавливает последний `sequence`; промежуточные кадры сохраняют подтверждённые действия и реальные перемены, произошедшие до конца момента. Прежний факт о вещи, мебели или местности сохраняется, когда её клетка выходит из поля зрения. Слова «больше не видно» для вещи или мебели появляются только если прежняя клетка остаётся в `visible_terrain`, а экземпляр отсутствует и не найден на другой клетке. Для существа без `id` отсутствие из соответствующей группы типа и `inPlace` означает уменьшение её числа наблюдений; для существа с `id` отсутствие в новом списке `creatures` означает «больше не видно».

Поддерживаются только строки `kind=full`. Другая строка вызывает ошибку с её `sequence`. Используется нативная видимая выборка записи, без дополнительного радиуса и без очистки чужого содержимого CDDA.

Поля пакета: «Герой», «Место», «Пора суток», «Погода», «Свет», «Самочувствие», «При себе», «Видимая местность», «Вещи вокруг», «Люди и звери», «Речь», «Звуки», «События». Пустые разделы опускаются. Описания включаются в предложения о вещах; отдельного поля описания нет. Имя и пол героя берутся из `player_state`; пол передаётся словом «мужчина» или «женщина». Характеристики существ не достраиваются из имени или типа.

Запись транспорта содержит `vehicle_part`, позицию, направление и `vehicle_name`, но не устойчивый идентификатор транспорта. Поэтому две одноимённые повозки в одном кадре отличить друг от друга нельзя; сведения о частях с одинаковым именем не позволяют надёжно утверждать число отдельных повозок. Внутренние координаты, uid и типы служат сравнению экземпляров и в текст не выходят. В остальных разделах одинаковые по содержанию строки группируются, количество пишется словами; различающиеся вещи не объединяются только по названию. В «Событиях» объединяются только непосредственно соседние одинаковые строки, чтобы сохранить порядок перемен. Количества до 999 передаются словами, большее количество вызывает ошибку. Видимые участки местности не пересчитываются в число клеток. Отмена ранее переданного состояния сообщается лишь при подтверждённой перемене. Отображаемые названия очищаются от цветовой разметки и начальных знаков улучшения `+`. Сырые показатели веса, ИМТ, температуры и освещённости не передаются. Дата, число и месяц не передаются.

### Действия

`--actions turns.jsonl` необязателен. Строка действий связывается с кадром `reason=turn` того же `native_turn`: оба записаны в конце хода. `input_number` является счётчиком запросов ввода и для связи не используется.

Поддержаны только действия настоящей записи: `RIGHT`, `DOWN`, `UP`, `RIGHTUP`, `LEFTDOWN` и `open`. Перемещение требует изменения `frame.position` в записанном направлении; открытие двери — наблюдаемого перехода закрытой двери к записанному `open_to`. `debug`, `safemode`, `player_data` исключены. Неизвестное действие исключается с предупреждением.

Действие без видимого результата и несколько неоднозначных действий в одном ходе не утверждаются как поступки. Без `--actions` перемены передаются без действующего лица. Последовательные подтверждённые перемещения одной части объединяются в одно предложение; одинаковые соседние направления упоминаются один раз, длина пути не сообщается.

### Описания и названия предметов

`--game-data` можно повторить. JSON-файлы каталогов обходятся в порядке имён, каталоги — в порядке параметров. Поле `description` ищется по `id` типа; принимается строка либо объект с `str`/`str_sp`. Более позднее найденное описание одного id заменяет предыдущее; описания через `copy-from` не наследуются.

Названия для `activity.tool` и `activity.material` берутся только из записей `type: "ITEM"`: из строки `name`, поля `name.str` или, если его нет, `name.str_sp`. Если имя не задано, инструмент проходит цепочку `copy-from`. Позднее явное имя того же id заменяет предыдущее. Значения передаются из JSON как записаны: инструмент не загружает CDDA, не переводит и не сочиняет названия. Если для указанного id имя не найдено в `--game-data`, команда сообщает об ошибке.

### Звуки

`frame.journal` исключён целиком: категория сообщения не обозначает происхождение. Ограничение записи обсуждается в [#920](https://github.com/PavelSlaven/Novgorod1230/issues/920).

Категории `sounds` 5 (`speech`) и 6 (`electronic_speech`) попадают в «Речь»; остальные — в «Звуки». В частности, 11 означает `alert`. Текст звука, включая записанную в `alert` реплику, передаётся дословно. Повтор одного буфера в снимках ввода не создаёт повторное событие; одинаковые отдельные события сохраняются. Если дословный звук несовместим с запретом цифр, идентификаторов или разметки в пакете, команда сообщает ошибку, не переписывая звук.

## Писатель и судьи

Писатель получает прежние части той же сцены, части текущего момента и предыдущий отрывок. Предыдущий отрывок помогает продолжению, но не является источником фактов. Для второго и последующих моментов необходим непустой `prose` предыдущего ответа.

Якоря имеют форму:

```json
{"ANCH-A": {"text": "Текст якоря.", "facts": "Основание якоря."}}
```

Номера `T01`, `T02` назначаются общей перестановкой. Каждый судья получает свою перестановку; seed управляет собственным 32-битным генератором инструмента. Одинаковые входы и seed дают одинаковые байты. Запрос судьи содержит то же основание игрового текста, что запрос писателя.

Судьи могут отличить якоря по форме основания и восстановить порядок игровых текстов по предыдущему отрывку. У якоря основание — строка `facts`, у игры — части `{scene_id, scene_first, packet}`. Слепая перестановка сохраняет эту видимую разницу.

## Сводка

`summary.json` и `summary.md` сохраняют отметки, цитаты, живость, причины итога, поля D186, предупреждения и исходные ответы. Неполный ответ не участвует в среднем, но его остальные отметки не удаляются. Цитаты проверяются только после замены переводов строк пробелами и сжатия повторных обычных пробелов.

Файл проверяющего:

```json
{"M1": {"criteria": {"2": "confirmed", "4": "rejected"}, "blocking": []}}
```

`confirmed` применим лишь при отметке «нет» по этому признаку хотя бы у одного судьи. Для признаков 2–4 без решения итог остаётся «не решено». Засчитанное нарушение, blocking или среднее полных ответов ниже 8 дают «не проходит». Затем проверяется число полных ответов и наличие нерешённых отметок; иначе текст проходит. Среднее сравнивается до округления. Отрицательные отметки остальных признаков остаются замечаниями.

Итог «проходит» — подсчёт отметок судей и решений проверяющего; он не заменяет приёмку: проверяющий сверх отметок проверяет фактические изменения, причинность и дословную речь (§16.1 нормы, строка 518).

Якоря показываются отдельно, без итога и без участия в таблицах выдумок игровых текстов. Таблицы содержат все отметки и уникальные пары «текст + цитата» внутри каждой ячейки класса и пункта. Ненайденные цитаты не скрываются.

Baseline сравним только при совпадении упорядоченного списка моментов и SHA-256 содержимого трёх шаблонов подряд: `judge-rubric.md`, `writer-system.md`, `writer-task.md`. При совпадении показываются прошлые значения и разности всех ячеек, включая нулевые; иначе показывается причина несравнимости без численного сравнения.

## Проверка и пределы

```sh
node --test tools/prose-probe/test/*.test.js
npm run test:tools
npm run docs:check
git diff --check
```

Происхождение реальных кадров и разрешённые сокращения перечислены в [README образцов](test/fixtures/README.md). Отдельный красный случай выбирается переменной `PROSE_PROBE_RED_CASE` и `--test-name-pattern`; порча применяется только к артефакту этого случая внутри тестовой временной папки. Обычный запуск проверяет настоящую CLI без порчи.

Занятие, поза и отклик NPC выводятся только из одноимённых полей кадра; инструмент не достраивает их из имени, действий или текста героя. Он не восполняет отсутствующие сведения о мире, узнавание, биографию, манеру или запах. Запись не содержит церковного календаря и надёжных границ комнат. Дальние ориентиры за пределами OMT не проецируются. Порядок игровых событий между пакетами восстанавливается по предыдущему отрывку, который помогает продолжению, но не служит источником фактов. Видимость существ зависит от последнего нативного кеша; отдельные объекты наследуют видимость клетки. Проверка художественного качества требует внешних ответов писателя и судей.
