# Этап 5. Подбор допустимых стартовых G1–G4 кандидатов

## 1. Назначение этапа

Подбор допустимых стартовых G1–G4 кандидатов — это пятый этап запуска новой партии. Он получает:

* нормализованную заявку игрока;
* утверждённую историческую рамку;
* загруженный региональный контекст;
* канонический граф региона из `world_base`.

На выходе этап возвращает не одно стартовое место, а список допустимых стартовых кандидатов.

Кандидат — это не готовая сцена. Это допустимая точка старта на уровне G1–G4, где позже можно будет:

* выбрать конкретное стартовое место;
* сгенерировать персонажа;
* материализовать G5;
* разместить NPC;
* разместить причинно обоснованные предметы;
* сформировать hidden state и visible context.

Короткая формула:

```text id="f6s0s6"
historical_frame
+ regional_context_package
+ world_base graph G1–G4
+ player normalized request
→ start_candidate_set
```

## 2. Главное правило этапа

Код выбирает список допустимых кандидатов из уже существующего графа и региональных ограничений.

Код не создаёт новые места.
LLM не создаёт новые места.
LLM не выбирает стартовую сцену.
LLM не создаёт NPC, предметы или G5-якоря.

На этом этапе разрешено:

* читать `world_base.graph_nodes`;
* читать `world_base.graph_edges`;
* читать региональные правила мест;
* читать place templates;
* читать landscape/water/land_use/route constraints;
* читать сезонные и временные ограничения;
* фильтровать узлы;
* проверять родительскую цепочку G1→G2→G3→G4;
* проверять соседние связи;
* проверять доступность по времени суток и сезону;
* формировать список кандидатов;
* группировать кандидатов;
* ранжировать кандидатов техническим scoring;
* запускать LLM только для аудита, сжатия или пояснения уже найденного списка.

На этом этапе запрещено:

* создавать новый G1/G2/G3/G4;
* создавать G5;
* выбирать финальный стартовый узел;
* создавать NPC;
* создавать предметы;
* создавать стартовую прозу;
* создавать событие;
* менять историческую рамку;
* исправлять карту через LLM;
* подставлять “похожее место”, если подходящих узлов нет;
* использовать общий текстовый prompt вместо `world_base` candidate retrieval.

## 3. Место этапа в pipeline

```text id="fq8lpg"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста из world_base
5. Подбор допустимых стартовых G1–G4 кандидатов
6. Выбор одного стартового места из candidate set
7. Генерация персонажа
8. Материализация стартовой G5-сцены
```

Этап 5 не завершает старт игры. Он только создаёт безопасное поле выбора для этапа 6.

## 6. Что такое стартовый кандидат

Стартовый кандидат — это узел G1–G4, который может быть использован следующим этапом как допустимый стартовый узел или часть стартовой иерархии.

Предпочтительно стартовать с G4, потому что G4 ближе всего к конкретной игровой локации. Но кандидат должен хранить полную цепочку:

```text id="lu0vpb"
G1 region cell
→ G2 zone
→ G3 place
→ G4 location
```

Для G4-кандидата обязательна структура:


## 7. Какие масштабы допустимы

### 7.1. G1

G1 — крупная региональная ячейка. Она может быть кандидатом только как контекст, но не как точная стартовая позиция.

Разрешено:

```text id="xd2qjc"
использовать G1 для ограничения региона, природной среды, соседства, больших дорог, исторических якорей
```

Запрещено:

```text id="wte8lt"
стартовать только в G1 без G2/G3/G4, если база содержит более глубокие узлы
```

Если доступен только G1, этап должен вернуть `requires_repair` или `blocked`, если политика требует точного старта.

### 7.2. G2

G2 — внутренняя зона G1: дорога, лесной массив, береговая зона, окрестность поселения, участок реки, полевая зона.

G2 может быть fallback-кандидатом, если нет G3/G4, но для старта он недостаточно точен.

Разрешено:

```text id="j4ogjk"
использовать G2 для будущего выбора G3/G4-кандидатов
```

Запрещено:

```text id="fuif7f"
считать G2 финальной сценической стартовой позицией
```

### 7.3. G3

G3 — конкретное место: село, погост, монастырь, городская часть, переправа, двор, торг, пристань, лесной стан.

G3 может быть стартовым кандидатом, если:

* у него есть допустимый place template;
* есть доступные дочерние G4 или допустима последующая материализация G4;
* он совместим с временем, сезоном и региональными правилами.

### 7.4. G4

G4 — конкретная локация внутри места: двор, ворота, пристань, участок дороги, амбарная зона, берег у переправы, торг, сени, опушка, вход в монастырский двор.

G4 — предпочтительный стартовый уровень.

G4-кандидат должен иметь:

```text id="mmo97d"
полную цепочку G1→G2→G3→G4
допустимый тип места
совместимые правила региона
минимум один вход/выход
совместимость с сезоном
совместимость с временем суток
возможность будущей G5-материализации
```

## 9. Алгоритм этапа

### 9.1. Проверить вход

Код проверяет:

```text id="t4otf5"
normalized_request.schema = new_game_normalized_request
historical_frame.schema = historical_frame
historical_frame.audit.pass = true
regional_context_package.schema = regional_context_package
regional_context_package.audit.pass = true
region_id задан
year задан
season задан
clock задан
```

Если `clock` не содержит `hour`, `minute`, `time_of_day`, `light_profile`, этап блокируется.

### 9.2. Загрузить узлы региона

Код загружает все G1–G4 узлы выбранного региона:

```sql id="qz5zpo"
SELECT *
FROM world_base.graph_nodes
WHERE region_id = :region_id
  AND scale_level IN ('G1', 'G2', 'G3', 'G4')
  AND status IN (:allowed_statuses);
```

Если граф хранит G1 как региональные ячейки, а G2–G4 связаны через `parent_node_id`, код обязан загрузить всю родительскую цепочку.

### 9.3. Загрузить связи

```sql id="acauxu"
SELECT *
FROM world_base.graph_edges
WHERE status IN (:allowed_statuses)
  AND (
    from_node_id IN (:loaded_node_ids)
    OR to_node_id IN (:loaded_node_ids)
  );
```

Связи нужны не для движения сейчас, а для проверки, что кандидат не является изолированной точкой без входа и выхода.

### 9.4. Построить parent chain

Для каждого узла G4 код восстанавливает:

```text id="tso6hu"
G4.parent = G3
G3.parent = G2
G2.parent = G1
G1.region_id = historical_frame.region_id
```

Если цепочка неполная, кандидат отбрасывается или отправляется в `rejected_candidates`.

Ошибка:

```text id="wumgdd"
START_CANDIDATE_BROKEN_PARENT_CHAIN
```

### 9.5. Проверить регион

Каждый кандидат должен относиться к выбранному региону.

```text id="zjk9ou"
candidate.region_id == historical_frame.region.region_id
```

Если узел связан с другим регионом, он не может быть стартовым кандидатом, даже если географически “похож”.

### 9.6. Проверить год

Если у узла, place template или regional rule есть период применимости:

```text id="m03ekl"
start_year <= historical_frame.year.value <= end_year
```

Если период несовместим, кандидат отбрасывается.

### 9.7. Проверить season

Код проверяет:

```text id="e470e1"
seasonal_rule
route_season_modifiers
weather_season_rules
land_use seasonal pattern
water crossing seasonality
route availability
```

Кандидат может остаться допустимым с предупреждением, если старт возможен, но есть риск.

Пример:

```json id="d3gg3w"
{
  "night_or_season_warnings": [
    "Route nearby is slower in winter.",
    "Water crossing requires later check before movement."
  ]
}
```

Но если место невозможно использовать в выбранный сезон, кандидат отбрасывается.

### 9.8. Проверить time_of_day

Код сверяет:

```text id="eaa3r0"
clock.time_of_day
clock.light_profile
access rules
NPC/work rhythm rules
route access
place opening/closing rules
safety constraints
```

Старт ночью допустим, если:

* выбранный узел может существовать ночью;
* персонаж может находиться там без немедленного противоречия;
* дальнейшая стартовая сцена сможет объяснить доступ;
* нет правила, прямо запрещающего нахождение там ночью.

Старт ночью не допустим, если:

* место должно быть закрыто;
* доступ невозможен;
* узел требует дневной активности;
* региональные правила запрещают такой старт;
* будущая visible scene неизбежно противоречит `clock.light_profile`.

### 9.9. Проверить place template

Если кандидат имеет `place_template_id`, он должен входить в `regional_context_package.settlement_and_place_rules.allowed_place_templates`.

```text id="7mmk84"
candidate.place_template_id ∈ allowed_place_template_ids
```

Если `place_template_id` отсутствует у G4, код может наследовать его от G3, если это разрешено схемой.

Если невозможно установить тип места, кандидат отбрасывается.

### 9.10. Проверить landscape/water/land_use

Код проверяет:

```text id="yjam89"
primary_landscape_template_id ∈ allowed_landscapes
primary_water_body_template_id ∈ allowed_water_body_templates, если задан
land_use_template_ids ⊆ allowed_land_use_templates
```

Если узел содержит несовместимый ландшафт, воду или хозяйственное использование, он отбрасывается.

### 9.11. Проверить route/access edges

Кандидат должен иметь минимум один валидный вход или выход:

```text id="vh6t2t"
entry_edge_ids.length + exit_edge_ids.length >= 1
```

Для G4 желательно:

```text id="0veivx"
минимум один путь к родительскому G3
или минимум один локальный проход
или минимум один edge к соседнему G4
```

Если кандидат изолирован, он не может быть стартовым местом.

### 9.12. Проверить совместимость с заявкой игрока

Код не должен “понимать художественно”, но может сопоставлять нормализованные поля с метаданными:

```text id="ec6rtl"
start_place_request.value
tone_request.value
difficulty_request.value
hard_constraints
soft_preferences
forbidden_content
```

Примеры:

```text id="xoel22"
если игрок запретил город → отбрасывать urban candidates
если игрок просил дорогу → повышать score route/roadside candidates
если игрок просил быт → повышать score household/rural/domestic candidates
если игрок просил случайно → не фильтровать по месту, только по допустимости
```

Если нет запроса, это не ошибка. Поле трактуется как `random`.

### 9.13. Проверить будущую G5-материализацию

Этап не создаёт G5, но должен проверить, что для выбранного G4-типа существуют допустимые G5-шаблоны.

```text id="63e0g7"
g4_type_id ∈ g5_context.g4_type_to_allowed_anchor_rules
```

Если G5-шаблонов нет, кандидат можно оставить только если политика разрешает будущий repair. Для полноценного старта такой кандидат лучше отклонять.

### 9.14. Сформировать score

Scoring не создаёт мир. Он только сортирует уже допустимых кандидатов.

Пример технического scoring:

```text id="a9j0s8"
score =
  base_allowed_score
+ request_match_score
+ full_parent_chain_score
+ access_edge_score
+ place_rule_score
+ season_match_score
+ time_match_score
+ g5_ready_score
- warning_penalty
- weak_source_penalty
```

Рекомендуемая шкала:

```text id="tyj64b"
90–100 = excellent
70–89 = good
50–69 = usable
30–49 = weak
0–29 = reject
```

Кандидаты ниже порога не попадают в основной список.

### 9.15. Сформировать группы

Чтобы этап 6 не выбирал из хаотического списка, код группирует кандидатов:

```text id="esrfyb"
by scale
by place_template
by start tone
by risk level
by social environment
by route accessibility
by landscape
by urban/rural/wild/road/water
```

Пример:

```json id="ozzm3w"
{
  "candidate_groups": [
    {
      "group_id": "rural_household_low_risk",
      "title": "Rural household starts, low risk",
      "candidate_ids": [],
      "group_tags": [
        "rural",
        "domestic",
        "low_risk"
      ]
    }
  ]
}
```

## 10. Кандидат не равен выбору

На этом этапе нельзя писать:

```json id="ac9l2q"
{
  "selected_start_node_id": "..."
}
```

## 13. Hard gates

Кандидат должен быть отклонён без LLM, если нарушено одно из правил:

```text id="b4ae7y"
region_id mismatch
missing parent chain
missing canonical node
missing source when require_sources=true
status=rejected
status=conflict
place_template not allowed in region
landscape template not allowed in region
water body template not allowed in region
land use template not allowed in region
no access edges
clock/access conflict
season impossible
G5 materialization impossible
player hard constraint conflict
```

Эти проверки выполняются кодом. Это не генерация мира, а валидация ссылок и ограничений.

## 15. Работа LLM на этом этапе

Базовый этап должен работать без LLM. Основной retrieval и hard filtering выполняются кодом.

LLM допускается только в трёх вспомогательных режимах:

1. `StartCandidateSetCompressor` — сжать большой список кандидатов для следующего LLM-этапа.
2. `StartCandidateSetAuditor` — проверить, нет ли смысловых противоречий в уже собранном списке.
3. `StartCandidateExplanationWriter` — сформировать технические пояснения для разработчика, не для игрока.

LLM не имеет права:

* добавлять новые candidate IDs;
* менять node IDs;
* менять scores;
* добавлять узлы вне `world_base`;
* выбирать один финальный старт;
* создавать сцену.

## 20. Validation rules

Код обязан проверить:

1. `schema === "start_candidate_set"`.
2. `version === 1`.
3. `selection_status` входит в enum: `ready`, `empty`, `blocked`, `requires_repair`.
4. Если `selection_status=ready`, `candidates.length >= candidate_policy.target_candidate_count_min`, если это возможно.
5. Каждый `candidate_id` уникален.
6. Каждый `canonical_node.node_id` существует в `world_base.graph_nodes`.
7. Каждый кандидат относится к `historical_frame.region.region_id`.
8. Каждый G4-кандидат имеет полную parent chain G1→G2→G3→G4.
9. Каждый G3-кандидат имеет parent chain G1→G2→G3.
10. Каждый place template допустим в регионе.
11. Каждый landscape template допустим в регионе.
12. Каждый water body template допустим в регионе или null.
13. Каждый land use template допустим в регионе.
14. Каждый route template nearby допустим.
15. У каждого allowed-кандидата есть минимум один entry/exit edge.
16. `clock_match=true` у всех allowed-кандидатов.
17. `season_match=true` у всех allowed-кандидатов.
18. `player_request_match != conflict`.
19. `g5_ready=true` у всех G4-кандидатов, если `prefer_g4_for_start=true`.
20. Нет `selected_start_node_id`.
21. Нет `visible_scene`.
22. Нет `intro_prose`.
23. Нет `npc_ids`.
24. Нет `items`.
25. Нет `g5_anchor_id`.
26. `source_trace` не пустой, если `require_sources=true`.
27. Все source IDs существуют в `source_records`.
28. `audit.evidence` не пустой.
29. Если `audit.pass=false`, `audit.concerns` не пустой.

## 23. Commit gate этапа

Этап считается успешным, если:

```text id="nx8qf6"
start_candidate_set валиден,
есть хотя бы один allowed-кандидат,
каждый allowed-кандидат существует в world_base,
каждый allowed-кандидат совместим с historical_frame,
каждый allowed-кандидат совместим с regional_context_package,
каждый allowed-кандидат имеет путь доступа,
каждый allowed G4-кандидат готов к будущей G5-материализации,
нет созданных downstream-сущностей,
audit.pass=true.
```

Если кандидатов нет, pipeline не должен передавать LLM задачу “придумай место”. Он должен:

1. ослабить только разрешённые soft preferences;
2. попробовать fallback scale G3, если policy позволяет;
3. вернуть `blocked`, если hard constraints не позволяют выбор;
4. вернуть `requires_clarification`, если игрок запретил случайную замену;
5. записать `NO_ALLOWED_START_CANDIDATES`.
