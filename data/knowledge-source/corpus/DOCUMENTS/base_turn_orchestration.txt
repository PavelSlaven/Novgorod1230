# Режимы хода для агента-оркестратора

## 0. Общий принцип

Режим хода — это не отдельная мини-игра, а выбранный оркестратором маршрут обработки заявки игрока.

Игрок пишет свободный текст. Этот текст является намерением, а не фактом мира.

```text
"Я беру нож со стола"
≠
нож точно есть на столе и уже взят

"Я беру нож со стола"
=
персонаж пытается взять нож, если нож существует, видим, доступен и действие возможно
```

Оркестратор каждый ход обязан пройти общий входной шлюз, выбрать основной режим, при необходимости добавить вторичные режимы и только потом запускать расчёт последствий.

## 1. Универсальная последовательность любого хода

```text
1. Получить player_input.
2. Зафиксировать raw_text как намерение, не как факт.
3. Загрузить текущее party_state.
4. Загрузить current_position.
5. Загрузить текущее время, свет, погоду.
6. Загрузить visible_context последнего хода.
7. Загрузить character_knowledge_map.
8. Загрузить релевантный hidden_state, если он может повлиять на результат.
9. Загрузить NPC, предметы, контейнеры, доступные маршруты, события и recent_changes_log.
10. Нормализовать намерение игрока.
11. Выбрать основной режим хода.
12. Выбрать вторичные режимы, если действие смешанное.
13. Проверить физическую, социальную, временную и информационную доступность действия.
14. Если действие невозможно по фактам мира — не назначать проверку, а сформировать отказ/частичный результат/альтернативу.
15. Если исход спорный, опасный или неочевидный — назначить проверку.
16. Рассчитать длительность.
17. Обновить время, если действие не мгновенное.
18. Обновить тело персонажа, если есть причина.
19. Обновить NPC, место, предметы, hidden_state и события.
20. Сформировать список изменений.
21. Провести аудит новых фактов.
22. Записать изменения в party_state.
23. Сформировать новый visible_context_package.
24. Проверить visible_context на отсутствие hidden leaks.
25. Сгенерировать narrator prose только из visible_context.
26. Проверить narrator prose.
27. Показать игроку результат и новые доступные действия.
```

Базовая формула:

```text
ход = состояние партии + намерение игрока + проверка доступности + подсистема + последствия + фиксация + видимое состояние + проза
```

## 2. Режим 1. Внимание, осмотр, поиск, слушание, слежение

### Включает намерения

```text
осмотреться;
искать;
слушать;
следить;
вспоминать, если речь о воспринимаемом или известном;
проверить что-то взглядом;
понюхать;
присмотреться;
прислушаться;
изучить след;
осмотреть предмет;
осмотреть контейнер;
осмотреть NPC.
```

### Когда выбирать

Оркестратор выбирает этот режим, если игрок не пытается сразу менять мир, а хочет получить больше информации о текущей сцене.

### Последовательность

```text
1. Определить current_position.
2. Определить точку внимания: вся сцена, NPC, предмет, контейнер, дверь, проход, звук, след, запах, тело персонажа.
3. Проверить, находится ли цель внимания в текущем G5/G4-контексте.
4. Проверить видимость: свет, расстояние, преграды, погода, угол обзора.
5. Проверить слышимость/запах/осязание, если цель не визуальная.
6. Проверить, знает ли персонаж, что именно он ищет.
7. Проверить, не требует ли осмотр перемещения ближе.
8. Проверить занятость рук, если осмотр физический.
9. Проверить риск: свидетели, запрет, чужое имущество, социальная опасность.
10. Определить длительность.
11. Если результат очевиден — раскрыть видимое без броска.
12. Если результат неочевиден — выполнить проверку внимания/наблюдательности/поиска.
13. Если найден признак скрытого — раскрыть только признак, а не скрытую истину.
14. Если ничего заметного нет — честно зафиксировать отсутствие заметного результата.
15. Обновить character_knowledge_map, если персонаж что-то узнал.
16. Обновить visible_context.
17. Сгенерировать прозу только из нового видимого состояния.
```

### Жёсткие запреты

```text
Осмотр не создаёт предмет из воздуха.
Поиск не обязан находить желаемое.
Скрытый факт не раскрывается целиком без основания.
Нельзя показать содержимое закрытого контейнера без открытия или достаточного условия.
Нельзя назвать источник звука, если персонаж его не определил.
```

## 3. Режим 2. Перемещение внутри сцены или места

### Включает намерения

```text
идти;
подойти;
отойти;
перейти к двери;
зайти внутрь;
выйти наружу;
перейти к NPC;
перейти к предмету;
пройти в соседнюю минилокацию;
бежать внутри сцены;
отступить без боя;
проверить видимый проход.
```

### Когда выбирать

Если действие меняет `anchor_id`, `minilocation_id` или `location_id`, но не обязательно уводит персонажа в дальний путь.

### Последовательность

```text
1. Определить current_position.
2. Определить заявленную цель движения: anchor, minilocation, location, видимый выход или направление.
3. Проверить, существует ли соответствующий G5/G4 edge.
4. Проверить, видит ли персонаж этот путь или знает о нём.
5. Проверить доступ: открыт, закрыт, заперт, охраняется, запрещён, неизвестен.
6. Проверить физические условия: свет, погода, грязь, снег, теснота, препятствия.
7. Проверить состояние тела: раны, усталость, холод, груз.
8. Проверить занятые руки, если движение осложнено.
9. Проверить свидетелей и социальный риск.
10. Определить длительность.
11. Если путь прост и доступен — обновить позицию.
12. Если путь спорный/опасный — выполнить проверку перемещения, скрытности, реакции или силы.
13. Обновить время.
14. Обновить NPC: кто заметил, кто отреагировал, кто изменил позицию.
15. Обновить hidden_state и events, если движение запустило триггер.
16. Записать новую current_position.
17. Собрать новую видимую сцену.
18. Сгенерировать прозу прибытия или частичного результата.
```

### Жёсткие запреты

```text
Нельзя телепортировать персонажа.
Нельзя пройти через несуществующий edge.
Нельзя считать неизвестный проход известным маршрутом.
Нельзя возвращать старое место как новую генерацию, если оно уже сохранено.
```

## 4. Режим 3. Перемещение по маршруту

### Включает намерения

```text
двигаться по маршруту;
идти по дороге;
вернуться назад;
идти к известному месту;
идти к месту, дорогу к которому персонаж знает;
ехать;
плыть;
идти через брод, мост, тропу, ворота, зимник.
```

### Когда выбирать

Если заявка использует сохранённый route/edge или известный персонажу путь между узлами карты.

### Последовательность

```text
1. Определить current_position.
2. Определить целевой узел или route_id.
3. Проверить, существует ли маршрут в фактической карте.
4. Проверить, знает ли персонаж маршрут.
5. Проверить, известен ли маршрут игроку как player-safe информация.
6. Проверить доступность маршрута сейчас: сезон, погода, время суток, запертые ворота, охрана, брод, лёд.
7. Проверить нагрузку и состояние тела.
8. Рассчитать итоговое время пути.
9. Рассчитать риск пути.
10. Если путь безопасный/обычный — применить время и расход.
11. Если путь рискованный — выполнить проверку движения/ориентации/выживания/скрытности.
12. Проверить события на пути.
13. Обновить время.
14. Обновить состояние тела.
15. Обновить route state, traces, knowledge, last_route_id.
16. Обновить NPC и место отправления/прибытия.
17. Записать новую позицию при прибытии или промежуточную позицию при частичном ходе.
18. Сформировать новую видимую сцену.
19. Сгенерировать prose после расчёта последствий.
```

### Жёсткие запреты

```text
Маршрут может существовать, но быть неизвестным персонажу.
Знание игрока не равно знанию персонажа.
Один и тот же маршрут в другое время обрабатывается заново с новыми условиями.
```

## 5. Режим 4. Дальний курс

### Включает намерения

```text
иду на север;
держусь востока;
иду прочь;
иду вниз по реке;
ухожу в лес;
иду вдоль берега;
держу направление к видимому ориентиру;
иду, пока не встречу дорогу;
иду куда глаза глядят.
```

### Когда выбирать

Если игрок не указывает конкретный сохранённый маршрут или известный узел, а задаёт направление, ориентир или общий курс.

### Последовательность

```text
1. Определить current_position.
2. Определить направление или ориентир.
3. Определить способ движения: пешком, бегом, верхом, по воде, скрытно, с грузом.
4. Проверить карту знаний персонажа: понимает ли он местность, знает ли ориентиры.
5. Проверить фактическую карту: какие узлы, маршруты, препятствия и исторические/хозяйственные якоря есть в направлении.
6. Не раскрывать игроку скрытые якоря напрямую.
7. Рассчитать прогресс.
8. Рассчитать отклонение курса.
9. Проверить риск заблудиться.
10. Проверить время пути, состояние тела, нагрузку, погоду и свет.
11. При необходимости выполнить проверку ориентации/выживания/наблюдательности.
12. Выбрать результат курса: маршрут, препятствие, хозяйственный след, промежуточная зона, приближение к якорю, заблуждение, риск, встреча, возврат к следам.
13. Материализовать только ближайший необходимый фрагмент, если он не был создан.
14. Проверить новый фрагмент на регион, эпоху, ландшафт, хозяйство и старые факты.
15. Обновить время, тело, события и знания.
16. Записать фактическую и воспринимаемую позицию, если они расходятся.
17. Сформировать видимую сцену.
18. Сгенерировать prose.
```

### Жёсткие запреты

```text
Дальний курс не может бесконечно идти без прогресса.
Исторический якорь не притягивает персонажа автоматически.
Скрытая фактическая карта не выдаётся как знание персонажа.
```

## 6. Режим 5. Предметы, имущество, контейнеры, инвентарь

### Включает намерения

```text
брать;
использовать предмет;
отдать;
спрятать;
продать;
купить;
сломать;
починить;
открыть;
вскрыть;
переложить;
достать из сумки;
обыскать контейнер;
надеть;
снять;
передать;
попробовать применить инструмент.
```

### Когда выбирать

Если действие касается физического объекта, контейнера, снаряжения, инвентаря, собственности или доступа.

### Последовательность

```text
1. Определить объект действия.
2. Проверить, существует ли объект в party_state.
3. Если объект не существует — проверить, допустима ли материализация по профилю места, но не создавать объект из желания игрока.
4. Проверить, видит ли персонаж объект.
5. Проверить, знает ли персонаж, что это за объект.
6. Проверить физический доступ: расстояние, преграда, контейнер, замок, высота, вес.
7. Проверить занятые руки.
8. Проверить состояние предмета.
9. Проверить владельца, держателя и контролёра доступа.
10. Проверить социальный, правовой и репутационный риск.
11. Проверить свидетелей.
12. Проверить, меняется ли инвентарь или только имущественная связь.
13. Если действие простое и разрешённое — применить изменение.
14. Если действие спорное — выполнить проверку силы, ловкости, внимания, ремесла, скрытности или обычая/закона.
15. Обновить предмет, контейнер, владение, доступ, следы, состояние, инвентарь.
16. Обновить NPC reactions, если действие заметили.
17. Обновить hidden_state и события.
18. Обновить visible_context.
19. Сгенерировать prose.
```

### Жёсткие запреты

```text
Заявка игрока не создаёт предмет.
Физически взять предмет ≠ стать владельцем.
Имущество вне физического доступа не считается инвентарём.
Содержимое контейнера не пересоздаётся после определения.
Нельзя раскрывать содержимое закрытого контейнера без основания.
```

## 7. Режим 6. Разговор, вопрос, просьба, торг, ложь, договорённость, социальное давление

### Включает намерения

```text
говорить;
спрашивать;
просить;
торговаться;
лгать;
договариваться;
убеждать;
угрожать словами;
давить статусом;
просить помощи;
просить разрешения;
выяснять слух;
нанимать;
обещать;
обмениваться.
```

### Когда выбирать

Если действие адресовано NPC, группе, власти, хозяину, свидетелю, торговцу, старшему, спутнику или неизвестному человеку.

### Последовательность

```text
1. Определить адресата.
2. Проверить, существует ли NPC/группа в текущей сцене или известной зоне.
3. Проверить, видит/слышит ли персонаж адресата.
4. Проверить, может ли адресат видеть/слышать персонажа.
5. Проверить дистанцию, шум, свет, занятость, статус ситуации.
6. Загрузить профиль NPC нужной глубины.
7. Если фоновый NPC вступает в адресное взаимодействие и должен оставить последствия — повысить профиль до сценического или ключевого.
8. Проверить, знает ли NPC персонажа.
9. Проверить отношение: свой/чужой, статус, страх, долг, интерес, память.
10. Проверить, что NPC знает и что скрывает.
11. Проверить, кто слышит разговор.
12. Определить цель игрока: информация, помощь, доступ, сделка, обман, угроза, просьба.
13. Проверить, может ли NPC вообще дать желаемое.
14. Если результат очевиден по роли и ситуации — дать результат без броска.
15. Если результат спорный — выполнить социальную проверку.
16. Обновить отношение NPC, знание NPC, слухи, обещания, долги, доступ или отказ.
17. Обновить время.
18. Обновить visible_context.
19. Сгенерировать prose/реплику без раскрытия private motives.
```

### Жёсткие запреты

```text
NPC не обязан быть полезным.
NPC действует из статуса, страха, интереса, долга, памяти и ситуации.
Нельзя раскрывать скрытое знание NPC как авторскую истину.
Нельзя заставить NPC согласиться броском, если он не может или не имеет права согласиться.
```

## 8. Режим 7. Бой, насилие, защита, физическая угроза

### Включает намерения

```text
нападать;
защищаться;
ударить;
схватить;
повалить;
удержать;
вырваться;
достать оружие для применения;
угрожать оружием;
бросить предмет как оружие;
сбежать из непосредственной угрозы;
закрыться щитом;
позвать помощь в опасности;
сдаться;
обезоружить.
```

### Когда выбирать

Если в сцене появилась прямая физическая угроза: атака, борьба, погоня, попытка удержать, оружие в применении, сопротивление вреду.

### Последовательность

```text
1. Определить, начался ли бой или это ещё социальный конфликт с риском боя.
2. Определить участников.
3. Определить, кто кого видит.
4. Определить готовность сторон.
5. Определить, кто застигнут врасплох.
6. Определить дистанцию.
7. Определить оружие и предметы в руках.
8. Проверить броню, щит, укрытие.
9. Проверить состояние тела.
10. Проверить нагрузку и занятые руки.
11. Проверить свидетелей.
12. Проверить право и последствия насилия.
13. Проверить возможность отступить, спрятаться, позвать помощь или сдаться.
14. Определить главное боевое действие хода.
15. Если действие невозможно — отказать или дать частичный результат.
16. Если действие возможно и спорно — выполнить боевую проверку.
17. Рассчитать результат, вред, состояние, позицию, шум, следы.
18. Обновить NPC reactions.
19. Обновить предметы, оружие, броню, снаряды.
20. Обновить время на короткий боевой отрезок.
21. Запустить таймеры: кровотечение, огонь, подмога, паника, слух.
22. Обновить социальные последствия: свидетели, страх, обвинение, закон, слухи.
23. Записать изменения.
24. Сформировать visible_context после боевого действия.
25. Сгенерировать prose.
```

### Жёсткие запреты

```text
Бой не является отдельной мини-игрой.
Один боевой ход — одно значимое действие.
Оружие не создаётся заявкой игрока.
Если действие невозможно по фактам сцены, бросок не назначается.
Насилие почти всегда имеет социальные последствия.
```

## 9. Режим 8. Время, ожидание, сон, работа, длительное действие

### Включает намерения

```text
ждать;
спать;
работать;
долго искать;
лечить долго;
торговаться долго;
идти долго;
ехать;
сидеть до утра;
караулить;
прятаться какое-то время;
наблюдать;
отдыхать;
есть/пить, если это занимает время;
заниматься ремеслом.
```

### Когда выбирать

Если главное в заявке — прохождение времени, длительность или ожидание события.

### Последовательность

```text
1. Определить, сколько времени намерен потратить игрок.
2. Если длительность не указана — выбрать минимально разумную длительность по действию.
3. Проверить, возможно ли действие в текущем месте.
4. Проверить безопасность ожидания/сна/работы.
5. Проверить состояние тела.
6. Проверить еду, воду, тепло, укрытие, инструменты, если релевантно.
7. Применить формулу времени: новое время = старое время + длительность действия.
8. Проверить смену части суток.
9. Обновить погоду.
10. Обновить тело: сытость, бодрость, здоровье, активные состояния.
11. Обновить NPC: кто ушёл, пришёл, заметил, изменил отношение, распространил слух.
12. Обновить место: доступность ворот, рынка, переправы, следы, опасность.
13. Проверить отложенные события и таймеры.
14. Проверить скрытые процессы.
15. Сформировать видимые последствия.
16. Записать изменения.
17. Сгенерировать новую сцену.
```

### Жёсткие запреты

```text
Нельзя не двигать время, если действие явно требует времени.
Нельзя двигать время без причины.
NPC и место не замирают, пока игрок ждёт.
Скрытые процессы могут двигаться без прямого показа игроку.
```

## 10. Режим 9. Тело, лечение, еда, сон, восстановление

### Включает намерения

```text
лечить;
перевязать;
осмотреть рану;
есть;
пить;
спать;
отдыхать;
греться;
снять усталость;
справиться с холодом;
проверить состояние тела;
помочь другому телесно.
```

### Когда выбирать

Если действие напрямую затрагивает состояние тела персонажа или NPC: здоровье, сытость, бодрость, активные состояния, раны, холод, болезнь.

### Последовательность

```text
1. Определить телесную цель: персонаж, NPC, животное, рана, холод, голод, усталость.
2. Проверить, знает ли персонаж о проблеме.
3. Проверить доступность нужных предметов: еда, вода, одежда, огонь, бинт, инструмент, лекарство.
4. Проверить место: можно ли лечить, есть, спать, греться.
5. Проверить длительность.
6. Если действие простое и ресурс есть — применить восстановление/расход.
7. Если действие спорное — выполнить проверку лечения, внимания, разума, выносливости или ремесла.
8. Обновить состояние тела.
9. Обновить активные состояния: рана, кровотечение, холод, усталость, болезнь.
10. Обновить предметы: еда потрачена, бинт использован, одежда намокла/высохла и т.п.
11. Обновить время.
12. Проверить NPC/свидетелей, если действие происходит на виду.
13. Записать изменения.
14. Сформировать visible_context.
15. Сгенерировать prose.
```

### Жёсткие запреты

```text
Лечение не отменяет рану без причины.
Еда должна существовать и быть доступной.
Сон требует времени и относительно подходящего места.
Если состояние не затронуто причиной, оно не меняется.
```

## 11. Режим 10. Скрытность, прятаться, следить, нарушение порядка

### Включает намерения

```text
прятаться;
красться;
следить;
подслушивать;
украсть;
нарушить порядок;
войти без разрешения;
открыть чужое;
обойти запрет;
сделать что-то тайно;
скрыть предмет;
соврать с риском разоблачения;
уйти незаметно.
```

### Когда выбирать

Если действие зависит от видимости, свидетелей, шума, права доступа, чужого имущества, социального риска или скрытого наблюдения.

Этот режим обычно не самостоятельный: он накладывается на предметный, социальный, перемещенческий или боевой режим.

### Последовательность

```text
1. Определить скрываемое действие.
2. Определить основной режим: движение, предмет, разговор, бой, ожидание.
3. Проверить видимость персонажа.
4. Проверить свет, шум, погоду, расстояние, укрытия.
5. Проверить NPC, свидетелей и линии зрения/слуха.
6. Проверить социальный запрет: чужая вещь, закрытая зона, порядок места, статус персонажа.
7. Проверить занятость рук, нагрузку, состояние тела.
8. Если скрытность очевидно невозможна — не назначать бросок.
9. Если исход спорный — выполнить проверку скрытности/ловкости/внимания/обычая.
10. Рассчитать, кто заметил, кто понял, кто ошибся.
11. Обновить hidden_state: подозрение, witness memory, следы, таймер реакции.
12. Обновить visible_context: показать только то, что персонаж заметил.
13. Записать последствия.
14. Сгенерировать prose без раскрытия скрытого знания NPC.
```

### Жёсткие запреты

```text
Скрытность не стирает свидетелей.
Неудача может создать след, шум, подозрение или отложенное событие.
Нельзя раскрывать игроку скрытые выводы NPC, если персонаж их не понял.
```

## 12. Режим 11. Исторический слой, слухи, память, скрытое знание

### Включает намерения

```text
вспомнить;
проверить слух;
спросить себя, что персонаж знает;
узнать о месте;
понять, куда идти;
вспомнить человека;
оценить обычай или закон;
понять историческое событие;
опознать имя, власть, род, знак, слух, маршрут.
```

### Когда выбирать

Если действие касается знания, памяти, слуха, исторической реальности или скрытой карты.

### Последовательность

```text
1. Определить topic знания.
2. Проверить character_knowledge_map.
3. Проверить, есть ли основание знания: происхождение, занятие, опыт, слух, видимое, NPC сказал, память партии.
4. Проверить, является ли знание фактом, слухом, неопределённостью или ошибочным убеждением.
5. Если знание отсутствует — не выдавать его как факт.
6. Если знание может быть получено через источник — предложить действие: спросить, искать, осмотреть, идти к ориентиру.
7. Если это исторический слой — проверить регион, год, событие, фазу и доступность знания персонажу.
8. Если это скрытая карта — не раскрывать объективную карту мира.
9. Если нужна проверка узнавания — выполнить проверку внимания/разума/обычая/профессии.
10. Обновить character_knowledge_map только при новом обоснованном знании.
11. Сформировать visible_context.
12. Сгенерировать prose с пометкой неопределённости или слуха, если знание не твёрдое.
```

### Жёсткие запреты

```text
Знание игрока не равно знанию персонажа.
Исторический якорь не гарантирует точную дорогу.
Слух не превращается в факт.
Будущее историческое событие не выдаётся как знание персонажа.
```

## 13. Режим 12. Комбинированный ход

### Включает намерения

```text
"подхожу к ларю и открываю его";
"тихо иду к двери и слушаю";
"хватаю нож и угрожаю";
"спрашиваю дорогу и пытаюсь торговаться";
"убегаю, закрываясь щитом";
"жду до темноты и потом иду".
```

### Когда выбирать

Если заявка содержит несколько действий или одно действие требует нескольких подсистем.

### Последовательность

```text
1. Разбить заявку на атомарные намерения.
2. Определить главное действие хода.
3. Определить вторичные действия.
4. Проверить, можно ли выполнить их за один ход.
5. Если нельзя — выбрать первое значимое действие и оформить остальное как намерение/следующий возможный шаг.
6. Если можно — назначить основной режим и дополнительные проверки.
7. Учесть время суммарно или по главному действию.
8. Не разрешать одному ходу бесплатно дать несколько полноценных результатов.
9. Рассчитать последствия главного действия.
10. Применить вторичные эффекты как штраф, риск, задержку, частичный результат или follow-up.
11. Зафиксировать изменения.
12. Собрать visible_context.
13. Сгенерировать prose.
```

### Жёсткие запреты

```text
Нельзя одним ходом одновременно полноценно атаковать, защищаться, бежать, вскрывать контейнер и вести переговоры.
Если действий слишком много, оркестратор выбирает главное намерение по контексту.
Остальное становится риском, штрафом, подготовкой или следующим действием.
```

## 14. Таблица диспетчеризации для оркестратора

```text
осмотреться → внимание / осмотр
искать → внимание / поиск
слушать → внимание / слух
следить → внимание + скрытность
вспоминать → знание / память / исторический слой

идти → перемещение внутри сцены или маршрут
бежать → перемещение + тело/риск; при угрозе может стать боем/погоней
двигаться по маршруту → маршрут
держать дальний курс → дальний курс

брать → предметы/имущество
использовать предмет → предметы/имущество + профиль действия
спрятать предмет → предметы + скрытность
отдать/продать/купить → предметы + социальная логика
сломать/чинить → предметы + проверка инструмента/ремесла

говорить → социальное действие
спрашивать → социальное действие + знание
торговаться → социальное действие + предметы/имущество + время
лгать → социальное действие + скрытность/риск
договариваться → социальное действие

нападать → бой
защищаться → бой
угрожать оружием → социальный конфликт с риском боя или бой, если угроза стала немедленной
схватить/удержать/вырваться → бой/борьба
сбежать из угрозы → бой + перемещение

ждать → время
спать → время + тело
работать → время + тело + предметы/место
лечить → тело/лечение + время + предметы
есть/пить → тело + предметы + время

прятаться → скрытность
нарушать порядок → социальный риск + предмет/движение/скрытность по цели действия
```

## 16. Минимальный алгоритм агента-оркестратора

```text
1. Принять player_input.
2. Сохранить raw_text.
3. Загрузить party_state и current_position.
4. Загрузить visible_context, hidden_state, character_knowledge_map и recent_changes_log.
5. Нормализовать намерение.
6. Определить primary_mode.
7. Определить secondary_modes.
8. Проверить доступность действия.
9. Если действие невозможно — сформировать безопасный отказ/частичный результат через visible_context.
10. Если возможно — запустить соответствующий режим.
11. Если нужен бросок — выполнить проверку по общей формуле.
12. Рассчитать длительность.
13. Обновить время, тело, NPC, место, предметы, события.
14. Отделить visible changes от hidden changes.
15. Сформировать write plan.
16. Провести commit gate.
17. Записать изменения.
18. Сформировать visible_context.
19. Провести аудит visible_context.
20. Сгенерировать narrator prose.
21. Провести аудит prose.
22. Показать игроку новый экран.
```

## 17. Критическое правило для всех режимов

```text
Сначала состояние партии.
Потом намерение игрока.
Потом доступность.
Потом подсистема.
Потом последствия.
Потом фиксация.
Потом visible context.
Потом проза.
```

Нельзя делать наоборот.

Особенно запрещено:

```text
сначала написать красивую прозу, а потом под неё подобрать факты;
создать предмет из заявки;
создать NPC из удобства ответа;
открыть скрытый факт без условия;
переместить персонажа без route/edge/курса;
считать слух фактом;
считать знание игрока знанием персонажа;
не двигать время при длительном действии;
двигать время без причины;
перезаписывать уже сохранённое место.
```
