# Этап 19. Формирование полного hidden state

## 1. Назначение этапа

Формирование полного `hidden_state` — это этап запуска партии, на котором система сохраняет полную внутреннюю правду стартовой сцены, не предназначенную для прямого вывода игроку.

Этот слой хранит:

* скрытые мотивы NPC;
* скрытые знания NPC;
* закрытые двери и зоны;
* замки, ключи, запреты, разрешения;
* чужие вещи и владельческие риски;
* содержимое закрытых контейнеров, если оно уже причинно определено;
* скрытые или неочевидные риски;
* текущие таймеры;
* отложенные события;
* внутренние причины поведения NPC;
* offscreen-состояние ближайших зон;
* условия раскрытия скрытой информации;
* последствия действий игрока, которые ещё не стали видимыми.

Короткая формула:

```text id="7g8hdk"
g5_scene_graph
+ initial_npc_placement
+ initial_item_placement
+ character_knowledge_map
+ time_light_consistency_audit
+ regional_context_package
+ hidden_state_policy
→ full_hidden_scene_state
```

Главное отличие:

```text id="5lnip3"
visible_context = что персонаж может воспринять
character_knowledge_map = что персонаж знает или считает
hidden_state = что система знает как внутреннюю правду сцены
```

## 2. Главное правило этапа

`hidden_state` не выводится игроку.

Нельзя напрямую переносить hidden state в:

```text id="cdw64c"
visible_scene
visible_changes
choice labels
map UI
journal text
narrator prose
NPC реплики
подсказки интерфейса
```

Hidden state может стать видимым только через разрешённый канал раскрытия:

```text id="uqt64c"
осмотр;
успешная проверка;
диалог;
наблюдение;
действие игрока;
ошибка NPC;
шум;
след;
открытие двери;
вскрытие контейнера;
свидетельство;
прошедшее время;
изменение света;
изменение погоды;
перемещение в другую точку сцены;
```

Если нет условия раскрытия, скрытый факт остаётся закрытым.

## 3. Место этапа в pipeline

```text id="kw0vp1"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит стартового места
11. Генерация персонажа
12. Аудит персонажа
13. Материализация G5-сцены
14. Аудит G5-сцены
15. Размещение стартовых NPC
16. Размещение стартовых предметов
17. Проверка времени и света
18. Формирование карты знаний персонажа
19. Формирование полного hidden state
20. Аудит hidden state
21. Формирование visible context
22. Narrator prose
```

Этап 19 идёт после карты знаний персонажа, потому что hidden state должен явно знать, какие факты нельзя раскрывать персонажу.

## 4. Что создаёт этап

Этап создаёт `full_hidden_scene_state`.

В него входят:

```text id="fcp6mk"
hidden_npc_state
hidden_access_state
hidden_property_state
hidden_container_state
hidden_item_state
hidden_risk_state
hidden_event_state
hidden_social_state
hidden_route_state
hidden_environment_state
discovery_rules
reveal_conditions
consequence_hooks
forbidden_output_rules
```

Этап не создаёт:

```text id="ql9h5e"
новые G1/G2/G3/G4/G5-узлы;
новые NPC вне уже размещённых;
новые предметы вне item placement;
новые контейнеры вне item placement;
новые социальные роли;
новые профессии;
новые исторические события;
visible_scene;
intro_prose;
player-facing подсказки;
```

## 7. Hidden state и visible context

### 7.1. Hidden state

Хранит внутреннюю правду:

```text id="zywum5"
NPC лжёт;
дверь закрыта изнутри;
у NPC есть причина избегать разговора;
в контейнере что-то есть, но игрок не знает;
предмет чужой;
у предмета есть владелец;
доступ контролирует конкретный NPC;
в темноте можно не заметить свидетеля;
после шума кто-то придёт через 3 минуты;
дорога за воротами опасна, но персонаж этого не знает;
```

### 7.2. Visible context

Показывает только воспринимаемое:

```text id="y4igby"
мужик отводит взгляд;
дверь закрыта;
ларь стоит у стены;
замок виден;
в углу темнее;
из-за двери слышен звук;
чужая вещь выглядит ухоженной;
рядом есть человек, который может заметить действие;
```

### 7.3. Character knowledge map

Показывает, что персонаж знает или считает:

```text id="n4p3ez"
персонаж знает, что чужие вещи нельзя брать;
персонаж не знает, кто владелец сундука;
персонаж слышал слух о дороге;
персонаж ошибочно считает, что дверь ведёт наружу;
```

### 8.1. Background NPC

Для фонового NPC hidden state может быть минимальным:

```text id="1gircz"
attention bias;
witness ability;
whether they will call others;
whether they can identify the character;
what makes them leave;
what makes them become scene NPC.
```

### 8.2. Scene NPC

Для сценического NPC hidden state должен хранить:

```text id="h27mxy"
private motive;
private constraint;
what they know but do not say;
reaction to player actions;
condition for trust/hostility;
memory hooks;
```

### 8.3. Key NPC

Для ключевого NPC hidden state должен хранить:

```text id="n8k6qa"
persistent motive;
memory model;
relationship state;
consequence model;
schedule hooks;
authority or property control;
future reaction triggers;
```

## 23. Алгоритм этапа

### 23.1. Проверить входы

Код проверяет:

```text id="czkr90"
g5_scene_audit.pass = true
npc_placement_audit.pass = true
item_placement_audit.pass = true
time_light_consistency_audit.pass = true
character_knowledge_map_audit.pass = true
```

Если эти gates не пройдены, hidden state формировать нельзя.

### 23.2. Собрать уже утверждённые сущности

Код передаёт LLM только:

```text id="z9cmvq"
существующие NPC;
существующие G5 anchors;
существующие предметы;
существующие контейнеры;
существующие property bindings;
существующие routes/edges;
существующую карту знаний персонажа;
существующие риски;
```

### 23.3. Определить скрытые факты

LLM создаёт скрытые факты только для уже существующих сущностей.

Допустимые типы:

```text id="w883m6"
npc_private_motive
npc_private_knowledge
npc_reaction_trigger
closed_access_truth
property_truth
container_content_truth
hidden_item_property
risk_truth
event_timer
social_rule_truth
route_truth
environment_truth
```

### 23.4. Указать condition раскрытия

Каждый скрытый факт обязан иметь:

```text id="9n9p6v"
reveal_condition_id
или discovery_rule_id
или explicit system_only flag
```

Если скрытый факт не может быть раскрыт вообще, он должен иметь:

```text id="ptl8oj"
system_only=true
reason_why_never_directly_revealed
```

### 23.5. Сформировать consequence hooks

Если скрытый факт влияет на игру, он должен иметь hook.

Пример:

```text id="1v97o1"
если игрок берёт чужую вещь → witness risk → NPC reaction
если игрок шумит у закрытой двери → NPC wakes up
если игрок ждёт 10 минут → event timer fires
если игрок вскрывает контейнер → container content materializes/reveals
```

### 23.6. Сформировать forbidden output rules

Для каждого опасного скрытого факта:

```text id="hwupk5"
private motive
closed content
future event
true ownership
hidden danger
offscreen actor
```

создаётся правило, запрещающее прямой вывод в visible/narrator.

## 24. Что LLM делает на этапе

LLM обязательна, потому что hidden state — это смысловой слой причин, мотивов, рисков и условий раскрытия.

LLM делает:

```text id="9qy1g3"
задаёт скрытые мотивы NPC;
задаёт скрытые условия доступа;
задаёт скрытую правду собственности;
задаёт скрытые последствия;
задаёт timer/event hooks;
задаёт условия раскрытия;
разделяет system truth и player-visible hints;
```

LLM не делает:

```text id="l46pm9"
не создаёт новые места;
не создаёт новых NPC;
не создаёт новые предметы;
не пишет visible scene;
не пишет narrator prose;
не меняет clock/season/weather;
не меняет character knowledge;
не раскрывает hidden state игроку.
```

## 31. Validation rules

Код обязан проверить:

1. `schema === "full_hidden_scene_state"`.
2. `version === 1`.
3. `hidden_state_status` входит в enum.
4. Каждый hidden block имеет id.
5. Каждый `npc_instance_id` существует.
6. Каждый `item_instance_id` существует.
7. Каждый `container_instance_id` существует.
8. Каждый `g5_anchor_id` существует.
9. Каждый `g5_edge_id` существует, если указан.
10. Каждый `route_id` существует, если указан.
11. Нет новых NPC.
12. Нет новых items.
13. Нет новых containers.
14. Нет новых G5 anchors.
15. Нет новых G4/G3/G2/G1.
16. Каждый hidden fact имеет `reveal_condition_ids` или `discovery_rule_ids` или `system_only=true`.
17. Каждый risk имеет trigger.
18. Каждый event имеет trigger.
19. Каждый consequence hook имеет target.
20. Каждый consequence hook имеет effect scope.
21. Closed container contents не marked visible.
22. NPC private motives не marked visible.
23. True ownership не marked visible, если character does not know.
24. Future event timers не marked visible.
25. Forbidden output rules покрывают все sensitive hidden facts.
26. Hidden state не противоречит character_knowledge_map.
27. Hidden state не противоречит time_light_consistency_audit.
28. Hidden state не противоречит item/access/property bindings.
29. Hidden state не содержит `visible_scene`.
30. Hidden state не содержит `intro_prose`.
31. Hidden state не содержит `narrator_text`.
32. `source_trace` не пустой, если require_source_trace=true.
33. `audit_self_check.evidence` не пустой.
34. Если `audit_self_check.pass=false`, concerns не пустой.

## 34. Commit gate этапа

Этап считается успешным, если:

```text id="9mf6s6"
full_hidden_scene_state валиден,
все hidden facts связаны с существующими сущностями,
нет новых NPC/items/containers/anchors/routes,
каждый hidden fact имеет reveal/discovery/system_only правило,
каждый риск и событие имеют trigger,
private NPC motives закрыты,
closed container contents закрыты,
true ownership закрыт, если персонаж этого не знает,
future timers закрыты,
forbidden_output_rules покрывают скрытые факты,
нет visible_scene/intro_prose/narrator_text,
audit pass=true.
```

Если commit gate не пройден, pipeline не должен переходить к visible context.
