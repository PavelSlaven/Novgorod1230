## M2 — единая точка save completion

- `src/game_io.cpp:734-784`: `game::save()` сразу возвращает `false` при `save_is_dirty` (:736-739); `game_save` event отправляет **до** файлов (:744); затем последовательность writers с общим fail/false (:745-762). Это не сигнал завершения.
- Успешная ветка после writers обновляет world info и save list (:763-767), пишет `.pt` (:768-772), затем возвращает `true` (:778). Место будущего sync-accept hook — **после завершённой `.pt` и до `return true`**, на игровом потоке. Приём: полная копия world/userdir согласованного набора → fsync файлов и каталогов → атомарный current/previous; при неуспехе не объявлять save принятым. Это принятое решение вердикта, native готового механизма нет.
- Тонкость: `.pt` пишется `void write_to_file` (`src/cata_utility.h:326-328`, `src/cata_utility.cpp:318-324`), который может бросить; `game::save()` ловит лишь `std::ios::failure` (:780). Перед заявлением «каждый `save()` возвращает bool и проходит приём» будущий патч должен привести `.pt` failure к явному false/видимой ошибке или проверить тип исключения. Иначе путь может завершиться исключением вне `false`.
- Путь быстрого сохранения `src/game_io.cpp:891-912`: пропуск, если ходов нет (:893-896), затем `save()` без проверки результата (:907-910). Autosave `:941-948` проверяет реальное время и вызывает quicksave. `src/do_turn.cpp:607-612` вызывает autosave по `AUTOSAVE` и modulo ходов. `src/options.cpp:1722-1737`: defaults `AUTOSAVE=true`, 50 ходов, 5 реальных минут. В штатном профиле нужен `AUTOSAVE=false` **и проверка при старте**; в просмотренных `generations.py`, `run-p1-curses.ps1` буквального `AUTOSAVE` нет. `_profile_key` только хеширует `options.json` (`generations.py:38-52`), не доказывает значение.
- Часовой hook: заменить `src/do_turn.cpp:607-612` сравнением **номера текущего игрового часа > номера последнего успешно сохранённого часа** и прямым `save()` с проверкой bool/видимой ошибкой. `calendar::turn` меняется в `src/do_turn.cpp:549`; modulo `once_every(1_hours)` при скачке времени может пропустить границу. Успешный save обновляет час, неуспех не должен ложно отмечать час сохранённым. Тест: прыжок через час и несколько часов, сон/activity, ошибка save.
- Запрос «сохранить и играть дальше» должен идти в тот же `game::save()` с видимым результатом. Native `ACTION_SAVE` в `src/handle_action.cpp:2940-2950` спрашивает «Save and quit?» и выставляет `QUIT_SAVED` только при true; это выход. `ACTION_QUICKSAVE` :2953-2955 продолжает игру, но `quicksave()` пропускает no-moves и игнорирует bool, поэтому для обещания видимого результата нужен узкий вызов `save()` или исправление общей ветки.
- Native уровень файла: `src/mapsharing.cpp:110-171` открывает temp, flush+close и rename **одного** файла (:145-165); fsync файла/директории и атомарного набора здесь нет. `src/filesystem.cpp:177-186` повторяет filesystem rename до 3 раз и возвращает bool; это тоже один path. `src/cata_utility.cpp:288-330` оборачивает per-file запись/ошибку. Принятый gap current/previous этим не закрыт; не создавать второй писатель на каждый ход.
- Future checks: число вызовов `save()` = число попыток приёма; dirty/false/`.pt` failure не меняют current; сбой посреди копии сохраняет previous; `AUTOSAVE=false` реально прочитан из game profile; request/час/ACTION_SAVE идут через один completion; время `calendar::turn` и реальное время в metadata, видимый recovery moment; бюджеты ≤5 с save с копией+fsync. В плане тест autosave collision переименовать в «нет `save()` мимо приёма».
