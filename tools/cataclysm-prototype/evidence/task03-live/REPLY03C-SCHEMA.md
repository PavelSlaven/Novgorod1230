# reply03c: адресат native-речи, read-only

HEAD `dd98d4674`. Вердикт: **STOP**. Уже предусмотренного схемой поля для выбранного native NPC между вводом и `emit_interaction.target_actor_refs` нет. При запрете добавлять поле во вход и обходить через текст/отдельный канал выбранный адресат не может дойти до этой операции.

- Native owner `novgorod_semantic.cpp:695-709` принимает единственную строку `intent` через `string_input_popup`; `:625-636` формирует frame `{type,id,intent,observation}`. `write_observation` (`:134-215`) выдаёт `actors[]` со `actor_ref`, `visible`, `actor_id`, `position` (`:143-160`), затем items/targets; выбора там нет. Native список NPC — факты видимости, не адресат.
- Socket owner `p3-live-coordinator.mjs:47-58` принимает только `message.intent` и `message.observation`, передаёт их `runP3TurnStep`; `p3-live-socket.js:4-17` проверяет observation и клонирует его, но не определяет selection. `p3-boundary.js:655-661,737-748` переносит текст в `rootPlayerAction`, наблюдение в projection и всех видимых NPC в `player_safe_state.visible_entities`.
- Канонический `TURN_STEP_REQUEST_V1_SCHEMA` (`packages/turn/src/turn-step-contracts/request-schema.js:27-57`) содержит `root_player_action`/`remaining_intent` как строки, `actor` и `player_safe_state` как общие JSON-объекты. Их открытый тип технически допускает дополнительные ключи, но существующего **семантически определённого** ключа native-selection нет. Добавление ключа туда тоже было бы новым входным полем. Контракт требует полный видимый набор (`turn_step_llm_contract.md:316-340`); удалять из `actors` других NPC ради кодирования выбора нельзя.
- Канонический `TURN_STEP_PLAN_V1_SCHEMA` (`plan-schema.js:80-109`) допускает direct `player_utterance`, где `utterance` содержит строго `speaker_ref`, `utterance_text`, `input_mode`, `delivery`, без адресата; контракт `turn_step_llm_contract.md:444-459` прямо отличает `delivery` от audience. Сам `emit_interaction.target_actor_refs` существует в `plan-schema.js:64` и контракте `turn_step_llm_contract.md:1217-1227`, но это **выходная операция**, а не слот входа. В текущем direct speech `p3-boundary.js:714-734` собирает его из **всех** видимых NPC. Native mapping `:641-650` использует refs лишь после этого, в `references.actors` исходящего operation envelope.
- После native readback coordinator вызывает NPC reply по факту речи (`p3-live-coordinator.mjs:59-64`); ни выбранный ref, ни сама исходная операция туда не передаются. Поэтому поздняя фильтрация слышавших не восстанавливает адресата.

Проверен вариант выбора **только в native при apply**, без поля initial frame. К моменту `apply_operation` JS уже отправил `p3_native_operation_request_v1`: `p3-boundary.js:641-650,861-891` превращает `emit_interaction.target_actor_refs` в `request.references.actors`; у direct speech этот список пока содержит всех видимых. В native `novgorod_semantic.cpp:356-380,439-457` `speak` читает `args.utterance`, вызывает `sounds::sound` и не использует `references.actors`. Локальный выбор может изменить native действие, но существующий readback (`novgorod_semantic.cpp:514-544`) возвращает `native_effect.{speakerId,utterance,actualHeardListenerIds}`; `actualHeardListenerIds` — фактически услышавшие, включая свидетелей, не intended addressee. `validateP3Readback` (`p3-boundary.js:905-933`) не восстанавливает выбранного. `runP3NativeNpcReply` (`p3-boundary.js:414-426`) ищет первого видимого среди heard. Следовательно, выбранный при apply NPC не попадёт обратно в **уже созданный** `emit_interaction.target_actor_refs` и не дойдёт до response boundary без нового поля readback/observation или переопределения смысла `actualHeardListenerIds`. Оба обхода запрещены условием и нарушили бы различие адресата/свидетеля (`npc_conversation_mode_contract.md:1035-1044,1083-1089,1140-1152`).

Минимальное изменение для согласования: разрешить явный `target_actor_ref` (или эквивалентное одноэлементное `target_actor_refs`) **в native intent frame**; native выбор сверяет ID с видимым NPC, coordinator сохраняет его в пределах intent и `runP3TurnStep` использует при создании уже существующего `emit_interaction.target_actor_refs`. Отсутствие выбора означает обычную речь без NPC response. Это новое поле входа; при нынешнем запрете работа блокирована. Нужен ответ распорядителя: разрешить именно такое изменение входного протокола либо отказаться от native выбора в этом срезе. Не предлагать маскировку ID в строке intent, сужение observation или второй канал.
