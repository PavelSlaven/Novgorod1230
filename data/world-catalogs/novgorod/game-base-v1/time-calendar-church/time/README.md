# time — календарь 1230–1250 и распорядки (candidate)

Все таблицы генерируют `scripts/build_calendar.py` и `scripts/build_schedules.py`;
проверяют `scripts/check_calendar.py` и `scripts/check_schedules.py`. Руками не править.

```
cd scripts
python paschalia.py --json ../paschalia_1230_1250.json   # 1. пасхалия (движимые даты)
python build_calendar.py                                  # 2. calendar_1230_1250.csv
python check_calendar.py                                  # 3. проверка
python build_schedules.py                                 # 4. schedules_routines.csv
python check_schedules.py                                 # 5. проверка
```

## calendar_1230_1250.csv — 363 строки

Юлианский календарь, 1230–1250. Поля: `cal_id, date_or_rule, year, kind
(feast|fast|fast_exception|belief|market|work_season|event), name_ru, effects,
computation_ref, source_refs, confidence, status, note`.

### Пасхалия (движимые даты) — скрипт, не руками

`scripts/paschalia.py` вычисляет дату Пасхи (юлианский календарь) по формуле
Гаусса, засвидетельствованной источником:

> book:356156 (Леонтьева, Кобрин, Шорин, «Вспомогательные исторические
> дисциплины», 2009) §Глава 6. Хронология ¶1328–1333, confidence B.

Результат перепроверен независимым алгоритмом (Meeus, *Astronomical
Algorithms*, гл. 8, «Julian Easter»); скрипт падает с `AssertionError`, если
две формулы расходятся хоть для одного года 1230–1250. Совпали для всех 21
года (проверено `check_calendar.py`).

От Пасхи выведены день-в-день (простая юлианская арифметика дат, без внешних
библиотек): Масленица (−55), Великий пост/Чистый понедельник (−48), Вербное
воскресенье (−7), Страстная седмица (−3..−1), Пасха (0), Фомина неделя/
Антипасха (+7), Радуница (+9), Вознесение (+39), Троица (+49), Неделя Всех
святых (+56), начало Петрова поста (+57, понедельник после Всех святых).
Конец Петрова поста — фиксированная дата 28 июня (канун Петрова дня); длина
поста (1–6 недель) посчитана скриптом отдельно на каждый год и записана в
`note` соответствующей строки — совпадает с оговоркой источника
(book:122328 ¶3714), что длина «варьируется».

### Неподвижные праздники, посты, сплошные недели

Список неподвижных праздников — `book:356156 ¶1321`; Успенский (1–15 авг.) и
Филиппов/Рождественский (15 ноя. – 24 дек.) посты — `¶1322` (источник сам
оговаривает: сроки «по позднейшему уставу», для XIII в. могли отличаться —
перенесено в `note`, не скрыто). Еженедельный пост среда/пятница и четыре
сплошные недели (Святки, Масленица, Светлая, Троицкая) — по `book:356156` и
`book:122328` (Рыбаков, «Язычество Древней Руси», 1987, доказательство спора
о постах в среду/пятницу в XII в.).

### Народно-аграрный календарь и торговые/промысловые сезоны

Купала (24 июня), Ильин день (20 июля), Спас/зажинки (6–7 авг.), Покров
(1 окт.), Никольщина (6 дек.), Радуница, русальная неделя, коляда 1 марта —
все `book:122328`, часть помечена confidence C там, где источник сам
маркирует гипотезу («по всей вероятности», «Рыбаков предполагает»
— торговый день пятница). Годовой цикл труда (пахота, сев, сенокос, жатва,
молотьба, ледоход/ледостав, путина, пушной промысел) — confidence C,
regional analogy: ни один источник в этой сессии не дал точных календарных
дат по годам 1230–1250 для этих работ (только типичные окна по аналогии с
позднейшим народным календарём); это зафиксировано как gap, а не выдумано.

### Событие 1230 г. — только привязка, без дублирования

`cal_event_famine_1230_frost` — календарная привязка мороза 14.09.1230,
cross-ref на `food-drink/dishes/famine_1230.csv#fam_frost_1230` (confidence A,
НПЛ), а не повтор данных о ценах/голоде.

## schedules_routines.csv — 16 строк

Поля: `sch_id, role_or_occupation_ref, day_type, season, time_blocks
[{segment, activity_ref}], place_access_ref, source_refs, confidence, status, note`.

### Известный и зафиксированный (не скрытый) разрыв источника

`main:data/novgorod-region/novgorod_occupations_v1_enriched.tsv`, столбцы
`daily_schedule_*` и `night_behavior` — **скрипт проверил и подтвердил**, что
это **один и тот же текст, буквально повторённый во всех 68 occupation_id**
(assert в `build_schedules.py`, независимо перепроверен в `check_schedules.py`).
Это не распорядок по роли, как требует бриф (`role_or_occupation_ref` в
key_fields), а незаполненный шаблон. Взято как единственная имеющаяся
базовая линия (`generic_occupation_template`), с явной пометкой gap; реальная
дифференциация по занятиям (ремесленник vs купец vs клир vs крестьянин) —
задача следующего прохода (M3, наполнение схемы, не этого сборщика).

Текст качественный (утро/день/вечер/ночь), не в часах — поэтому буквальную
проверку «блоки покрывают 24 ч без перекрытий» из акцептанса выполнить
нельзя; вместо неё `check_schedules.py` проверяет покрытие всех четырёх
качественных сегментов там, где текст источника их реально даёт (`normal`,
`winter`, `summer`, `autumn`, `market_day`), и честно пропускает `church_day`
(в тексте источника нет клаузулы «ночь») и `crisis` (текст вообще не делится
по частям суток — описывает нарушение обычного распорядка, а не расписание).

### schedule_adaptation_rules — 4 строки

`Одним ПРОМТОМ/data/rus13-base-staging/nov_region_audit/novgorod_status_rules_v1.json#schedule_adaptation_rules`
— каждое правило помечено `status: approved` внутри файла с
`metadata.status: draft` (это сохранено в `note`, а не скрыто).

### Ссылки на approved temporal-v4 (не копии)

`sch_place_monastic_refectory`, `sch_npc_monastic_worker`,
`sch_npc_reaction_signal_policy` — ссылки на уже approved записи

## Известные пробелы (не закрыты этим проходом)

- Нет по-настоящему разных распорядков по occupation_id/роли — источник
  генерический (см. выше).
- Годовой аграрный/промысловый/навигационный цикл — только качественные
  окна confidence C, без точных дат по годам.
- `region_id`/universal-флаг (critic_problems #1) не добавлен в этот проход;
  весь календарь и распорядки считаются applicability=novgorod, как и
  approved temporal-v4 записи, на которые они ссылаются.
