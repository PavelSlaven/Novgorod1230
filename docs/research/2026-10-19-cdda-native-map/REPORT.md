# Карта родных механизмов CDDA (PR #778)
> Движок: CDDA.
> Даты: 2026-10-19 — 2026-10-19.
> Источник отчёта: codex-direct/cdda-map-pr-report.md

## Вопрос

Как опубликовать в репозитории карту родных механизмов CDDA, чтобы исполнители могли находить готовые механизмы перед разработкой своих?

## Метод

В исходном отчёте описана работа в отдельной ветке и worktree от снимка upstream Cataclysm-DDA. Карту разделили по областям, снабдили индексом и таблицей соответствий «нужда → родное»; индекс указывает пин снимка, а строки кода в областях относятся к этому пину. Карту представили как навигацию, а не как нормативный документ. ([source-report.md](source-report.md):3-8; [индекс карты](../../context/cdda-native-map/INDEX.md):3,5,9-11)

Сводную таблицу собирает генератор из таблиц областей. В исходном PR-отчёте перечислены добавление генератора и теста, ссылка из docs README и строка CHANGELOG. ([source-report.md](source-report.md):5-16; [индекс карты](../../context/cdda-native-map/INDEX.md):13-29)

## Ход

Карта и страницы областей были добавлены первым коммитом; затем добавлены генератор таблицы с тестом, ссылка из README и запись в CHANGELOG. После проверки генератором таблицу пересобрали; исходный отчёт отмечает изменение одной строки, связанной с сохранением состояния. ([source-report.md](source-report.md):5-9,27-32)

## Выводы

Индекс формулирует подход «сначала готовое CDDA, при необходимости расширять его, новое создавать при отсутствии родного механизма» и отдельно указывает, что карта служит навигацией, а не нормой. ([индекс карты](../../context/cdda-native-map/INDEX.md):3)

## Решения владельца

D14: Код назначает предмету владельца из соответствующей группы; находка в дикой местности остаётся бесхозной либо помечается как потерянная кем-то без выдуманного владельца. Владение сохраняется, владелец и знающие о предмете люди помнят о нём, а код определяет при восприятии, узнаёт ли персонаж предмет; реакция NPC и правовые последствия обрабатываются своими системами. Текст также утверждает режим тёплого preload host «А+Б» и задаёт для него время запуска и восстановления.
