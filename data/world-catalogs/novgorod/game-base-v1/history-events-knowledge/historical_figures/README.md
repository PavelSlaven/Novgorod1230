# historical_figures — исторические лица (authority-записи)

Домен брифа `historical_figures`, приоритет M3. Статус: **candidate**, не утверждено.
Правило владельца (#133): LLM не выдумывает исторических лиц — только код/кодифицированный список выбирает
из готовых authority-записей. Эта таблица — материал для такого списка, не runtime-код.

## Что это

`figures.csv` (23 строки): князья, посадники, тысяцкие, архиепископы и участники политического кризиса 1230
года плюс внешние акторы (хан, ярл, епископ, орденский магистр, литовский князь), релевантные Новгороду
1230–1250. Обновлено в проходе исправлений 2026-09-26 — см. `../VERIFICATION.md`, раздел
«Исправления 2026-09-26», за построчным перечнем.

## Источники и метод

1. **14 строк — `sqlite novgorod_1230(1).persons_1230`** (confidence **A**, источник S01 = НПЛ, Насонов
   1950/Michell&Forbes 1914). Это первичный, летописно засвидетельствованный набор: князь Михаил
   Всеволодович Черниговский, его сын Ростислав, приглашённый князь Ярослав Всеволодович и его сыновья Фёдор
   и Александр (будущий Невский), архиепископ Спиридон, посадники Внезд Водовик и Степан Твердиславич,
   тысяцкий Микита Петрилович, и пятеро участников уличного конфликта 1230 г. (Иван Тимошкинич, Волос
   Блудкинич, Семён Борисович, Прокша, иконописец Станила).
   `office_start/office_end` парсятся скриптом из текста `period_1230` (регэксп на «с/до DD месяца YYYY»,
   с 2026-09-26 также «с/до месяц YYYY» без дня); там, где точного дня нет ни в `period_1230`, ни в более
   точных источниках, окно оставлено на весь 1230 год (не выдуман точный день). Для 6 строк (R01, R03, R04,
   R05, R08, R09) окно 2026-09-26 скорректировано ссылками на sqlite `events` (confidence A) и на книжные
   свидетельства группы (`servak history-events-knowledge.csv`) вместо придуманных точных дат или неверно
   расширенных черновиком окон — см. `note` каждой строки и `VERIFICATION.md`.
2. **7 строк — черновик `rus13tpl novgorod_key_npc_seeds_v1.json`** (`historical_key_npc_profiles`,
   `requires_human_historical_audit: true`). Это фигуры, которые sqlite-таблица не покрывает (она даёт только
   срез 1230 года): архиепископ Далмат (1249–1250), Батый, Биргер Магнуссон, Герман фон Буксгевден
   (Дерптский), Андреас фон Вельвен, Миндовг. Confidence **C** (кроме одного исключения ниже).
   Пять профилей черновика, совпадающих с людьми из sqlite (Ярослав, Фёдор, Александр, Спиридон, Степан
   Твердиславич), **не продублированы** — они только расширили окно `office_end` sqlite-строки до годов,
   которые называет черновик (см. `note`), кроме случаев 2026-09-26, где окно уже исправлено книжной ссылкой
   (Ярослав, Степан) — там черновичное расширение не применяется повторно.
   `source_refs` этих 7 строк с 2026-09-26 честно говорит «не найдено постраничной цитаты в книжных
   свидетельствах группы» вместо прежней общей фразы, которая выглядела как ссылка, но ей не была; для
   Батыя добавлены конкретные книжные цитаты по датам, которые нашлись (взятие Владимира 1238, ярлык
   Ярославу 1243). Биргер Магнуссон и Батый также содержательно исправлены (см. следующий раздел).
3. **2 строки — добавлены 2026-09-26 из книжных свидетельств группы**, не покрытые ни sqlite, ни
   черновиком: тысяцкий Борис (Негочевич), предшественник Микиты Петриловича (бежал с Водовиком в Чернигов
   8 дек. 1230), и архиепископ Антоний — уже «на покое» к 1230 г., умер 8 окт. 1232. Оба — confidence **B**
   с постраничными книжными ссылками (не выдуманы: см. `VERIFICATION.md`).

## Исправленные анахронизмы и неверные окна (2026-09-26)

- **Биргер Магнуссон**: строка называла его «шведским ярлом» на 1240 г. — анахронизм, ярлом он стал не
  ранее 1248 г. `office` переформулирован («шведский полководец, титул ярла — не ранее 1248»), участие в
  Невской битве 1240 г. осталось помеченным как спорное (черновик сам это отмечает).
- **Батый**: окно 1237–1243 подразумевало конец правления в 1243 г., хотя ханом он оставался значительно
  дольше (традиционно до ~1255/56, но точная дата смерти не подтверждена книжными свидетельствами этой
  группы в этом проходе). `office_end` очищен (не заполнен придуманной датой).
- **Степан Твердиславич**: `office_end` 1240-12-31 (артефакт парсинга черновичного «1240-е») исправлен на
  дату смерти в должности — 1243-08-16 (книжные свидетельства).
- **Ярослав Всеволодович**: `office_end` 1246-12-31 (год смерти, ошибочно взятый как конец новгородского
  княжения) исправлен на 1236-12-31 — согласовано с окном новгородского княжения в
  `polities_external_relations` этой же группы.
- **Фёдор и Александр Ярославичи**: `office_start` 1230-01-01 исправлен на 1231-01-01 (книжные
  свидетельства датируют прибытие княжичей-наместников январём 1231, а не «концом 1230» из
  `period_1230`); `office_end` Фёдора сужен с 1233-12-31 до точной даты смерти 1233-06-10.
- **Михаил Всеволодович Черниговский**: `office_end` 1230-06-30 раньше стоял без оговорки, как если бы это
  была установленная дата; теперь явно помечен как верхняя граница диапазона sqlite-события «1230-05/06»
  (confidence A), а не утверждённый точный день.
- **Далмат**: `office_start` 1249-01-01 остался тем же годовым размещением, но теперь с явной оговоркой в
  `note`, что точный месяц перехода не установлен (это не новая находка — уже упоминалось в разделе
  «Известный конфликт данных», но раньше не было явной пометки в самой строке).

## Известный конфликт данных (не исправлен самостоятельно)

`hf_draft_hist_npc_mikhail_stepanich` («Михаил Степанич», посадник, 1230–1250 по черновику) **перекрывает**
летописно засвидетельствованных посадников Внезда Водовика (до 1230-12-08) и Степана Твердиславича
(с 1230-12-09), confidence A. По стандартной хронологии новгородского посадничества (см. С22 «Новгородские
тысяцкие в XIII в.» и общий корпус работ по новгородскому посадничеству, использованный при составлении
черновика rus13tpl) отдельного «Михаила Степанича» в этом окне обычно не выделяют — сам черновик уже
помечает эту фигуру «использовать осторожно», «требуется ручная проверка». Строка **сохранена**, но с
`confidence=D` и `status=candidate-conflict`, а не тихо удалена или тихо исправлена — решение (удалить или
переатрибутировать) остаётся за владельцем/старшей моделью.

## Проверка (`scripts/validate_figures.cjs`)

- Все 23 строки имеют непустой `source_refs` (0 пропусков).
- Проверка «сроки одной и той же должности не перекрываются» (acceptance-критерий брифа) по бакетам
  посадник/архиепископ/тысяцкий/новгородский-князь: **3 перекрытия** (было 5 до исправления
  2026-09-26 — 2 устранены реальными датами: Михаил/Ярослав по sqlite-событию, Микита/Борис по дате
  передела власти), из них:
  - Спиридон/Далмат на 1249 г. — переходный год, точный месяц смены владыки не в источниках этого прохода
    (не ошибка данных, а недостающая точность даты — зафиксировано, не исправлено выдумкой);
  - 2 перекрытия — оба от того же конфликта «Михаил Степанич» (см. выше), уже помечены `candidate-conflict`.
  Внешние акторы (Батый, Биргер, Герман, Андреас, Миндовг) не Новгородские официалы — исключены из проверки
  «того же офиса» отдельным фильтром в `validate_figures.cjs` (иначе «литовский князь» ложно попадал в
  бакет «новгородский князь»); архиепископ «на покое» (Антоний) с 2026-09-26 также исключён отдельным
  фильтром, иначе его вычисленное окно ложно перекрывалось бы с действующим Спиридоном.

## Известные ограничения

- `office_start/office_end` для лиц без точной даты в источнике — годовое окно (`YYYY-01-01`..`YYYY-12-31`),
  не точная дата. Это осознанная грубость, а не потерянная точность: `period_note` хранит исходный текст.
- 5 draft-строк (Далмат, Герман, Андреас, Миндовг и Батый частично) не имеют постраничной научной цитаты
  в книжных свидетельствах группы (только заголовок черновика + пояснение) — помечено `confidence=C`,
  кроме конфликтной строки (`D`). Уточнение точных дат должностей (архиепископы, посадники после Степана)
  в этом проходе не проводилось — реальный остаточный пробел для follow-up.
- `event_refs` оставлено пустым во всех строках — связь figure↔event (`historical_events/event_phases.csv`)
  не резолвлена скриптом в этом проходе (можно восстановить по совпадению имени/года, не сделано здесь).
- Книжная запись `book:566839 §Глава II Русь и Ливония ¶661` («бывший посадник (1219) убит 9 дек. 1230»)
  упоминает лицо по имени Борис, но не отождествлена в этой таблице с тысяцким Борисом (Негочевичем,
  `hf_book_boris_negochevich`) — сходство имени и даты недостаточно, чтобы приписать ему чужую смерть без
  прямого подтверждения; помечено в `note` этой строки, не разрешено самостоятельно.

## Пересборка

```
node scripts/build_figures.cjs <sqlite_dump.json> <novgorod_status_rules_v1.json> . [<book_evidence.csv>]
node scripts/validate_figures.cjs .
```
Скрипты — `.cjs` (не `.js`): корневой `package.json` репозитория задаёт `"type": "module"`, а эти скрипты
используют `require()` (переименовано 2026-09-26, было причиной `ReferenceError: require is not defined`
при запуске команд README «как есть»).

### Экспорт `sqlite_dump.json`

```
python -c "
import sqlite3, json, io
con = sqlite3.connect(r'C:\Users\Slaven\Downloads\novgorod_1230(1) (1).sqlite')
con.row_factory = sqlite3.Row
cur = con.cursor()
out = {}
for t in ['metadata','sources','confidence','territories','settlements','ends','streets','city_features',
          'institutions','persons_1230','events','economy','famine_prices','law','social_groups',
          'material_culture','birchbark_selection']:
    cur.execute(f'select * from {t}')
    out[t] = [dict(r) for r in cur.fetchall()]
with io.open('sqlite_dump.json', 'w', encoding='utf-8') as f:
    json.dump(out, f, ensure_ascii=False, indent=1)
"
```
