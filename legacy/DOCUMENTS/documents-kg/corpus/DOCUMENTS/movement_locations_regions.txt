# Перемещение, локации и регионы

## Статус и граница миграции

Этот документ фиксирует **target materialization v3**. Принятое историческое
P28 evidence не активировало runtime. До отдельного `versioned production
activation cutover` единственным active production path остаётся
materialization v2. Документ не разрешает частичную активацию, dual write,
v3→v2 fallback или использование target-контрактов production runtime.

Temporal duration и interruption дополнительно регулирует active target-норматив
`temporal_world_and_interruptible_activities.md`. Movement владеет только
sealed segment/method/environment inputs и progress proposal; exact rational
arithmetic, timestamp comparison и boundary ordering принадлежат
`@rus/time-events-history`. Traversal interval не округляет duration и не
использует gameplay `TIMESTAMPTZ`.

После `versioned production activation cutover` пространственная модель:
canonical G0–G5 в `world_base`; party G5 overlay/generated G5, G6 и
`scene_position` — в `party_runtime`. G7/G8 не вводятся. Factual topology,
знание персонажа и player projection — независимые слои.

## 1. Авторитетное положение и носители

Положение не выводится из UI-координат и не хранится как generic `current_position`. Единственный factual source — versioned `movement_endpoint_ref` и снимок позиции владельца путешествия.

```text
movement_endpoint_ref = scene_position
                      | site_connection_endpoint
                      | world_route_endpoint
                      | transit_anchor
                      | route_anchor_scene
                      | stranded_state
```

`stranded_state` допускается только источником утверждённого rescue/repair/migration plan, никогда обычной целью. У attached субъекта world location производна от carrier attachment; у него не может быть второй root world location. Фактическая топология не заменяется предполагаемым игроком направлением или известным ему названием.

## 2. Топология и сегменты

G4 владеет traversal profile, directional exits и expansion profile. Route topology authored явно: route состоит из одной конечной непрерывной цепочки ordered physical segments с versioned source/target endpoint binding. Site connection не пересекает G4; world traversal проходит ровно один physical segment за один `timed_traversal` step. Несколько допустимых выходов — options, а не ambiguity.

Каждый segment имеет pinned factual context, orientation, environment, approved method/cost и recheck contract. Переход G-ancestor, boundary или смена context не создаёт времени сам по себе. Boundary crossing требует matched exact contract; layout не создаёт topology.

## 3. Path query и готовность

Path query получает journey owner/scope, factual start endpoint, ровно один `target_request` **или** `intended_direction_id`, knowledge scope, capability context и expected state versions. Игровое знание не подменяет factual ID: resolver отдельно pin-ит factual resolution.

```text
mechanical_readiness = ready | requires_frontier_resolution
                     | requires_preparation | temporarily_blocked | data_gap
knowledge_visibility = visible | hidden | misidentified
```

Только `ready` option с непустыми steps executable. `requires_frontier_resolution` возвращает topology proposal; `requires_preparation` — preparation proposal. Их commit не меняет старый option, не перемещает носитель и не продвигает время; затем выполняется новая path query. Empty candidate set, missing route/endpoint/context/cost или неоднозначный mandatory binding — typed hard block, без nearest/first-row/semantic fallback.

## 4. Неизменяемые планы

Ready option становится `party_route_plan` только после resolution endpoint refs, полной dependency pinning, capability checks, completed preparation и canonical digest validation. План хранит owner, scope, source snapshot, original target/direction, factual resolution, ordered steps и static dependency pins. Payload/steps immutable; lifecycle только `ready|superseded|retired`.

```text
world_travel  = root world location или segment progress
carrier_local = действие/сцена внутри attached carrier; без world-route traversal
```

Смена root/attached ownership или scope завершает текущий план на exact handoff endpoint; продолжение начинается отдельным plan/execution. Нельзя незаметно заменить corridor/segment, carrier или method в уже выбранном плане.

## 5. Исполнение движения

`party_route_plan_execution` — единственная mutable journey-state строка; history и events append-only. Статусы: `planned`, `active`, `waiting_at_anchor`, `suspended_at_scene`, `stranded_in_transit`, `completed`, `aborted`, `superseded`.

Step kinds строго разделены:

- `immediate_action`: action cost, без segment progress и game time;
- `timed_activity`: тратит время, но не продвигает physical segment;
- `timed_traversal`: progress ровно одного physical segment.

Traversal start валидирует exact departure endpoint, pinned segment/context, carrier, capability, method и readiness. Block до старта не создаёт travel state. Interval атомарно: snapshot → deterministic checks → один terminal outcome → append-only result/time/progress/consequences. Допустимы только `progressed`, `segment_completed`, `paused_in_transit`, `interrupted_at_anchor`, `stranded`, `blocked_before_progress`.

При завершении segment носитель ставится на exact arrival endpoint; смена route-point context выполняется в pinned phase и имеет нулевую собственную стоимость. Interruption требует approved anchor; иначе результат — `stranded`. В stranded нет teleport, nearest endpoint или обычного движения.

## 6. Разделение ответственности

Resolver/materializer/validator возвращают proposals и reports. Единственный commit component валидирует approved write set и атомарно применяет его; он не выбирает альтернативу. Movement не создаёт semantic data: topology/frontier resolution и target preparation — явные отдельные команды перед plan activation. LLM не создаёт маршрут, endpoint или factual topology.

## 7. Traceability

Target источники: `spatial_architecture_standard_g0_g6.md` §§4, 8–10, 11. До
`versioned production activation cutover` active v2 остаётся sole production
owner; v3 runtime-заявка не читает и не пишет v2 fallback.
