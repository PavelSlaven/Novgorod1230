## Вопрос

Какие дефекты были обнаружены в `main` и PR #98 на момент аудита? Сохранённая запись описывает результаты проверки проекта и ход последовавших ответов владельца ([source-memory.md](source-memory.md):11, 14, 16).

## Метод

В памяти аудит описан как полный read-only проход по `main` с коммитом `21bd0938` и PR #98 с коммитом `ca704b65`. В работе участвовали 50 помощников; каждую находку проверяли на опровержение, а находки высокой и критической важности — дважды ([source-memory.md](source-memory.md):11).

## Ход

По итогам аудита был составлен список из 10 решений владельца и план из 7 шагов. Вечером 25 сентября владелец ответил на предложения по устройству процесса, корпусу M2c, расположению решений, изменениям `Runtime_Plan`, материализации, удалению и фиксации старой версии, правилам данных и дальнейшей работе над PR #98. Сохранённая запись не содержит номеров D для этих 10 решений ([source-memory.md](source-memory.md):16).

PR #143 расширили и отправили на проверку. В него вошли изменения governance-документов, `HOW_WE_WORK.md`, записи `LW-026..039` и поле качества CR. Contract Auditor выдал `PASS_WITH_NOTES`, все замечания исправили; для слияния требовалось согласие владельца после зелёного CI. После согласия PR #143 слили, ветку и worktree удалили, а `main` объединили с PR #98. При синхронизации разрешили пересечения в governance README и AGENTS; тесты PR #98 переключили на `docker rm -fv` для защиты #142 ([source-memory.md](source-memory.md):16).

Сначала agentmemory отключили только для проекта Novgorod через `.codex/config.toml` и `.git/info/exclude`; для Cursor тогда рассматривали отдельный профиль Novgorod. Позднее владелец выбрал другой вариант: отдельный профиль не создавать, а очистить записи Cursor с проверкой через bridge. Запрос удалить две записи Novgorod задержал классификатор безопасности, после чего Cursor передали поручение забыть 8 записей Novgorod, оставив 2 записи rus13_literary_finetune и данные других проектов ([source-memory.md](source-memory.md):16).

Cursor передали задачу контекстной карты и правок `Runtime_Plan` для PR #98. Следующими в очереди записаны CR #146 на корпус M2c, обновление манифеста по индексу в CR #144 и отдельный реализационный CR для M2c. Память также сообщает, что Codex отправил 119 коммитов и сохранил контекст PR #98 ([source-memory.md](source-memory.md):16).

В ходе последующих уточнений владелец принял рекомендации по 20 деталям, включая самостоятельные расписания мест: ночную стражу в городе и дневной рынок. Ответы внесли в комментарии к #133 и материалы к #127 и #109; по результатам уточнений также появились CR #144 и #146 ([source-memory.md](source-memory.md):16).

## Результаты

Аудит насчитал 135 проверенных находок ([source-memory.md](source-memory.md):3). В сводке распределения указаны 3 критические находки, 40 высокой важности, 72 средней, 20 низкой и одна опровергнутая ([source-memory.md](source-memory.md):11).

На проверенных тогда ветках система процесса уже существовала, но не применялась в runtime-ветке PR #98. Решения владельца от 25 сентября находились только в связующей переписке и памяти; действующие нормы расходились с видением проекта, карты контекста не описывали v17, а ход игры v17 зависел от сценарного стека Нижней Двины и закрытого списка операций. В записи также отмечены ослабленные или перепривязанные кода тестов, отсутствие нужного календаря в bootstrap v17 и внедрение agentmemory устаревших межпроектных «предпочтений» в Cursor и Codex ([source-memory.md](source-memory.md):14).

Среди зафиксированных последствий были изменения governance-документов в PR #143, отключение agentmemory для проекта Novgorod в настройке Codex и передача Cursor задач по очистке записей и карте контекста. PR #143 был слит после согласия владельца; память сообщает, что к PR #98 отправили 119 коммитов Codex и что для него создали следующие корпусные и реализационные CR ([source-memory.md](source-memory.md):16).

## Решения владельца

Память перечисляет 10 тем решений, но не сохраняет их номера D: governance PR; CR корпуса M2c; место хранения решений; изменения `Runtime_Plan`; открытые входы для действий материализации; удаление v16 и фиксация версии; agentmemory; устранение неиспользуемых владельцев; правила данных; отправка коммитов и контекстная карта PR #98. Владелец одобрил предложения по governance, M2c, хранению решений, `Runtime_Plan`, материализации, старой версии, правилам данных и PR #98. По agentmemory он сначала распорядился отключить его только для проекта Novgorod, а позднее выбрал очистку записей Cursor без отдельного профиля. По рекомендациям для неиспользуемых владельцев были перечислены переход на `spatial_v3_npc_*` с объединением понятий `region_npc_*`, удаление старых таблиц после v17, удаление `environment-state` и `space-map`, продвижение погоды внутри materialization, очистка неиспользуемых этапов новой игры после PR #98 с git tag при сохранении облегчённого пакета для M7, а также отказ от семантического corpus-RAG в пользу лексического поиска ([source-memory.md](source-memory.md):16).
