# Стартовая территория: land-use и place types — кандидатный пакет

**Статус:** `candidate`, не approval, не import/activation и не runtime readback. Утверждает Opus/data owner.
**Scope:** 32 G4 и 195 canonical G5 низовьев Северной Двины (Вихтуй/Заостровье).

## Состав

- `matrix.csv` — 70 типов из закреплённого regional PF inventory: 31 land-use + 39 place; причинная оценка, региональный selector status, PF links, точные G4/G5 candidate refs или gap, manifestation и источники.
- `candidates.csv` — 39 типов с условной/правдоподобной причинной применимостью. G4/G5 IDs машинно выделены в отдельных столбцах. Все refs — кандидаты; `scope_evidence_class=context_only_no_type_or_pf_binding` означает только географический контекст, без PF/type binding. `candidate_compatibility_exceptions` хранит только адресные пары узел/измерение с причиной и source refs.
- `typed-gaps.csv` — оставшиеся 31: 21 «нет точного основания» и 10 «не применим по имеющимся данным», каждый с причиной и условием закрытия; ни одна строка не означает `false`.
- `selector-reconciliation.csv` — предложение по четырём LU, отсутствующим в selector и не указанным как explicit exclusions. Это рекомендация для ревьюера, не изменение regional-environment.
- `validate.mjs` — read-only deterministic validator; `research-evidence.json` — компактные ссылки на проверенные находки; `extract-research-evidence.mjs` обновляет этот файл и поддерживает `--check`; автоматический тест — `../../scripts/start-territory-types.test.mjs`.

## Деноминаторы и статус

70 = каталог типов, закреплённый в `places-binding/inputs/m2c-nature-coverage-entries.json` (31 LU/39 place). 39/31 — разбиение этого пакета по предварительной причинной применимости, а не региональное одобрение. Текущий selector региональной кандидатуры содержит 24 LU/37 place. Пять из разницы 7+2 явно записаны как `explicit_exclusions` (`lu_open_field_strip_cultivation`, `lu_fishpond_aquaculture`, `lu_watermill_water_management`, `pt_watermill_site`, `pt_shipyard_boatyard`); остальные четыре LU перечислены в `selector-reconciliation.csv` как невыбранные, но не explicit exclusion. Selector не менялся; по D62 (2026-10-01) пробел для песка нужно устранить, и пакет рекомендует promotion после ревью Opus.

Старый региональный PF manifest хранит тип→PF соответствие, но candidate PF overlap не доказывает точное присутствие типа на узле. В текущих Spatial v3 node bindings нет прямых `land_use_template_id`/`place_template_id`; используются существующие node facets/PF. `presence_rules` остаются `scope_kind=place_family`; пакет не добавляет presence rules, людей, предметы, права, доступ, сезонность или topology. За сезонностью, запасом/ресурсом и работой стоит обращаться к отдельным источникам и владельцам.

Совместимость проверяется по непустым `compatible_landscape_template_ids` и `compatible_water_body_template_ids`; G5 при пустом значении берёт значение родителя G4. Каждое несовпадение требует точного исключения с причиной и разрешимыми ссылками. Исключение остаётся кандидатной редакционной оценкой и не меняет template vocabulary или active Spatial binding.

## Невыбранные LU: рекомендация

Для четырёх LU подготовлены рекомендации в selector-reconciliation.csv. По песку рекомендуется promotion с ограничениями (guards как у глины) и отдельным PF-шагом для pf_riverbank. D62 (2026-10-01) предписывает устранить пробел; tributary_mouth и mouth_bar совместимы с template allowlists, но promotion не создаёт presence без PF authoring. Сам selector не менялся. Для каменоломни сохраняется невыбранный статус: проверенная геология не даёт доступной коренной породы в стартовом scope; условие переоткрытия — в typed-gaps.csv.

## Открытые вопросы владельцу

- **Shipyard — решение D62 (2026-10-01):** региональное исключение остаётся; вытаскивание лодок и обслуживание малых судов (zaostrovye_landing_boat_drawing) не равны верфи. Переоткрытие — только при источнике о постройке судов.
- **Песок — решение D62 (2026-10-01):** пробел нужно устранить. По песку рекомендуется promotion с ограничениями (guards как у глины) и отдельным PF-шагом для pf_riverbank. Исследовательский JSON не содержит findings о песке; строка не утверждает исторический сбор или scene presence. Сам selector остаётся без изменений до отдельного утверждения.
- **Сад и бортничество — решено по исследованию D62, Opus pass 4 (APPROVE_WITH_LIMITS):** плодовый сад и лесное бортничество получили оценку «не применим по имеющимся данным» для baseline нижней Двины около 1230 г. (с оговорками ниже). Огород уже представлен кандидатом lu_kitchen_garden; сбор дикоросов, в том числе ягод, — кандидатом lu_wild_food_gathering. Отдельного типа культивируемого ягодника в инвентаре нет; добавить в следующую редакцию предложение о таком типе, если он нужен. Двинский акт с «ягодником» в lead research помечен not_found, его не использую как доказательство.
- **Каменоломня — решено по исследованию D62, Opus pass 4 (APPROVE_WITH_LIMITS):** оценка «не применим по имеющимся данным» основана на залегающей глубоко коренной породе и отсутствии подтверждённого доступного карьера у стартовой территории; это не исключает ледниковые валуны. Отдельного типа сбора валунов в инвентаре нет. Предложение для следующей редакции: рассмотреть самостоятельный LU сбора/использования свободных валунов, не смешивая его с каменоломней и песчано-гравийной добычей; для кандидатных refs потребуется локализация валунов.

## Исследовательская сверка после REVIEW-start-types-10

- **Плодовый сад:** проверенные находки помещают яблони на новгородском археологическом участке во второй половине XI века; участок заброшен к началу XIII века. Проверенный сад в Холмогорах относится к служению Афанасия (1682–1702), но состав посадок не указан; поздняя журналистская статья по Соловкам описывает фрукты и отапливаемые теплицы. Современные климатические нормы Архангельска (июль 16,5°C в среднем, зарегистрированный минимум −45,2°C) — только редакционная климатическая опора, период норм не указан; это не реконструкция климата 1230 года. Для стартового baseline плодовый сад признан «не применим по имеющимся данным», не универсально невозможным. Проверенные выдержки: `research-evidence.json#orchard-01`, `research-evidence.json#orchard-02`, `research-evidence.json#orchard-11`, `research-evidence.json#orchard-12`, `research-evidence.json#orchard-14`.
- **Бортничество:** два проверенных биогеографических изложения дают северную границу естественного ареала около 60° с.ш. Авдеев указывает ареал от юга Франции до Сибири, достигающий 60° с.ш.; Брандорф и Ивойлова сообщают о границе для России до Урала. Оба — вторичные изложения стандартного ареала, их независимость не установлена. Есть также проверенное, но не снабжённое источником энциклопедическое обобщение о пчеловодстве в северо-восточных зависимостях Новгорода до XIV века; оно не называет мест и не локализует промысел на Нижней Двине. Поэтому нижнедвинский вывод остаётся ограниченным решением по scope, не доказательством отсутствия пчёл или невозможности завоза. Проверенные выдержки: `research-evidence.json#bort-01`, `research-evidence.json#bort-02`, `research-evidence.json#bort-03`.
- **Каменоломня:** проверенная сводка Лавровой помещает коренную палеозойскую основу нижней Двины ниже уровня русла, с глубинами скважин 55–93 м; известняковые горизонты отмечены ниже Усть-Пинеги. Проверенный материал об Орлеце говорит, что крепость 1342 года построена из местного известняка, но не датирует начало добычи. Не писать «карьер известен с XIV века», «1342 — начало добычи», и не относить наблюдения нижней морены у Орлеца/Панилова к выходам коренной породы. Добыча в стартовом scope признана «не применим по имеющимся данным». Это не исключает валуны: Лаврова подтверждает эрратические валуны в моренах региона, но точную плотность и локализацию у Вихтуя/Заостровья источники не дают. Проверенные выдержки и оговорки: `research-evidence.json#quarry-01`, `research-evidence.json#quarry-02`, `research-evidence.json#quarry-07`, `research-evidence.json#quarry-15`.
- **Огород и ягодник:** отдельный тип lu_kitchen_garden уже кандидат, как и lu_wild_food_gathering для дикоросов/ягод. Отдельного типа культурного ягодника в 70 строках нет. Сообщение о двинском «ягоднике» из акта — not_found при проверке и не включено в основание. Предложение на будущее: рассмотреть отдельный тип культивируемого ягодника, если он нужен; сейчас нового ID не добавляю.
- **Сбор валунов:** отдельного LU для сбора свободного валунного камня в каталоге нет. lu_stone_quarrying описывает карьер, lu_sand_gravel_extraction — песок/гравий/галечник; ни один не равен сбору крупных валунов. Предложение на будущее — отдельный LU для сбора/использования валунов после доказательства местных подходящих узлов.
- **Песок:** G4 tributary_mouth и G5 mouth_bar проходят landscape/water allowlists; в selector-reconciliation остаётся рекомендация promotion после Opus/data-owner review. Сам selector и presence не менялись.
- Связь с v17-channels сохранена: этот пакет не добавляет presence rules; O1/O2a остаются владельцами профилей, reader и existing scope_kind=place_family presence.

## Проверки и дальнейшая спецификация

Проверки: `node data/world-catalogs/novgorod/game-base-v1/places-binding/start-territory-types/validate.mjs`; свежесть выдержек сверяется `node data/world-catalogs/novgorod/game-base-v1/places-binding/start-territory-types/extract-research-evidence.mjs --check --source /srv/novgorod-work/fleet/tasks/start-types/out/lead-research-1.json`. Последняя команда требует исходный fleet research JSON, который не включается в git. Валидатор проверяет якоря `research-evidence.json#<evidence_id>`, статус verified и поля локальных file:line-ссылок, G4/G5 уровень refs, PF IDs, template inventory и совместимость G4/G5 landscape/water с template allowlists; повторяемость причин проверяет эвристикой `reason-dupes` (порог 20%).
`npm run test:game-base` автоматически подхватывает `game-base-v1/scripts/*.test.mjs`, включая тест пакета.

Будущая matrix acceptance после data approval должна связать pinned regional selector → approved exact node/facet/PF → существующий reader/presence и проверять gaps/negative cases. Отдельная замена `tools/spatial-v3/report-m2c-nature-coverage.py` должна считать exact approved applicability, а legacy template-ref coverage показывать отдельной метрикой. Код runtime reader, DDL и новый presence owner этим пакетом не предлагаются.
