# CI783: как запускать специальные native probes

Источник: `da8f91947f2eedb6a614062e49326d62f8acb5aa`, чтение через разрешённый `git show`. Ниже предполагается уже подготовленный чистый upstream, наложенные девять overlays и скопированные test sources по `README.md:297–316`, а также собранный `cata_test`. Каталоги для userdir и evidence должны быть новыми (`README.md:325–328`). Команды здесь являются рецептом по коду, нового прогона не было.

| Probe | Воспроизводимый запуск и подготовка | Почему нельзя просто добавить тег к обычному прогону |
|---|---|---|
| `novgorod_semantic_test.cpp:318–364` | Случай помечен **`[novgorod_semantic]`, без `[.]`**. Для `create` нужен `NOVGOROD_P4_MODE=create`: тест создаёт fixture, сохраняет мир и пишет `novgorod-p3-observation.json` (`:320–329`, `:150–177`). Для `apply` в том же userdir нужно подготовить `novgorod-p3-operation.json` с request, затем `NOVGOROD_P4_MODE=apply ... cata_test --rng-seed 17 --user-dir=<тот же каталог> 'Novgorod semantic request uses native avatar primitives'`; результат — `novgorod-p3-operation-readback.json` (`:332–364`). Тем же точным именем следует выбирать `create` и `read`; широкий тег включает и другие тесты. `read` пишет observation после загрузки (`:328–330`). `generations.py:400–443,1559–1563,1599–1601` предлагает P3 stage adapter через `--p3-semantic` и `p3-runner.js`; для него нужен Node и корректный semantic request. | Без request файл не существует: `REQUIRE(request_stream.good())` на `:333–334`. Обычный запуск тега попадает в ветку применения, поскольку режим по умолчанию пуст (`:320–333`). Самодостаточен лишь отдельный этап `create`; полноценный сценарий требует последовательности и данных запроса. |
| `novgorod_persistence_test.cpp:345–388` | Скрытый тег `[.][novgorod_persistence]`. Штатный координатор запускает его через `generations.py`: `python3 generations.py --experiment-root <новый каталог> --native-root <pinned native> --binary <native/tests/cata_test> init`, затем с теми же путями `apply --operation-id <id> --operation pickup_rock`, затем `read`. Для проверки отказов есть `suite --evidence-root <новый каталог>` (`README.md:330–344`; `generations.py:31–35,495–505,1553–1575,1583–1614`). Координатор задаёт `NOVGOROD_P4_MODE`, `NOVGOROD_P4_WORLD`, операцию, seed 17 и userdir (`generations.py:495–505`). | Тест требует режим `create|apply|read` (`:347–349`), а `apply/read` нуждаются в сохранённой fixture в **том же** userdir (`:1–8`). Он проверяет sidecar `novgorod_rng_state` (`:369–370`). Координатор дополнительно управляет поколениями и fault suite; одиночный запуск не проверяет этот протокол. |

Первый, проверка сериализации движка RNG, исполним отдельно без P4-режима (`:30–72`), но с `NOVGOROD_P4_MODE=apply|read` дополнительно требует sidecar или `NOVGOROD_RNG_EXPECT_LEGACY=1` (`:34–43`). Для остальных ветвей нужны соответственно `NOVGOROD_RNG_TEST_SAVE_FAILURE=1`, `NOVGOROD_RNG_TEST_MALFORMED_LOAD=1`, `NOVGOROD_RNG_TEST_LEGACY_LOAD=1` и отдельные одноразовые копии подготовленного P4 save/userdir (`:74–136`). | Без этих переменных три случая возвращают `SUCCEED`, не проверяя ошибку (`:76–79,96–99,120–123`). Последние два требуют активного мира и сохранения (`:101–115,125–136`); они портят или удаляют sidecar, поэтому один общий userdir для серии непригоден. |

Для обычного CI job разумно отделить эти протокольные пробы от простого списка тегов. `generations.py` реализует последовательность P4 и предоставляет готовый `suite`, но `README.md:325–328` прямо описывает его как эксперимент с реальными SIGKILL, reload/retry и `/dev/full`; он нуждается в отдельном каталоге и времени. Включение полного suite в каждое PR следует решать по отдельным замерам.
