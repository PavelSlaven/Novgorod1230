# Этап 17. Проверка времени и света

## 1. Назначение этапа

Проверка времени и света — это отдельный hard gate после размещения NPC и предметов, но до формирования `visible_context_package` и до narrator prose.

Этап проверяет, что все временные, сезонные, погодные, световые и видимые слои согласованы между собой.

Проверяются:

* `historical_frame.clock`;
* `calendar.season`;
* `weather_state`;
* `light_profile`;
* `g5_scene_graph.visibility_model`;
* `npc_visibility_state`;
* `item_visibility_state`;
* `visible_scene`, если он уже был предварительно сформирован;
* `visible_changes`;
* `narrator_input`, если он уже подготовлен;
* `player_character.body`;
* `current_position`;
* доступность мест, NPC и объектов;
* последствия холода, темноты, ожидания и погоды.

Главная цель этапа — не дать системе пропустить противоречие вида:

```text id="xyjp7l"
clock.time_of_day = deep_night
clock.hour = 03
light_profile = dark
visible_scene = "короткий световой день"
```

Такой результат должен блокироваться до narrator prose.

## 2. Главное правило этапа

`clock` является источником истины для времени суток.

`season` является источником истины для сезонного состояния.

`weather_state` является источником истины для текущей погоды.

`light_profile` является источником истины для видимости.

`visible_scene` не может менять время, сезон, погоду или свет.

Если prose, visible package, G5, NPC или предметы противоречат `clock/season/weather/light`, pipeline останавливается.

Запрещено:

* исправлять время молча;
* менять `clock` под уже написанную сцену;
* менять `season` под удобную погоду;
* делать ночь “световым днём”;
* делать тёмную сцену полностью видимой;
* делать дневную активность в глубокой ночи без отдельного основания;
* показывать невидимые объекты как видимые;
* раскрывать скрытые предметы через prose;
* объяснять конфликт художественной фразой вместо исправления источника данных.

## 3. Место этапа в pipeline

```text id="yutnd8"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста
5. Подбор стартовых G1–G4 кандидатов
6. Подбор place templates
7. Подбор NPC-кандидатов
8. Подбор предметных профилей
9. Выбор стартового узла
10. Аудит стартового места
11. Генерация персонажа
12. Аудит персонажа
13. Материализация G5-сцены
14. Аудит G5-сцены
15. Размещение стартовых NPC
16. Размещение стартовых предметов
17. Проверка времени и света
18. Формирование visible context
19. Narrator prose
```

Этап 17 должен быть отдельным, а не частью narrator-аудита. Он должен сработать раньше, чем неверный `visible_scene` попадёт в прозу.

## 6. Авторитетность слоёв

### 6.1. `clock`

`clock` управляет:

```text id="s5blez"
частью суток;
освещением;
доступностью NPC;
режимом работы мест;
видимостью;
усталостью;
ожиданием;
рисками перемещения;
уличной активностью;
тем, какие слова разрешены в visible_scene.
```

Если `clock.time_of_day=deep_night`, то фразы:

```text id="20qu57"
короткий световой день
люди заняты дневными делами
яркий дневной свет
на дворе день
дневная толпа
открытый торг
обычная дневная работа
```

запрещены без явного перехода времени и новой проверки.

### 6.2. `season`

`season` управляет:

```text id="tcgv5b"
типичной погодой;
землёй и дорогами;
одеждой;
видимостью;
наличием снега/грязи/льда;
температурой;
работами;
пищей;
сезонными предметами;
состоянием тела;
доступностью маршрутов.
```

Если `season=winter`, сцена не должна внезапно иметь летний зной, зелёную траву, тёплую ночь или летнюю грозу без регионального погодного правила.

### 6.3. `weather_state`

`weather_state` управляет:

```text id="4wqct5"
температурой;
осадками;
ветром;
состоянием земли;
дальностью видимости;
следами;
шумом;
риском холода/сырости;
пожарами/дымом/скольжением/грязью;
видимостью предметов и NPC.
```

### 6.4. `light_profile`

`light_profile` управляет:

```text id="q1b42t"
что видно без проверки;
что видно только вблизи;
что видно только при источнике света;
что слышно, но не видно;
что скрыто;
что требует осмотра;
что нельзя показывать в visible_scene.
```

Принцип:

```text id="qlje0r"
видимость = clock light + weather modifier + G5 visibility + distance + obstruction + player position
```

## 8. Проверки этапа

### 8.1. Clock schema

Проверяется:

```text id="em0be7"
day exists
hour ∈ 0..23
minute ∈ 0..59
time_of_day exists
clock_moment exists
light_profile exists
```

Ошибка:

```text id="2ktm9t"
TIME_LIGHT_CLOCK_SCHEMA_INVALID
```

### 8.2. Clock moment consistency

Проверяется соответствие `hour/minute/time_of_day/clock_moment`.

Примеры hard conflict:

```text id="fztu4k"
hour=3, time_of_day=day
hour=12, time_of_day=deep_night
clock_moment="глубокая ночь", light_profile="daylight"
clock_moment="полдень", light_profile="dark"
```

Ошибка:

```text id="za2xvf"
TIME_LIGHT_CLOCK_MOMENT_CONFLICT
```

### 8.3. Season/weather consistency

Проверяется, что погода совместима с сезоном и региональным weather profile.

Примеры:

```text id="cmrdfr"
winter + heat/hot без особого правила → conflict
summer + severe_cold без особого правила → conflict
winter + rain возможен только если региональные правила допускают оттепель
snow + hot → conflict
ice/ground snow + warm thaw может быть warning, если есть thaw rule
```

Ошибка:

```text id="6fmd0x"
TIME_LIGHT_SEASON_WEATHER_CONFLICT
```

### 8.4. Weather/light consistency

Проверяется влияние погоды на свет и видимость.

Примеры:

```text id="i9tfws"
heavy fog + full clear visibility → conflict
storm/snowfall + distant visible objects → conflict
dark + no light source + visible small items → conflict
cloudy day + daylight может быть allowed as dim/daylight depending regional rule
```

Ошибка:

```text id="rp2g2g"
TIME_LIGHT_WEATHER_VISIBILITY_CONFLICT
```

### 8.5. G5 visibility consistency

Проверяется:

```text id="m1se04"
g5_scene_graph.visibility_model.light_profile
g5_anchors[*].visibility
visible_anchor_ids
requires_inspection_anchor_ids
hidden_anchor_ids
player_start_position.visible_anchor_ids
```

Hard conflict:

```text id="fme2vm"
light_profile=dark,
но все anchors marked visible_now=true
```

Hard conflict:

```text id="mgl5j7"
hidden_anchor_id одновременно в visible_anchor_ids
```

Ошибки:

```text id="rl1q66"
TIME_LIGHT_G5_VISIBILITY_CONFLICT
TIME_LIGHT_HIDDEN_ANCHOR_VISIBLE
TIME_LIGHT_TOO_MANY_VISIBLE_ANCHORS_IN_DARK
```

### 8.6. NPC visibility and activity consistency

Проверяется:

```text id="xnr2i2"
npc.visibility_state
npc.current_activity
npc.attention_state
npc.schedule_state
clock.time_of_day
light_profile
weather_state
```

Hard conflict:

```text id="hsfq6k"
deep_night + ordinary daytime crowd + no night exception
deep_night + NPC identified by name/status at distance in darkness
dark + visible_to_player=true + no light/near/hearing basis
```

Допустимо:

```text id="podflj"
NPC слышен, но не виден
NPC виден как силуэт
NPC рядом с огнём
NPC спит
NPC сторожит ночью
NPC прячется/идёт/ждёт
```

Ошибки:

```text id="q08a93"
TIME_LIGHT_NPC_ACTIVITY_CONFLICT
TIME_LIGHT_NPC_VISIBILITY_CONFLICT
TIME_LIGHT_NPC_IDENTIFICATION_TOO_STRONG
```

### 8.7. Item visibility consistency

Проверяется:

```text id="nj8804"
item.visibility_state
container.content_state
item_anchor_bindings
clock.light_profile
weather_state.visibility_weather_modifier
player_start_position
```

Hard conflict:

```text id="c2w7tt"
dark + small item visible_to_player_now=true + no light source
closed container + visible concrete contents
hidden item + visible_to_player_now=true
known_but_not_seen item described as seen
```

Ошибки:

```text id="mbfkik"
TIME_LIGHT_ITEM_VISIBILITY_CONFLICT
TIME_LIGHT_CLOSED_CONTAINER_CONTENTS_VISIBLE
TIME_LIGHT_HIDDEN_ITEM_VISIBLE
```

### 8.8. Body state consistency

Время, погода и сезон должны влиять на тело персонажа, если условия экстремальные.

Проверяется:

```text id="yvfw8l"
temperature_band
precipitation
wind
player_character.body.clothing_summary
player_character.body.active_conditions
player_character.body.health
player_character.body.satiety
player_character.body.vigor
```

Если сильный холод, ветер, мокрая одежда или ночь создают риск, но `body` и `visible_changes` не отражают это вообще, нужен warning или block по policy.

Ошибки:

```text id="56e537"
TIME_LIGHT_BODY_WEATHER_EFFECT_MISSING
TIME_LIGHT_CLOTHING_WEATHER_CONFLICT
```

### 8.9. Visible scene consistency

Если `draft_visible_context_package.visible_scene` уже есть, он проверяется как текстовый слой.

Проверяется:

```text id="ougjmy"
visible_scene не меняет clock
visible_scene не меняет season
visible_scene не меняет weather
visible_scene не меняет light
visible_scene не показывает невидимое
visible_scene не раскрывает скрытое
visible_scene не описывает дневную активность ночью
visible_scene не описывает ночную темноту днём
```

Hard conflict:

```text id="p2yc7s"
clock.time_of_day=deep_night
visible_scene содержит "короткий световой день"
```

Ошибка:

```text id="hnd20j"
TIME_LIGHT_VISIBLE_SCENE_CLOCK_CONFLICT
```

### 8.10. Visible changes consistency

`visible_changes` не должны противоречить `clock`.

Hard conflict:

```text id="k3npzu"
clock=deep_night
visible_changes="световой день короток"
```

Вместо этого допустимо:

```text id="h8m0o8"
ночь глубока
холод усиливается
огонь гаснет
видимость падает
усталость растёт
стража становится строже
доступ к месту ограничен
```

Ошибка:

```text id="822or8"
TIME_LIGHT_VISIBLE_CHANGES_CLOCK_CONFLICT
```

### 8.11. Forbidden terms check

Код должен иметь словарь терминов, конфликтующих с time/light.

Пример:

```json id="egv8i9"
{
  "deep_night": {
    "forbidden_terms": [
      "короткий световой день",
      "дневной свет",
      "яркий день",
      "полдень",
      "солнце высоко",
      "дневная толпа",
      "открытый дневной торг"
    ],
    "allowed_terms": [
      "глубокая ночь",
      "темно",
      "лунный свет",
      "свет из окна",
      "лучина",
      "огонь",
      "силуэт",
      "слышно, но не видно"
    ]
  }
}
```

Forbidden terms не должны быть единственной проверкой, но они нужны как быстрый hard gate.

## 10. Работа LLM на этапе

Базовый hard gate должен работать кодом. Код обязан проверять:

* enum;
* диапазоны;
* `clock ↔ light`;
* `season ↔ weather`;
* forbidden terms;
* visibility flags;
* source trace;
* наличие конфликтующих строк в `visible_scene`.

LLM используется только как semantic auditor, если нужно проверить смысловые противоречия, которые трудно поймать регулярными правилами.

LLM не имеет права:

* менять `clock`;
* менять `season`;
* менять `weather_state`;
* менять G5;
* менять NPC;
* менять предметы;
* писать visible scene;
* писать narrator prose;
* исправлять текст.

LLM только возвращает audit.

## 11. LLM-параметры

### 11.1. `TimeLightSemanticAuditor`

Назначение: смысловая проверка времени, света, погоды, видимости и чернового visible context.

```json id="a377m2"
{
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "thinking": {
    "type": "enabled"
  },
  "reasoning_effort": "high",
  "temperature": null,
  "top_p": null,
  "max_tokens": 7000,
  "response_format": {
    "type": "json_object"
  },
  "context_budget": {
    "target_input_tokens": 80000,
    "hard_input_limit_tokens": 200000,
    "reserve_output_tokens": 7000
  }
}
```

Использовать `deepseek-v4-pro`, потому что этот gate проверяет причинные противоречия между несколькими слоями сцены. DeepSeek API поддерживает `deepseek-v4-pro`, `deepseek-v4-flash`, `thinking` и `reasoning_effort`; thinking mode включается через `thinking`, а reasoning effort задаётся отдельно.

Назначение: выбрать корректный этап отката при провале.

```json id="d19nxw"
{
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "thinking": {
    "type": "enabled"
  },
  "reasoning_effort": "high",
```

## 16. Validation rules

Код обязан проверить:

1. `schema === "time_light_consistency_audit"`.
2. `version === 1`.
3. `pass` является boolean.
4. `authoritative_frame.clock` совпадает с `historical_frame.clock`.
5. `authoritative_frame.season` совпадает с `historical_frame.calendar.season`.
6. `authoritative_frame.weather_state` совпадает с входным `weather_state`.
7. `light_profile` входит в enum.
8. `hour` в диапазоне `0..23`.
9. `minute` в диапазоне `0..59`.
10. `time_of_day` входит в enum.
11. `clock_moment` не противоречит `time_of_day`.
12. `time_of_day` не противоречит `light_profile`.
13. `season` не противоречит `weather_state`.
14. `weather_state.visibility_weather_modifier` применён к visibility constraints.
15. `g5_scene_graph.visibility_model.light_profile` не противоречит `historical_frame.clock.light_profile`.
16. `visible_anchor_ids` не содержат hidden anchors.
17. NPC visibility не нарушает light profile.
18. NPC activity не нарушает time_of_day.
19. Item visibility не нарушает light profile.
20. Hidden item не visible.
21. Closed container contents not visible.
22. `draft_visible_context_package.visible_scene` не содержит forbidden terms.
23. `draft_visible_context_package.visible_changes` не содержит forbidden terms.
24. Если `pass=false`, `concerns` не пустой.
25. Если `pass=false`, `repair_route` заполнен.
26. `evidence` не пустой.
27. Если `pass=true`, `can_continue_to_visible_context=true`.
28. `can_continue_to_narrator` не должен быть true до отдельного visible context audit.
