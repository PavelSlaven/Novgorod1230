# Этап 8. Подбор допустимых предметных профилей

## 1. Назначение этапа

Подбор допустимых предметных профилей — это этап запуска новой партии, который формирует ограниченный список возможных предметных категорий, контейнеров и правил собственности для уже допустимых стартовых мест.

Этот этап не создаёт конкретные предметы. Он не кладёт вещи в сцену. Он не создаёт инвентарь персонажа. Он не создаёт содержимое сундуков, мешков, лавок, амбаров, домов или тайников.

Его задача — подготовить разрешённое предметное пространство:

```text id="g07j3w"
candidate_place_template_set
+ regional item profiles
+ container profiles
+ property rules
+ trade rules
+ goods prices
+ social roles
+ occupations
+ historical frame
→ item_profile_candidate_set
```

Этап отвечает на вопрос:

```text id="7jaw1n"
Какие категории предметов, контейнеров и имущественных правил допустимы для таких стартовых мест?
```

Он не отвечает на вопрос:

```text id="f8i0qr"
Какие конкретные вещи сейчас лежат перед игроком?
```

## 2. Главное правило этапа

Предмет не возникает из желания игрока.

Если игрок написал:

```text id="4x8u9n"
хочу начать с мечом
хочу найти деньги
хочу чтобы рядом был сундук
хочу украсть еду
```

это не создаёт предмет.

Такая заявка может стать только ограничением или желанием, которое будущие этапы проверяют через:

```text id="nh8809"
место
эпоху
экономику
социальный статус
владельца
контейнер
доступ
видимость
причину появления
риск
```

Предметный профиль допустим только если он разрешён базой и совместим с выбранным типом места.

## 3. Место этапа в pipeline

```text id="3w15a8"
1. Заявка игрока
2. Нормализация заявки
3. Выбор исторической рамки
4. Загрузка регионального контекста из world_base
5. Подбор допустимых стартовых G1–G4 кандидатов
6. Подбор допустимых place templates
7. Подбор допустимых NPC-кандидатов
8. Подбор допустимых предметных профилей
9. Выбор стартового места
10. Генерация персонажа
11. Материализация G5
12. Размещение NPC и предметов
```

Этап 8 должен идти после place templates, потому что допустимость предметов зависит от типа места. Он также использует NPC-кандидаты, потому что вещи часто связаны с социальными ролями, занятиями, владельцами, свидетелями и контролёрами доступа.

## 6. Что считается предметным профилем

Предметный профиль — это не конкретный предмет, а разрешённая категория вещей.

Пример допустимого профиля:

```json id="da67hi"
{
  "item_profile_candidate_id": "item_prof_cand_001",
  "item_profile_id": "item_profile_001",
  "item_group": "food_or_household",
  "allowed_place_template_ids": ["place_template_001"],
  "typical_owner_model": "household_or_worker",
  "typical_visibility": "visible_or_stored",
  "can_be_materialized_later": true
}
```

Это означает:

```text id="zuv7to"
в таком месте такие вещи могут быть допустимы
```

Это не означает:

```text id="77n8as"
конкретная вещь уже лежит в сцене
```

## 7. Разделение уровней предметной среды

### 7.1. Категория предметов

Категория описывает ожидаемый предметный слой места.

Пример:

```text id="g5cffo"
бытовые вещи
пища
топливо
инструменты
упряжь
торговый товар
сакральные предметы
служебные вещи
оружие охраны
письменные принадлежности
дорожное снаряжение
```

Категория может быть частью стартового контекста, но не создаёт конкретного экземпляра.

### 7.2. Значимый предмет

Значимый предмет появляется только позже, если он:

```text id="sbcoww"
видим персонажу
выбран для взаимодействия
используется в действии
ищется
берётся
продаётся
ломается
скрывается
является уликой
принадлежит кому-то важному
создаёт риск
влияет на проверку
```

Тогда он получает отдельную карточку с классом, материалом, состоянием, размещением, обнаружимостью, владением, функцией, ценностью, статусом, следами, доступностью и риском.

### 7.3. Контейнер

Контейнер — это объект хранения, доступа или сокрытия. Он не является “бесплатным списком предметов”.

На этом этапе контейнерный профиль описывает:

```text id="93jhjx"
какие контейнеры возможны
где они обычно стоят
кто контролирует доступ
можно ли их открыть
какие риски есть
когда содержимое надо определить заранее
```

Конкретное содержимое контейнера создаётся позже, когда контейнер попадает в активную сцену и становится причинно доступным.

### 7.4. Правила собственности

Property rules описывают:

```text id="19mmqy"
владельца
держателя
контролёра доступа
право пользования
право распоряжения
риск кражи
риск свидетелей
местный обычай
социальный статус предмета
```

Предмет может физически находиться у одного человека, принадлежать другому, контролироваться третьим и быть доступным четвёртому только по разрешению. Физическое ношение не равно праву владения.

## 9. Алгоритм этапа

### 9.1. Проверить входы

Код проверяет:

```text id="hxvm42"
historical_frame.audit.pass = true
regional_context_package.audit.pass = true
candidate_place_template_set.audit.pass = true
npc_candidate_set.audit.pass = true, если передан
region_id задан
year задан
season задан
clock задан
candidate_place_template_set.selection_status = ready
```

Если нет допустимых place template links, предметные профили не подбираются.

### 9.2. Загрузить item profiles

```sql id="mk5qxo"
SELECT *
FROM world_base.item_profiles
WHERE (region_id = :region_id OR region_id IS NULL)
  AND status IN (:allowed_statuses);
```

Если есть региональная связка:

```sql id="n0gwk0"
SELECT rip.*, ip.*
FROM world_base.region_item_profiles rip
JOIN world_base.item_profiles ip
  ON ip.id = rip.item_profile_id
WHERE rip.region_id = :region_id
  AND rip.is_allowed = true
  AND rip.status IN (:allowed_statuses)
  AND ip.status IN (:allowed_statuses);
```

### 9.3. Загрузить container profiles

```sql id="kszjv4"
SELECT *
FROM world_base.container_profiles
WHERE (region_id = :region_id OR region_id IS NULL)
  AND status IN (:allowed_statuses);
```

Если контейнеры регионально связаны:

```sql id="7de1u1"
SELECT rcp.*, cp.*
FROM world_base.region_container_profiles rcp
JOIN world_base.container_profiles cp
  ON cp.id = rcp.container_profile_id
WHERE rcp.region_id = :region_id
  AND rcp.is_allowed = true
  AND rcp.status IN (:allowed_statuses)
  AND cp.status IN (:allowed_statuses);
```

### 9.4. Загрузить property rules

```sql id="e0ot0h"
SELECT *
FROM world_base.property_rules
WHERE (region_id = :region_id OR region_id IS NULL)
  AND status IN (:allowed_statuses);
```

Если правила регионально связаны:

```sql id="w6w93z"
SELECT *
FROM world_base.regional_property_rules
WHERE region_id = :region_id
  AND status IN (:allowed_statuses);
```

### 9.5. Загрузить trade rules и goods prices

```sql id="r2ql7p"
SELECT *
FROM world_base.trade_rules
WHERE region_id = :region_id
  AND status IN (:allowed_statuses);
```

```sql id="kg86n5"
SELECT *
FROM world_base.goods_prices
WHERE region_id = :region_id
  AND status IN (:allowed_statuses);
```

Если цены отсутствуют, это не всегда блокирует этап. Но предметы с торговой/обменной функцией должны получить warning:

```text id="jxcdpx"
ITEM_PROFILE_PRICE_REFERENCE_MISSING
```

### 9.6. Построить индексы

Код строит:

```json id="lgbmlp"
{
  "item_profile_by_id": {},
  "container_profile_by_id": {},
  "property_rule_by_id": {},
  "trade_rule_by_id": {},
  "goods_price_by_item_profile_id": {},
  "place_template_links_by_place_template_id": {},
  "npc_candidates_by_social_role_id": {},
  "npc_candidates_by_occupation_id": {},
  "npc_candidates_by_archetype_id": {}
}
```

### 9.7. Сопоставить item profile ↔ place template

Предметный профиль допустим, если:

```text id="e4dqn9"
item_profile.typical_place_template_ids пустой
или place_template_id ∈ item_profile.typical_place_template_ids
```

Если item profile имеет жёсткий список place templates, выход за список запрещён.

Если список пустой, профиль должен иметь другое основание:

```text id="7id8nj"
regional item rule
occupation match
social role match
container match
trade rule match
property rule match
```

Без основания item profile отклоняется.

### 9.8. Проверить social role / occupation basis

Если item profile связан с ролями или занятиями:

```text id="5jv9xs"
typical_social_role_ids
typical_occupation_ids
typical_npc_archetype_ids
```

код проверяет, что такие роли, занятия и NPC-кандидаты существуют в региональном контексте.

Если профиль требует ремесленника, торговца, хозяина, сторожа, служилого человека или иного держателя, но соответствующих кандидатов нет, профиль получает warning или reject.

### 9.9. Проверить container basis

Если item profile обычно хранится в контейнере:

```text id="x834sd"
typical_container_profile_ids
```

код проверяет наличие совместимого container profile.

Если контейнера нет, но предмет может быть видимым/открытым, это может быть warning. Если предмет должен храниться только в контейнере, профиль отклоняется.

### 9.10. Проверить property basis

Каждый interactable item profile должен иметь хотя бы одно применимое правило собственности:

```text id="be8hp0"
ownership_default
holder_default
access_default
или property_rule_id
```

Если предмет может стать объектом взаимодействия, но нет модели владения/доступа, он отклоняется.

Ошибка:

```text id="wra1rn"
ITEM_PROFILE_PROPERTY_RULE_MISSING
```

### 9.11. Проверить сезон

Если у предмета есть `seasonal_limits`, код сверяет их с `historical_frame.calendar.season`.

Примеры:

```text id="k97x06"
сезонная пища
зимняя упряжь
летние сети
сани
лодочное снаряжение
сухое топливо
испорченная еда
```

Если профиль невозможен в сезоне, он отклоняется. Если возможен с ограничениями, добавляется warning.

### 9.12. Проверить время суток и свет

Время суток не запрещает предмет как категорию, но влияет на:

```text id="xvwjx8"
видимость
доступность
законность действия
наличие свидетелей
возможность покупки/обмена
возможность вскрытия контейнера
возможность заметить вещь
```

Если `clock.light_profile=dark`, будущий visible context не должен показывать мелкие предметы как явно видимые без света, близости или осмотра.

На этом этапе фиксируется constraint:

```text id="l7bt9p"
dark light_profile → item visibility must be limited later
```

### 9.13. Проверить player request

Если игрок просил конкретную вещь, это не создаёт item profile автоматически.

Код может сделать только одно из трёх:

1. если соответствующий item profile есть в базе и допустим для места — добавить высокий `player_request_match`;
2. если profile есть, но не допустим — добавить rejected candidate;
3. если profile отсутствует — добавить `unknown_or_unavailable_requested_item`.

Пример:

```json id="co0bci"
{
  "player_requested_item_handling": {
    "raw_request": "хочу меч",
    "matched_item_profile_id": null,
    "result": "not_materialized",
    "reason": "Player request does not create item. No allowed item profile match for current candidate place set."
  }
}
```

### 9.14. Проверить rarity / value / risk

Редкий, дорогой, служебный, опасный или социально заметный item profile требует усиленного основания:

```text id="zl5kzn"
конкретный владелец
служебный контекст
торговый контекст
тайник
охрана
долг
залог
след события
трофей
подарок
обмен
конфискация
```

На этом этапе такие профили можно оставить как `restricted`, но нельзя сделать обычным background item.

### 9.15. Сформировать item profile candidate

Каждая допустимая связка оформляется отдельно:

```text id="z2ijn1"
item_profile
+ candidate_place_template_link
+ container_profile, если нужен
+ property_rule
+ trade/price reference, если применимо
+ owner/access model
+ visibility model
+ score
```

## 10. Формат item profile candidate

```json id="6ovcck"
{
  "item_profile_candidate_id": "item_prof_cand_001",

  "candidate_status": "allowed | restricted | weak | rejected",

  "item_profile": {
    "item_profile_id": "item_profile_001",
    "slug": "string",
    "title": "string",
```

## 14. Scoring

Scoring не создаёт предмет. Он только сортирует допустимые профили.

Рекомендуемая формула:

```text id="ybojyz"
score =
  place_match_score
+ social_role_basis_score
+ occupation_basis_score
+ npc_controller_basis_score
+ container_basis_score
+ property_rule_score
+ season_match_score
+ trade_price_reference_score
+ source_confidence_score
+ player_request_match_score
- rarity_penalty_without_basis
- missing_container_penalty
- missing_price_reference_penalty
- warning_penalty
```

Шкала:

```text id="n7qwns"
90–100 = excellent
70–89 = good
50–69 = usable
30–49 = weak
0–29 = reject
```

## 15. Hard gates

Профиль отклоняется без LLM, если:

```text id="frqwoh"
item_profile_id отсутствует в world_base
container_profile_id отсутствует в world_base
property_rule_id отсутствует в world_base
status = rejected
status = conflict
region_id несовместим
period/year несовместим
place_template mismatch
season hard conflict
requires_container=true, но контейнерного профиля нет
requires_property_rule=true, но property rule нет
requires_owner_or_controller=true, но нет social/NPC basis
player hard constraint conflict
rare/restricted item lacks causal basis model
source missing при require_sources=true
```

Эти проверки выполняет код, а не LLM.

## 17. Работа LLM на этом этапе

Базовый этап должен работать без LLM. Главный подбор предметных профилей выполняет код через `world_base`.

LLM допускается только в четырёх вспомогательных режимах:

1. `ItemProfileSetCompressor` — сжатие большого списка профилей.
2. `ItemProfileSetAuditor` — смысловой аудит уже собранного списка.
3. `ItemProfileExplanationWriter` — техническое пояснение для разработчика.
4. `ItemProfileFormatRepairer` — repair JSON-формата.

LLM запрещено:

* добавлять `item_profile_id`;
* добавлять `container_profile_id`;
* добавлять `property_rule_id`;
* создавать конкретный предмет;
* создавать содержимое контейнера;
* создавать владельца;
* создавать тайник;
* создавать деньги;
* создавать оружие;
* создавать торговый товар;
* создавать “находку”;
* создавать visible_scene;
* создавать intro_prose.

## 22. Validation rules

Код обязан проверить:

1. `schema === "item_profile_candidate_set"`.
2. `version === 1`.
3. `selection_status` входит в enum: `ready`, `empty`, `blocked`, `requires_repair`.
4. Каждый `item_profile_candidate_id` уникален.
5. Каждый `item_profile_id` существует в `item_profiles`.
6. Каждый `container_profile_id` существует в `container_profiles`, если указан.
7. Каждый `property_rule_id` существует в `property_rules`, если указан.
8. Каждый `goods_price_reference_id` существует, если указан.
9. Каждый `trade_rule_id` существует, если указан.
10. Все records относятся к выбранному `region_id` или являются глобальными разрешёнными записями.
11. Нет records со `status=conflict`.
12. Нет records со `status=rejected`.
13. Каждый `candidate_place_template_link_id` существует в `candidate_place_template_set`.
14. Item profile совместим с place template.
15. Item profile совместим с social role / occupation / NPC basis, если такие требования заданы.
16. Если item profile требует контейнер, существует совместимый container profile.
17. Если item profile интерактивный, существует property rule или встроенная access/ownership model.
18. Season compatibility пройдена.
19. Clock/light visibility constraints не нарушены.
20. Player request не превратился в конкретный предмет.
21. Rare/restricted profile не помечен ordinary без основания.
22. Нет `item_id`.
23. Нет `concrete_item_name`, если это не title профиля.
24. Нет `container_contents`.
25. Нет конкретного `owner_npc_id`.
26. Нет `visible_scene`.
27. Нет `intro_prose`.
28. `source_trace` не пустой, если `require_sources=true`.
29. Все source IDs существуют в `source_records`.
30. `audit.evidence` не пустой.
31. Если `audit.pass=false`, `audit.concerns` не пустой.

## 25. Commit gate этапа

Этап считается успешным, если:

```text id="l75ztl"
item_profile_candidate_set валиден,
есть хотя бы один allowed item profile или явно допустимо отсутствие предметных профилей,
каждый профиль ссылается только на записи world_base,
каждый профиль совместим с candidate_place_template_set,
контейнеры и property rules подтянуты для интерактивных предметов,
нет материализованных предметов,
нет содержимого контейнеров,
нет конкретных владельцев,
нет сцены,
audit.pass=true.
```

Если профилей нет, pipeline не должен просить LLM “придумать вещи”. Он должен:

1. ослабить только soft preferences;
2. вернуться к place template stage;
3. выбрать другой стартовый candidate set;
4. вернуть `blocked`;
5. записать `NO_ALLOWED_ITEM_PROFILES`.

```text id="efua43"
item_profile_candidate_set.item_profile_candidates[*].item_profile_candidate_id
container_profile_candidates[*].container_profile_candidate_id
property_rule_candidates[*].property_rule_candidate_id
```

Если LLM создаёт предмет вне candidate set, результат отклоняется без смыслового repair.
