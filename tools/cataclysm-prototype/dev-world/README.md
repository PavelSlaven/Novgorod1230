# Двор плотника — dev fixture

Крыша избы задаётся отдельным родным OMT на z=1 над всем контуром здания. Для изменения крыши нужен новый мир: уже сгенерированная карта сохранения не перестраивается из mapgen. Стартовый EOC сценария однократно задаёт герою 90% начального запаса калорий через родной math API; при загрузке сохранения он повторно не применяется.

Второй EOC сценария, `EOC_NOVGOROD_DEV_NPC_START_BODY` (`start.json:68`, `npc.json:75–92`), задаёт стартовое тело NPC.
- Как он доходит до NPC. Родной код ставит EOC сценария в очередь каждому новому персонажу (`src/effect_on_condition.cpp:155–177`). NPC получает его только при `run_for_npcs` (`src/character.cpp:452–459`), а `run_for_npcs` допустим только у `global` (`src/effect_on_condition.cpp:121–125`).
- Что делает. Один раз при создании NPC: если запас калорий ниже нормы, поднимает его до 100% нормы, затем ставит NPC пометку `novgorod_start_body`. Полные тела родного броска (`src/npc.cpp:734–741`) не трогает. Присваивание калорий отбрасывает дробную часть (`src/math_parser_diag.cpp:1733–1742`), поэтому норма считается с `round`.
- Зачем пометка. Глобальный EOC с `run_for_npcs` при каждой активации проходит по всем NPC (`src/effect_on_condition.cpp:376–387`); без пометки создание любого NPC заново поднимало бы запас всем.
- Основание — решение владельца D229: голод 1230 года на старте ещё не начался. При вводе голода с 14 сентября условие пересмотреть.

Еду и питьё дальше ведут только родные пути.

Случайные полные имена героя и NPC берутся из `personal-names.generated.json`. Файл строится из обычных мужских и женских строк пула `novgorod_1230_1250_personal_names_v1` в `data/world-catalogs/novgorod/game-base-v1/names-peoples/personal_names/name_pool_entries.csv`. Отбор содержит 204 мужских и 62 женских имени со статусом `draft`; проекция не утверждает исходные данные. Полное имя равно `name_form`, без добавления фамилии или отчества. Родные snippet-категории заменяются через `override: true`; сохранённые имена прежних персонажей не меняются.

Из корня репозитория:

```sh
node tools/cataclysm-prototype/generate-personal-names.mjs
node tools/cataclysm-prototype/generate-personal-names.mjs --check
node --test tools/cataclysm-prototype/personal-names.test.js
```

Параметр `--output <путь>` записывает проекцию в другой файл. Тест включён в `test:cataclysm-p3` и проверяет байты файла мода, количество имён и соответствие исходному отбору.

Небольшая сцена для проверки живого CDDA: изба с деревянной дверью, столом, соломенной постелью и глиняной печью, колодец, ряд частокола с воротами, двое NPC (мастер и сторож) и родные предметы `flint_steel`, `tinder`, `firewood`, `stick`, `stick_common`, `straw_basket`, `dry_fish`, `log` (`courtyard.json:45–75`). Это вымышленный двор возле Новгорода, не реконструкция города XIII века и не production world catalog. Вне стартового тайла остаются поля, леса, болота, реки и озёра; города и дороги отключены настройками родного региона (`src/regional_settings.cpp:619–636`), а `feature_flag_settings.whitelist` оставляет двор и разрешённые природные дополнения, исключая остальные места CDDA (`src/overmap.cpp:258–289`). Дополнения получают флаг двора через штатные map-extra flags (`src/map_extras.cpp:1300–1321, 1347–1367; src/map_extras.h:82–86`), а `MONSTER_WHITELIST` с режимом `EXCLUSIVE` разрешает 140 существующих видов фауны (`src/mongroup.cpp:372–442`). Ограничения применяются при создании нового мира: сохранённая карта из mapgen не перестраивается.

Мод подключается родным `MOD_INFO` (`data/mods/dda/modinfo.json`, `src/mod_manager.cpp:190–223`). `overmap_special`, `overmap_terrain`, `mapgen`, `start_location` и `scenario` задают место старта (`src/start_location.cpp:289–310,476`); `mapgen.place_npcs` создаёт NPC (`data/mods/aftershock_exoplanet/maps/mapgen/prepnet_orchard.json:71`). `flint_steel` использует штатный `firestarter` и требует трут (`data/json/items/tool/fire.json:70`). Данные мода C++ не содержат; распорядок NPC (`native-npc-post-work`) и запись кадра (`native-perception-capture`) — отдельные патчи CDDA из списка `native-overlays.txt:11–12`, который накладывает `apply-overlays.sh:13–20`.

Для первого мира: поместить каталог мода в `data/mods` изолированной native runtime, открыть CDDA с отдельным `--userdir`, русским `USE_LANG=ru` в `config/options.json` и ядровым `cataclysm-dda.mo` в `share/locale/ru/LC_MESSAGES/`. В `config/user-default-mods.json` задать зависимости только ["dda", "novgorod_dev_world"], затем через родное меню создать мир `novgorod-dev-04` со сценарием «Двор плотника» и сохранить игру штатным действием CDDA (`src/main_menu.cpp:1173`, `src/handle_action.cpp:2940,2953`, `src/game_io.cpp:734`). В `fixture/save/` копировать без правок каталог мира, полученный родным `game::save()`; в `fixture/config/` положить проверенные `options.json` и `user-default-mods.json`. Повторные запуски продолжают тот же save.
Прежний fixture содержал obsolete-мод `test_data`, который попадал в новый мир из `config/user-default-mods.json` (`src/mod_manager.cpp:195-201,310-326`, `src/worldfactory.cpp:84`) и печатал `test recurrence`. Новый fixture на servak находится в `/srv/novgorod-work/scratch/fix04e-devworld/fixture-800-ru`: его `mods.json` содержит только `dda` и `novgorod_dev_world`, а копия прежнего `options.json` уже имела `USE_LANG=ru`. Аватар стартует снаружи избы, на клетке (0, 7) зоны `ZONE_START_POINT` (`courtyard.json:47`, `start.json:37` — `ALLOW_OUTSIDE`); мастер стоит на посту Work (13, 15) снаружи у южной стены избы, сторож — на посту Gate (12, 19) у ворот, стол, постель, печь и мелкие вещи внутри избы.

Структурная проверка JSON не доказывает, что CDDA выбрал нужный тайл, выдал подходящее снаряжение и сохранил NPC. Для проверки загрузки и согласованности данных используйте собранный на закреплённом CDDA `tests/cata_test`: проверенная копия бинаря взята из `/srv/novgorod-work/scratch/fix04e-s847/native-trace/tests/cata_test` (SHA-256 `df62f3d613e5dbbb88494e623fd6e98f3165ae9092a8a363f80b2ebc7ebabfd7`). Из отдельного каталога с `data/`, `gfx/` и `tests/cata_test` выполните:

```sh
devworld_userdir=$(mktemp -d ./user-mod-check.XXXXXX)
timeout 1200s ./tests/cata_test --rng-seed 17 --mods=novgorod_dev_world --user-dir="$devworld_userdir" poisson_distribution
```

Ожидаемый код выхода — 0 без debug error при инициализации; на servak это подтверждено логом `/srv/novgorod-work/scratch/fix04e-devworld/mod-validation/positive.log`. Отрицательный контроль с несуществующим `material` в отдельной копии мода дал код 1 и `invalid material` (`negative.log`). `cataclysm --check-mods novgorod_dev_world` на curses-бинаре в PTY 120×40 не завершился за 30 минут (код 124, `/srv/novgorod-work/scratch/fix04e-devworld/checkmods.log`), поэтому здесь используется `cata_test`. Перед использованием fixture дополнительно нужны интерактивные проверки карты, NPC, предмета, двери и родного save/reload; историческая достоверность отдельно не заявлена.

Видимые игроку строки мода — по-русски прямо в JSON. Мастер — шаблон-персона `novgorod_dev_master` («Жирко», `gender`, `personality`, фракция `novgorod_dev_master_household`), сторож — `novgorod_dev_watchman` («Прокша», та же фракция); `place_npcs` ставит каждого один раз через `unique_id` (`courtyard.json:72–75`), `faction_owner` отдаёт фракции мастера все вещи тайла (`courtyard.json:76`). `items.json` переопределяет русские названия родных вещей сцены через `copy-from` того же id; механика вещей не меняется. Так же переопределён `stick_common`: сцена кладёт его в избе (`courtyard.json:63`), родной мир тоже кладёт его рядом (`wild-items.json:198,268`), и NPC видит вещь в кадре.

Для воспроизводимого маршрута старт фиксирует родная зона `ZONE_START_POINT` в `courtyard.json:47` (`src/start_location.cpp:501–511`, `src/mapgen.cpp:3404–3442, 4779`), а поле `"rotate": false` у специального места `novgorod_dev_courtyard_special` сохраняет северную ориентацию (`src/overmap_special.cpp:351`, `src/overmap.cpp:2938–2940`). Эти настройки нужно задать до создания нового мира: уже существующая карта автоматически не перестраивается. Запись состоит из 50 вводов эталонного маршрута задания 25 без исходного ввода №16. После штатного сохранения скопируйте каталог мира без изменений в `world-after-route` до повторной загрузки; проверяющий читает эту копию. Для снимка карты загрузите сохранение с выключенной записью кадров, снимите карту и выйдите без сохранения.

Дата старта задана родным полем сценария `"start_of_game": { "hour": 7, "day": 61, "season": "summer", "year": 1 }` (`start.json:70`). CDDA читает его в `src/scenario.cpp:141–151` и считает момент от `calendar::turn_zero` (`src/scenario.cpp:152–157`): при длине сезона 91 это `turn_zero` + 151 день + 7 часов. Год CDDA — 364 дня, `turn_zero` приходится на 21 марта (`src/calendar.cpp:856–868`), поэтому `month_and_day` даёт 20 августа 07:00 (`src/calendar.cpp:875–908`). Значение применяется при старте новой игры: `game::start_game` вызывает `start_calendar`, который берёт `scenario::start_of_game()` (`src/game.cpp:797, 10671–10678`, `src/scenario.cpp:631–634`); старт не раньше начала катаклизма (`src/scenario.cpp:592–602`).

Поле `start_of_cataclysm` (`start.json:71`) задаёт то же время. Без него родной сценарий начинает катаклизм 15 мая (`src/scenario.cpp:122–138`). Тогда при создании NPC родной код считает 96 дней после катаклизма, а от этого числа зависят бросок запаса калорий (`src/npc.cpp:734–741`) и наверстывание навыков (`src/npc.cpp:799–801`). При совпадении двух полей NPC создаётся как в первый день катаклизма.

Проверка — тест `novgorod_post_work_scenario_start_date` (`tools/cataclysm-prototype/novgorod_post_work_test.cpp:791–797`). Дата относится только к новому миру. Свет, координаты Новгорода и соответствие юлианскому календарю 1230 года этим полем не задаются (issue #825).

Распорядок двора держится на родных механизмах CDDA: классах NPC, постах, лагере фракции, глобальном EOC и родных потребностях. Посты — переменные места `novgorod_dev_master_Work` (13, 15), `novgorod_dev_master_Home` (11, 10) и `novgorod_dev_watchman_Gate` (12, 19) (`courtyard.json:50–56`); зона `LOOT_WOOD` фракции `novgorod_dev_master_household` (x 12–14, y 15–16) накрывает только Work, Home и Gate лежат вне зон (`courtyard.json:48`). Класс мастера задаёт `work_hours` [5, 20], `RETURN_TO_START_POS`, `job_priorities` `{"ACT_MULTIPLE_CHOP_PLANKS": 1}` и навык `fabrication` (`npc.json:35–38`), класс сторожа — `work_hours` [20, 5] и `RETURN_TO_START_POS` без `job_priorities` и навыков (`npc.json:48–49`). Родная проверка смены даёт мастеру часы 5–19, сторожу — 20–23 и 0–4 (`src/npc_class.cpp:439–445`, `src/npc_arbitration.cpp:181–189`). Ключ `job_priorities` читает overlay `native-npc-post-work.patch`: разбор отвергает неизвестную активность, отрицательный приоритет и работу, которой нет у NPC (`:28–43`), приоритеты применяются к NPC при создании (`npc::randomize`, `:97–108, 117`) и при загрузке сохранения (`:429`). На посту NPC работает, только если он на смене, у класса есть приоритет работы (`job_data::has_job` — приоритет больше нуля, `src/npc.cpp:244`) и пост лежит внутри включённой зоны своей фракции (`can_work_at_guard_post`, `native-npc-post-work.patch:316–331`); тогда ветка `hold_position` после `address_needs` продолжает идущее или отложенное занятие либо раз в 10 минут ищет работу через `find_job_to_perform`, иначе NPC делает паузу (`:148–176`). Работа поста уходит в очередь занятий с пометкой возобновления (`suspend_guard_job_activity`, `:370–380`) в трёх случаях: NPC уходит от опасного поля (`:124–131`), идёт к посту, на котором работать нельзя (ветка `return_to_guard_pos`, `:132–147`), или выполняет цель потребности дерева поведения (`:177–184`). Отложенное занятие возобновляется, только когда на посту можно работать (`:396–421`). Поэтому мастер работает только на посту Work, на Home не работает, а сторож без приоритетов лишь стоит на посту.

Двор — родной лагерь фракции мастера. Поле `camp` особого объекта (`start.json:22`) при создании мира ставит лагерь с владельцем `novgorod_dev_master_household` и именем «Двор плотника» (`src/overmap_special.cpp:155–156`, `src/overmap_special_fixed.cpp:271–284`). Родной проект такого лагеря `faction_base_bare_bones_NPC_camp_0` даёт ему `water_well` (`data/json/recipes/basecamps/special_hardcoded.json:34`), поэтому житель пьёт и воду лагеря (`basecamp::has_water`, `src/basecamp.cpp:347–351`). Overlay в `map::place_npc` делает жителем NPC фракции-владельца, которого mapgen ставит внутри лагеря: миссия `NPC_MISSION_CAMP_RESIDENT` и `basecamp::add_assignee` после `overmap_buffer.insert_npc`, потому что `add_assignee` ищет NPC через `overmap_buffer.find_npc` (`native-npc-post-work.patch:582–593`, `src/basecamp.cpp:574–583`). Отложенная работа поста у жителя возобновляется так же, как у сторожевого NPC (`has_guard_job_context`, `:333–344`). Вне смены у жителя работают родные ветки дерева поведения `camp_work`, `free_time` и `return_to_camp`; еду и питьё ведут родные пути `address_needs` и исполнителей потребностей. Родная ветка `camp_work` проверена (`src/character_oracle.cpp:518–533, 561–568`): часов работы класса она не знает. Расширение — проверка родных часов класса в её предикатах (`npc_outside_work_hours`, `native-npc-post-work.patch:618–627, 632–649`): у класса с часами, отличными от 0–24, работа лагеря вне смены не выбирается. Лагерь и жители появляются только в новом мире. Ограничение: член фракции-владельца с постоянным постом без часов работы (`GUARD`, `work_hours` 0–24) после размещения станет жителем и потеряет пост — для такого NPC `post_duty_of` вернёт `none` (`src/npc_arbitration.cpp:175–178`). В данных мода таких NPC нет: у мастера часы 5–20, у сторожа 20–5.

На посту родная ветка `hold_position` вызывает `address_needs( NPC_DANGER_VERY_LOW + 1 )` (`src/npcmove.cpp:1868`), и обычный блок еды и питья закрыт любому, кто держит позицию: такое значение опасности передаётся, чтобы NPC не начинал есть и спать (`:3919–3923`). Житель на посту своего лагеря без опасности родным кодом не выделен, и жажда мастера на смене дорастает до 80–81, порога родного крайнего блока (`:3086`). Расширение переносит родной обычный блок (`:3177–3224`) без изменений в метод `npc::address_normal_food_drink()` (`native-npc-post-work.patch:185–253`); `address_needs` вызывает его на прежнем месте (`:254–309`), а ветка поста — только у жителя лагеря при настоящей опасности не выше `NPC_DANGER_VERY_LOW` и жажде больше `NPC_THIRST_CONSUME` (`:148–176`). Сон и остальное после проверки опасности на посту по-прежнему закрыты. Голод на посту ведёт родной крайний блок: запас калорий ниже 75% нормы (`src/npcmove.cpp:3085–3110`). Обеда на смене нет: еда в избе с поста не видна, житель ест вне смены родными ветками. Условие жажды нужно потому, что на пустом желудке родной голод равен 100 (`src/character_body.cpp:991–997`), еду лагеря житель выше 95% нормы не берёт (`src/npcmove.cpp:5415`), и обычный блок, открытый голодом (`:3179–3180`), пил бы воду местности при любой жажде каждые несколько минут (`:3199–3210`, `drink_from_water_source` — `:6509–6526`). Вне поста эта родная петля остаётся (issue #943).

Глобальный EOC `EOC_NOVGOROD_YARD_ROUTINE` срабатывает раз в час (`wild-eocs.json:17–19`) и стоит в списке `eoc` сценария (`start.json:68`): при старте игры его ставит в очередь `effect_on_conditions::load_new_character` (`src/effect_on_condition.cpp:160–163`), и посты текущего часа назначаются сразу. Без этого житель лагеря остался бы без поста до первого срабатывания: родной `regen_ai_cache` ставит начальный пост по `RETURN_TO_START_POS` только тем, кто не житель (`src/npcmove.cpp:1441–1447`). EOC делает родной `switch` по часу суток (`:22`), и каждый `case` задаёт посты обоих NPC — полное состояние часа: 5 — мастеру Work, сторожу Gate (`:25`), 19 и 20 — мастеру Home, сторожу Gate (`:42`, `:59`). Посты ставит `u_set_guard_pos` с `unique_id`, который добавляет `unique_id` NPC префиксом к имени переменной (`doc/JSON/NPCs.md:999`). Родной `f_switch` применяет последний подходящий `case` (`switch_int >= case`, `src/npctalk.cpp:7261–7280`): в часы 5–18 — Work и Gate, в 19–23 — Home и Gate, а с 0 до 4 ни один `case` не подходит и посты остаются прежними. Занятие, сон, еду и положение EOC не задаёт: их определяют родные потребности (`npc::address_needs`, `src/npcmove.cpp:2968`) и родная работа. Тяга NPC к посту — `duty_urgency` (`src/character_oracle.cpp:390–418`): на посту в смену она терпит умеренную усталость, вне смены не мешает потребностям (`src/npc_arbitration.cpp:273`).

Запас двора: по 16 `log` на каждой из клеток (12, 15), (12, 16), (13, 16), (14, 16) — 64 бревна, 42 `dry_fish` на столе (10, 10), соломенная постель `f_straw_bed` (12, 10) и глиняная печь `f_clay_oven` (14, 9) (`courtyard.json:45, 65–71`); все вещи тайла принадлежат фракции `novgorod_dev_master_household` (`courtyard.json:76`). Работа мастера — родная цепочка `ACT_MULTIPLE_CHOP_PLANKS` → `ACT_CHOP_PLANKS`: `find_job_to_perform` выбирает её по приоритету (`src/npcmove.cpp:3984, 4008–4009`), `multi_activity_do` и `chop_plank_activity` берут бревно из зоны `LOOT_WOOD` (`src/activity_item_handling.cpp:3856–3864, 3422–3443, 3565–3566`), `chop_planks_activity_actor::finish` превращает бревно `log` в доски `2x4` (`src/activity_actor.cpp:10433`). Число досок с бревна — `normal_roll( 2 + fabrication, 1 )`, остаток до десяти — щепа `splinter` (`src/activity_actor.cpp:10437–10450`). Проверяющий читает родные JSON из установленного runtime и копию `mtype_taxon_crosswalk.csv` из установленного мода. Для CLI и теста задаются внешние данные:

| Переменная | Значение |
|---|---|
| `NOVGOROD_WILD_REFERENCE_CAPTURE` | каталог `capture25` с эталонной записью и `inputs.log` |
| `NOVGOROD_WILD_REFERENCE_WORLD` | конечное сохранение задания 25 |
| `NOVGOROD_WILD_MOD` | каталог установленного мода `novgorod_dev_world` |
| `NOVGOROD_WILD_ALLOWLIST` | путь к TSV allowlist; unit-тест требует эту переменную, а в приведённой команде CLI при её отсутствии используется `tools/cataclysm-prototype/wild-surroundings-allowlist.tsv` |
| `NOVGOROD_WILD_RUN30` | запись из 50 вводов задания 30 после её создания |
| `NOVGOROD_WILD_WORLD30` | копия `world-after-route` после реального маршрута |

После реальной записи задайте `NOVGOROD_WILD_RUN30` и `NOVGOROD_WILD_WORLD30`, затем запустите проверяющий CLI из корня репозитория:

```sh
python3 tools/cataclysm-prototype/check_wild_surroundings.py \
  --run "$NOVGOROD_WILD_RUN30" \
  --reference-inputs "$NOVGOROD_WILD_REFERENCE_CAPTURE/inputs.log" \
  --world "$NOVGOROD_WILD_WORLD30" \
  --mod "$NOVGOROD_WILD_MOD" \
  --allowlist "${NOVGOROD_WILD_ALLOWLIST:-tools/cataclysm-prototype/wild-surroundings-allowlist.tsv}"
```

Unit-тест использует внешние capture/save/mod. Если ни одна из шести переменных не задана, `unittest` пропускает весь модуль с причиной «нет данных записи servak: переменные NOVGOROD_WILD_* не заданы». При частичной настройке `setUp` выдаёт `RuntimeError` со списком незаданных переменных. Чтобы тесты выполнялись без пропусков, задайте все шесть переменных `NOVGOROD_WILD_*`, затем выполните:

```sh
python3 -m unittest tools/cataclysm-prototype/test_check_wild_surroundings.py
```
